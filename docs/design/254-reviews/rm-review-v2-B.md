## 查證的事實(自己查的)

- 邀請是**自我證明**的:`open_invite` 用 payload 裡自己帶的 admin_pub 驗,netcfg 由它自己的 admins 簽即可(invite.rs:144-153、:156-178)。所以任何人都能做出同一個 net_id、自選 admins 的邀請。今天唯一擋住「同 net_id 的另一個網路蓋掉既有 mnet」的,是 `existing()`:要嘛逐 byte 相同,要嘛剛好 +1 版、由舊 admins 簽、prev_hash 接上;否則回 TooOld / SameVersionDifferent(approve.rs:304-318)✅。
- `bind()` 用 pend 的 netcfg(來自邀請)的 admins 驗 members / secrets / msecrets(approve.rs:275-286)✅。所以同意包的可信度**完全等於邀請的可信度**。
- 網主的 k8 只在建網(以及本單的換版)時產生;`ApproveFlow` 把 `rec.base.members`(= k8)原樣放進同意包,新同意的人只寫進 k11,**不會**進 k8(approve.rs:156-157、:160-182)✅。所以 v 版之後才被同意的節點,不在 v 版的 members 裡。
- `existing()` 遇到同一個 DAC 時,沿用舊的 me(含 state)(approve.rs:319-321)✅。
- `confirm()` 要求 info k9 = k7 的版本(netrec.rs:303-306)✅;`creator()` 讀 k8 第一筆(netrec.rs:281-283)✅ → §2.4「建立者第一」是必要的。
- `join_state`:k10 缺、k11 false = NotApplied;9–11 全缺 = Unknown(限速)(flow.rs:120-150)✅。
- SignAllowList 的 ADMIN_LABELS 已經涵蓋 netcfg / members / secrets / msecrets(SignAllowList.kt:11),本單不需要新標籤 ✅;ADMIN_SIGN 不需要使用者驗證(Keys.kt:70-72 `ec(...)` 沒有 `setUserAuthenticationRequired`)✅。
- store 不偵測回滾(store.rs:7-11)✅。
- NU §3 交接清單:wsl.24 的規則原文是「**網路裡**還有 wsl.24 節點時不得開始」,另有「被移除者能在它身上用舊 secrets 配新設定」(254-net-update-members.md:123)、F10(:42)✅。

## MAJOR

### M1 §3.6-2 的「取代舊 mnet」讓攻擊者自己決定的欄位打開 existing() 的防線:同 net_id 的偽造網路可以蓋掉真的 mnet

情境(攻擊者 = 被移除的人,或任何知道 net_id 的人;net_id 出現在每一份更新包和同意包裡,剪貼簿也看得到):
1. 攻擊者自己產一把金鑰,做一份 netcfg:同一個 net_id、同一個名稱、version = 受害者 mnet 版本 + 2(或任意更大的數)、admins = 攻擊者。再做一張自簽的邀請,`open_netcfg_current` 會接受(invite.rs:156-178 的信任只來自邀請自己)。
2. 他對留下的成員 B 說:「網主換完密碼重新邀請大家,貼這張。」B 的 app 產生加入申請(只需要 B 的擁有者連線),攻擊者回一份自己簽的同意包,SAS 兩端都由攻擊者顯示,所以必定吻合。
3. 匯入時 `existing()` 本來會回 TooOld 而拒絕。但 v2 的新規則是:「落後 ≥ 2 版**或** k7 在新版 members 的 removed / 不在 members → 問『要換成新的嗎?』,確認後**以新同意包取代整個 mnet**」。觸發條件的兩個欄位(版本、members)**都是攻擊者簽的內容**。對話框的措辭又是在引導使用者按「是」。
4. 取代之後:
   - B 的 mnet 變成攻擊者的網路,同名、同 net_id,真的 net_root / secrets / 歷代都沒了;
   - 網主之後給 B 的真更新包會被當成分叉或「資料太舊」而拒絕;
   - 狀態頁的共用規則(§3.5)看到 mnet 版本 > 節點 k9,顯示「這台還在舊密碼」;§3.2 發現歷代最舊一版 > k9+1,於是叫 B「請讓它離開網路再重新加入」;
   - B 照做,他的節點就用攻擊者給的 net_secrets(在步驟 3 已經加密給 B 節點的 ecdh_pub)加入**攻擊者的 mesh**。整條路都是我們自己的畫面在引導。

和今天相比:今天偽造的邀請只能建立一個**另外的**網路紀錄(net_id 不同),或者因 `existing()` 被拒;v2 讓它能冒用真網路的身分,而且是一鍵刪掉真紀錄。這也正是本輪要特別檢查的「讓手機接受偽造或更舊的網路」。

修法(只改觸發條件,不加機制):
- 取代只在以下條件**全部**成立時才提供:
  - 新同意包的 netcfg 由**舊 mnet 的 admins 之一**簽,而且邀請的 admin_pub ∈ 舊 mnet 的 admins;
  - net_id 相同;
  - version > 舊 mnet 版本。

  本單不換網主(NU §7),網主的金鑰不會變,所以真的重新邀請一定滿足這三條;偽造的一條都過不了。這樣就擋掉偽造,也擋掉用更舊的真物件把 mnet 倒回去。
- 觸發條件拿掉「k7 不在 members」(見 m1:它對合法流程也會誤觸發)。只留「TooOld」與「+1 版但 k7 在 removed」。
- k7 在新版 removed 時,**不沿用**舊的 me(approve.rs:319-321 會把舊的 Applied 狀態帶過去),改成新的 joining 項。
- 測試(負對照):
  - 同 net_id、version + 2、admins 換成別把金鑰的同意包 → 即使使用者確認也拒絕,mnet 不變;
  - 由真網主簽、但 version ≤ 舊 mnet 的同意包 → 拒絕;
  - 真網主的 v3 → 確認後取代,且 me 是 joining;
  - mutant:拿掉「舊 admins 簽」這條 → 第一個測試要失敗。

### M2 wsl.24 的 F10 污染會在節點升級之後留下來,§3.2 會把它判成「已是新密碼」;§3.2 的理由「wsl.24 節點不送(F10 不會發生)」是錯的

情境:
1. 分裂期間,被移除者用舊 net_root 算出 v1 的 psk_member,開成員連線到某位成員 C 還在 wsl.24、v1 的節點(provd/session.go:82 允許成員連線送 `network/update`)。
2. 他送 v2 的 netcfg(公開物件,任何一份更新包裡都有)配 v1 的 secrets。v1 secrets 他手上可能有:C 當初的同意包走過剪貼簿,裡面就有加密給 C 節點的那份。F10:wsl.24 不綁版本 → code 0,k9 = 2,SAE 還是舊的(NU:42 的探針)。
3. C 之後把節點升級到 wsl.25,再按「把新密碼送給節點」:§3.2-1 讀到 k4 = wsl.25、k9 = 目前版本 → 「已是新密碼(完成)」。狀態頁的共用規則也不再提示。
4. 結果:這台節點**一直**留在被移除者的那一邊。C 的手機經它上網的流量都在被移除者的 mesh 裡,而 UI 說一切正常。NU 說「下一次合法 update 會整個覆蓋」,但在下一次移除之前,不會有下一次 update。

證據:
- NU:123「**網路裡**還有 wsl.24 節點時不得開始移除成員……被移除者能在它身上用舊 secrets 配新設定」;
- NU:42 F10 探針 `v2 cfg + v1 secrets -> code 0`;
- 設計 §3.2 末「wsl.24 節點不送(F10 不會發生)」:不送的是我們,攻擊者照樣能送;
- 設計 §10 對 A-M4 / B-M7 寫「誠實界線(別人的節點看不到)」:那一條的後果沒有寫出來,而後果是**看不見的永久分裂**,不只是「暫時分裂」。

修法(最小):
- §3.1 的確認對話框加一條必須勾選的前提:「全隊每一台節點都已更新到 wsl.25 以後(這支手機只檢查得到你自己的節點)」。網主連得上的自己的節點,仍照 §3.1-5 硬擋。
- 成員端的匯入成功畫面、以及 §3.2 的 wsl.24「先更新軟體」那一句,都加上:「如果這台在換密碼之後、更新軟體之前開過機,更新後請讓它離開網路再重新加入。」理由:這台在 wsl.24 期間可能被灌過假的 v2,app 無法分辨。
- §3.2 末的理由改寫:k9 足以判定的前提,要加上「這台節點在 v(n) 發出之後從沒跑過 wsl.24」。
- §6 / 誠實界線寫出後果:看不見、會一直持續、被移除者能經這台節點進入隊伍。
- 釋出條件:移除功能隨 wsl.25 出,dev 車隊(04 / 02)燒 wsl.25 之後才開放。寫進 §9 checklist。
- 測試:在 Go 端或以 harness 重現 F10 的污染節點(wsl.24 的 /tmp 複本,或用 provclient 以舊 secrets 灌),升級到 wsl.25 後讀 info → 斷言 app 在這種狀態下判定 k9 = 目前(記錄為已知界線)。真正的負對照是:對話框和提示有沒有出現。

### M3 舊紀錄的成員項沒有 k10:第一次換密碼(以及降級再升級)的預設值沒有定義,選錯就會讓成員悄悄拿不到更新

情境:
- §2.1 規定 k10「同意時設」。但今天已經存在的 approved 項(approve.rs:170-179)都沒有 k10;降級到舊 app 寫回也會把 k10 丟掉(§5 自己也寫了)。
- §2.3 / §3.3「成員已在目前版本 → 不產包」。如果實作把缺的 k10 當成目前版本,或者當成 0 / 跳過,在**第一次在現場用這個功能**時,所有既有成員都會不產包,或者產出壞的鏈。
- §3.3 只會顯示「已複製」,沒有任何地方會發現。這是 A-BLOCKER-1 那一類問題(成員永遠補不回),從另一個入口進來。

修法:
- §2.1 寫明:k10 缺 = 「k13 最舊那一版」。第一次換密碼時,k13 由 k7 補一項,所以就是 k7 的版本(今天 = 1)。
- 降級再升級後,k13 只剩目前版本,這時 k10 缺的成員就畫面標示「版本未知:對方若匯入失敗,請重新邀請他」。成員端本來就會去掉已有的部分,鏈從最舊一版起是安全的。
- T3 / T10 加兩臂:approved 項沒有 k10 → 包的鏈從 v2 起、成員匯入成功;負對照:缺的 k10 當成目前版本 → 不產包。

### M4 網主自己的節點遺失 / 被抓時,沒有任何換密碼的路;§6 寫「節點被抓 → 移除擁有者」對網主的節點不成立

情境:
- 現場最常見的觸發之一,是網主自己帶的某台節點掉了或被拿走。被抓的節點上有目前的 SAE 和 net_root(node.go:426-432 用它導出 psk_member)。
- 但 §3.1 規定「自己那一組沒有移除」,單台移除不做(使用者決定),移除共同網主也不支援。所以網主沒有辦法把全網換成被抓節點不知道的密碼。
- §6「節點被抓(同遺失:移除擁有者,其他節點離開再加入)」這句對網主的節點是錯的。

修法:
- §6 更正為誠實界線:「網主自己的節點遺失 → 本單無法換密碼,只能重建網路(全隊離開、重新建網)」。
- 列進 §8 給使用者決定:要不要允許「換密碼、但把網主指定的自己那台排除在外」。資料模型其實已經支援:members 去掉那台的 DAC、不送它。這是範圍決定,不是我能替使用者定的。
- 確認對話框和網主的說明頁寫出同一句。

## MINOR

- **m1 「k7 不在 members」會對合法流程誤觸發。** 同意包的 members = k8,而 k8 不含 v 版之後才被同意的節點(approve.rs:156-157、:180-182)。所以 v2 之後才加入的成員 D,之後用第二張邀請加第二台節點時,同意包的 members 裡沒有他的 k7 → 跳出「要取代嗎?」。按「是」會丟掉他其他節點的 k10。按「否」,設計沒有定義結果。併進 M1 的修法:這個條件拿掉。
- **m2 版號規則的寫法,以及連不上的節點。**
  - §2.4 寫 `v = max(紀錄, k9)`,但又寫任一台 k9 > 紀錄就不開始。所以實際上 v 就是紀錄版本,改寫成一句,免得實作照 max 走。
  - §3.1-5「連不上的節點略過」讓回滾檢查變成盡力而為:自己所有節點都連不上時,照樣會簽出可能重複的版號。改成至少要有一台自己的節點連得上、而且 k9 = 紀錄版本,才能開始。
  - k9 > 紀錄時的出路(重建網路)也要寫出來,否則網主之後永遠不能再移除任何人。
- **m3 §3.4-2「逐 byte 與 mnet 歷代相同才算已有」沒有處理歷代缺的情況。** mnet k9 只從第一次匯入起,降級後只剩目前版本。比 mnet 歷代還舊的版本,要定義為「略過、不比對」。真正要驗的只有接上 mnet 目前版本的那一環:新的第一版由 mnet k3 的 admins 簽,而且 prev_hash = OBJECT_HASH(mnet k3)。否則合法的包會被當成「分叉」。
- **m4 「已經匯入過,但 net_secrets 若缺可補進 k10」也要跑規則 3–5**(網主簽、目前版本、target 是自己的節點),並走同一次 CAS。否則它會變成一條沒驗簽就能寫 mnet 的旁路,也就是 B-M1 從後門進來。
- **m5 「這張邀請在換密碼前發出,已失效」這句分不出來。** `check_joinreq` 對作廢和真的用過都回 `InviteUsed`(approve.rs:71-74)。要嘛 k12 加一個可區分的值,要嘛句子改成通用的「這張邀請已用過或已失效,請重新邀請」。
- **m6 §10 指向的內容不存在。**
  - §10 說 k4 的解析規則「見 §3.6」,忘記對話框的那句話「進 §3.6 實作清單」,但 §3.6 兩者都沒有。
  - 請把 k4 規則(`-wsl.N`,N < 25 或解析不出 → 不送)與 A-m7 那句話實際寫進正文。
- **m7 §3.2-1 的分支順序與 `join_state` 不一致。**
  - 「k10 ≠ 本網 / 缺 → 不在這個隊伍網路」寫在限速判斷之前。直接用 `flow::join_state`:Unknown → 等;NotApplied → 導向隊員模式「加入網路」(A-m5b:節點從沒入網或已離開),不要說「不在這個隊伍網路」;OtherNetwork → 停。
- **m8 隊員重新加入 / 第二台節點只用 mnet k5。** 隊員重新加入送的是 mnet 裡的 secrets(R19),而 k5 只屬於 k7 那台。
  - 非 k7 的自己節點要從 k10 依 dac_hash 取。
  - 更新包裡沒有 k7 那台的 secrets 時,k5 要怎麼處理也要寫:保留舊的,會讓重新加入送出舊版 secrets,節點以 §2.2-5 拒絕。這是 fail-closed,但畫面要說。
- **m9 §3.4-6 遇到 mnet 沒有 k7 時沒有定義。** 例如 NeedsNewInvite 之後,或 k7 那台被網主「忘記」了,但這個人其他的節點都還有效:這時是整包拒絕,還是只看規則 4?要寫清楚。
- **m10 「一個人」= owner_pub。**
  - 名稱由成員自己取,惡意成員可以取和別人一樣的名稱,讓網主移除錯的人。分組要顯示 owner_pub 指紋,以及那個人每台節點的 device_id。
  - 同一個真人換過手機(owner_pub 不同),會變成兩組,要移除兩次。寫進說明。
- **m11 k10 只在同意時設 → 鏈只會越來越長。** 換版超過 16 次之後,早期加入的成員就算一直跟上,也拿不到包(§2.3 ≤ 16 步)。出路(重新邀請會重設 k10)要寫進誠實界線。
- **m12 新增的結構與秘密衛生。** 更新包的解析結構、mnet k10、解出的 member_secrets 明文,要比照既有做法:MNet 不 derive Debug(mrec.rs:79-80);明文用完歸零(approve.rs:213、:385-387);錯誤訊息不帶物件內容。測試清單加一條:新結構沒有 Debug,錯誤字串不含 hex。
- **m13 測試缺口。**
  - M1 的三個負對照、me 不沿用;
  - M2 的提示;
  - M3 的 k10 缺;
  - §3.4 的「已經匯入過 + 補 k10」走驗簽(m4);
  - 「k9 = 目前」判定成功的 mutant:例如把 k4 檢查放到 k9 之後。
