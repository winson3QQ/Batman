# #247-2 runc 1.1.14 → 1.3.6(容器逃逸 CVE)

狀態:**v2 — v1 review = FAIL(B1/M1/M2)→ 本版修正(§6),複審 = PASS(2026-10-07)**。單號 winson3QQ/Batman#247 子項 2。前置 #252 已 merge(Go 套件用 build 樹 go1.26.4)。

## 1. 事實(2026-10-07)
- 目前 fleet(1.5.3-wsl.1)的 runc:`runc version 1.1.14`、`go1.26.4`、`libseccomp: 2.5.5`;containerd 1.7.22、docker/dockerd 27.3.1。來源:packages feed openwrt-24.10 @953b6d4 的 `utils/runc/Makefile`。
- runc 官方 GHSA(`gh api repos/opencontainers/runc/security-advisories`):
  | CVE | 嚴重度 | 受影響 | 修正 |
  |---|---|---|---|
  | CVE-2025-31133(masked path 競態 → 逃逸) | high | ≤1.2.7 | 1.2.8 / 1.3.3 |
  | CVE-2025-52565(/dev/console bind 競態 → 逃逸) | high | ≥1.0.0-rc3, ≤1.2.7 | 1.2.8 / 1.3.3 |
  | CVE-2025-52881(procfs 寫入轉向 → 逃逸/DoS) | high | ≤1.2.7 | 1.2.8 / 1.3.3 |
  | CVE-2026-41579(/dev symlink,有限 host fs 影響) | low | ≤1.3.5 | **1.3.6** / 1.4.3 |
  → 1.1.14 全部受影響;**1.3.6 全修**。1.1.x 已停止維護。
- 威脅模型:攻擊面是「惡意或被竄改的容器 image / config」。**價值主要在三個 high**:CVE-2026-41579 的 advisory 註明在 Docker 下不可利用(moby initlayer)。我們的 payload 框架會載入 tenant image(OTS 自建 image + Docker Hub 的 rabbitmq、postgis;flash-and-go 可放任意 tenant)→ 供應鏈或惡意 tenant 可逃逸到 host(root)。
- 上游 OpenWrt:openwrt-25.12 / master = **runc 1.3.6**(搭 containerd 2.2.5 / docker 29.6.1);24.10 仍 1.1.14。25.12 的 runc Makefile 對 24.10 只差:版本/hash、`PKG_BUILD_DEPENDS += dockerd`、mips 的 ARCH_DEPENDS 過濾、拿掉 `PKG_BUILD_FLAGS:=no-mips16`。沒有 patch 檔。
- 相容性:containerd 官方 1.7.28–1.7.36 自己內附 runc 1.3.0–1.3.6(1.7.33 正好 1.3.6,見下) → containerd 1.7 + runc 1.3 是上游支援組合。runc 1.3 go.mod `go 1.23.0`(我們 go1.26.4 ✅)。
- runc 1.2/1.3 行為變更(CHANGELOG):`/proc/self/exe` 改用 overlayfs 封存(`libcontainer/exeseal`,lowerdir=`/usr/sbin` + runc state dir);做不到時**runc 自己**回退成每次 run/exec 複製一份 binary(memfd/O_TMPFILE,約 12 MB,**算在容器的 memcg**;runc#4427 就是這個 OOM,讓 containerd 1.7.23 退回 runc 1.1.15)。`runc-dmz` 只存在 1.2.0,1.2.1 已移除(#4488),`runc_nodmz` 在 1.3 無作用。`runc kill -a` 棄用但仍接受。libseccomp 無最低版本要求(review 實編:對 staging 2.5.5 連結成功)。
- **支援期**:runc 支援政策下 1.3 現為 latest-2,只收 CVSS ≥7 修正;**runc 1.6.0 GA 後 1.3 不再有修正**(1.6.0-rc.1 2026-10-06)。**containerd 1.7 已於 2026-09-30 EOL**(官方 RELEASES.md),1.7.22 還有 1.7.33–1.7.36 修掉的 CVE(其中 critical 的 CVE-2026-53488 是 CRI-only;dockerd 管的 containerd 停用 CRI → dogfood 確認)。→ **#250(containerd/docker 升級)須在 runc 1.6.0 GA 前完成**。
- 為何選 1.3.6 不選 1.4.x:containerd 1.7.30–1.7.36 內附 1.3.4–1.3.6(1.7.33 正好 1.3.6)= 上游實際驗證過的組合;1.4 未與 containerd 1.7 搭配發布過。

## 2. 方案
**C(採用)**:board patch `patches/ekh-bcm271{0,1}/0010-runc-1.3.6-cves-247.patch`:runc Makefile **只改版本 + hash**(= 25.12),保留 24.10 打包;**同一個 patch 拿掉 dockerd 的 runc vendored-version 檢查**(moby 27.3.1 的 `runc.installer` 寫死 v1.1.14,否則**每個乾淨 build 都在 dockerd Build/Prepare 失敗**;增量樹看不到 = review B1)。
- ~~A:25.12 Makefile 原樣~~ → 否決:25.12 的 `PKG_BUILD_DEPENDS += dockerd` 與既有 containerd → runc 形成**循環依賴**(make 會靜默丟一條邊,建置順序不確定 = review M1)。
- B:整個 packages feed pin 到 25.12 → 牽動上千套件,不考慮。

另外:
- **manifest 精確版本閘**加 `runc=1.3.6-r1`(兩板)。
- **daily-validation** 新增 `runc-cve-247`:每台跑 docker 的節點 `runc --version` ≥ 1.3.6。
- containerd/docker **不升**(→ #250,大版本另評估)。
