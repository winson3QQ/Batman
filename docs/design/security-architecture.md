# #423 安全架構總設計：金鑰、身分、授權、撤銷、准入（v1）

**這份文件定什麼**：整個系統有哪些金鑰、各放哪裡、誰簽發、誰能用；身分憑證與授權物件有哪些欄位；撤銷怎麼成立；從出廠到加入 mesh 每一步檢查什麼；晶片與驗證開機能提供什麼證明。v2.0 與 v2.5 的安全相關單照這份實作。
**不定什麼**：位元組格式、訊息順序、畫面流程、程式結構。這些在各單自己的實作設計裡定，並引用本文件的章節。本文件**不寫程式、不改節點**。

## 2. 信任根：五個，互不替代

系統裡有五種「最上層的金鑰」。**任何一個都不能做另一個的事**；這是整份架構最重要的一條分隔。

| # | 信任根 | 回答的問題 | 誰持有 | 簽什麼 | 不能做什麼 |
|---|---|---|---|---|---|
| T1 | **原廠根**（bench 用開發根） | 這是不是我們做的節點、它的金鑰是不是在晶片裡 | 我們（原廠）。開發根只在開發者電腦，只簽 bench 晶片 | 節點憑證（§4.1） | 不能管理任何已入庫的節點、不能加入任何網路（K22） |
| T2 | **單位信任錨** | 誰能管這台節點、這個網路 | 家庭：家長手機的金鑰。小隊：機關的離線根金鑰（U1、D1、D6） | 授權物件（§4.2） | 不能偽造節點身分（那是 T1 與晶片） |
| T3 | **TAK CA** | 這支手機能不能連 TAK server | 小隊：ICS 發證站；家庭：節點上的 OTS 自己 | TAK server 與 client 憑證 | 不能授權任何 Batman 管理動作（D5） |
| T4 | **發行根 R** | 這個映像是不是我們發的 | 我們，離線 | 簽章金鑰 K 的背書；K 簽發行物件（已出貨 ✅）。開機映像簽章金鑰（#405）是 K 之外的另一把，由 R 另行背書 | 不能讓節點安裝更新（安裝要 T2 之下的授權，§9） |
| T5 | **主機根**（CM4 OTP） | 這台主機開的是不是簽過的映像 | 燒在每顆 CM4 裡，燒後不可改 | 不簽東西；ROM 用它驗開機映像，並導出只有簽過的映像讀得到的裝置秘密（#115、#414） | S-A、S-B 沒有它 |

- 開發與量產的根分開：開發根、測試根 T（`release.go:2` ✅）只存在於開發建置。量產建置不含它們的公鑰。**bench 608B 的憑證只由開發根簽，所以進不了量產網路**（#196 的輸入）。
- 換掉 T2（換代或復原）之後既有網路仍可管理，是 K7 的要求，做法見 §5.4。

## 3. 金鑰階層表

「放哪」分晶片、主機（CM4 OTP）、磁碟（註明哪個分割區、有沒有加密）、手機、離線。「遺失」指持有者遺失或金鑰外洩時怎麼辦。

### 3.1 節點上的金鑰

| # | 金鑰 | 類型 | 放哪 | 誰產生、誰簽發 | 誰能用 | 輪替 | 撤銷 / 遺失 |
|---|---|---|---|---|---|---|---|
| N1 | 身分金鑰 | P-256 | 晶片（bench：608B 槽 1；量產：#426 的晶片），**不可匯出** | 晶片內產生；公鑰是節點憑證的主體，由 T1 簽 | 沒有人拿它簽主機給的東西（槽 1 只准內部簽章，`255-608b-config.md` §3 ✅） | 不輪替；換晶片 = 新節點 | 節點遺失 → 撤銷這個節點 id（§5） |
| N2 | 連線金鑰 | P-256 | 晶片（608B 槽 0） | 晶片內產生；公鑰寫在節點憑證裡 | 只有 helper（root，K21）；只簽「固定用途標籤 ‖ 交握雜湊」（當場證明，K20） | 同 N1 | 同 N1 |
| N3 | 收件金鑰 | P-256 ECDH | 晶片（608B 槽 2） | 同上 | 只有 helper；用來解開寄給這台的秘密（網路密碼包） | 同 N1 | 同 N1 |
| N4 | 認領秘密 | 32 位元組 | 晶片（608B 槽 5，不可讀）；另一份印在機身 QR | 燒錄時由 `se-sign` 產生 | 晶片只回答「對或錯」（CheckMac） | 不輪替（⚠️ 重燒卡後仍有效是需求，也是永久秘密，見 §5.5） | QR 外洩 = 能在未入庫時搶先入庫；已入庫的節點不受影響 |
| N5 | 節點憑證 | X.509 | 晶片（608B 槽 8，明文） | T1 簽 | 任何人可讀 | 只能重燒卡（`255-608b-impl.md` §3.1） | 靠撤銷節點 id |
| N6 | WireGuard 金鑰 | Curve25519 | 磁碟 p5（S-C 起才真的被 LUKS 保護） | 節點自己產生；公鑰由 N2 簽一份綁定聲明（§4.3） | 核心的 WireGuard；root | 可隨時重產，重簽綁定 | 節點被撤銷 → 其他節點從 peer 移除它（§6 第 5 步） |
| N7 | 磁碟金鑰（LUKS） | 對稱 | 不存放；S-C 起每次開機由「晶片裡的秘密 + 主機裝置秘密（T5）」導出。S-A、S-B 是卡上的佔位檔 | 首次開機 | 開機早期的 root | 重新加密才能換 | 整台遺失：S-C 起拿不到；S-A、S-B 等於明文 |
| N8 | SSH 主機金鑰 | Ed25519 | p5 | 首次開機 | sshd | 恢復出廠時重產 | — |
| N9 | 網路密碼（mesh SAE、手機 Wi-Fi） | 對稱 | p5 | 管理員產生；對每台節點的 N3 加密後送達（已出貨 ✅） | wpa_supplicant / hostapd；root | 每次成員離開就換（§5.2） | 見 §5 |

| # | 金鑰 | 放哪 | 誰簽發 | 能做什麼 | 輪替 | 遺失 |
|---|---|---|---|---|---|---|

| A4 | 成員金鑰 | 手機 | A3 或 A2 | 讀狀態、拿到自己那台的手機 Wi-Fi 設定 | 同上 | 同上 |
| A5 | 維修授權 | 不是長期金鑰：是 A3 對「某一台、某一段」簽的一次性授權（§4.2 的維修類型） | A3 | 打開那一台的維修入口（K23） | — | 自己結束（§8.3） |

### 3.3 我們（原廠）與 TAK 的金鑰

| # | 金鑰 | 放哪 | 能做什麼 | 遺失 |
|---|---|---|---|---|
| M1 | 原廠根（T1）私鑰 | 離線（❓ 保管方式由使用者定，§15 Q-B） | 簽節點憑證 | 外洩 = 有人能做出「看起來是我們做的」節點；它仍要通過入庫（T2）才進得了任何網路 |
| M2 | 發行根 R、簽章金鑰 K | R 離線；K 在發版機器 | 簽更新（已出貨 ✅） | K 外洩：R 背書新的 K，舊 K 靠版本下限擋（`254-p3-impl.md` §3.7 ✅） |
| M3 | 開機映像簽章金鑰 | 離線；CI 只有開發金鑰（#405） | 簽 `boot.img` | 外洩 = S-C 的開機鏈失效，且 OTP 不可改 → ⚠️ 要在 #115 定 OTP 能放幾把、能不能作廢（Pi 的 EEPROM 支援金鑰撤銷位元，未查證） |
| M4 | TAK CA（T3）及其下的 server、client 憑證 | 小隊：ICS 發證站。家庭：節點 p5 | 簽 TAK 憑證 | 依 #58、#54；撤銷 client = 從 OTS 帳號停用（TAK 不查 CRL，`ics-mtls-crl-revocation-infeasible.md`，#58 引用 ⚠️ 未重查） |
| M5 | 工作負載發佈者金鑰 | 發佈者離線 | 簽容器映像（#97） | 從允許清單移除 |

**原則**
- 私鑰不可匯出的（N1–N3、A1 家庭版、A3、A4）遺失時**一律是撤銷加重新簽發，沒有備份還原**。可以備份的只有 A1（小隊）、M1–M3。
- N6、N9 這種在磁碟上的秘密，只有 S-C 起才算被保護。S-A、S-B 的設計不能把安全性建立在它們保密上。

## 4. 身分與授權的欄位

**分工**：節點憑證（X.509，T1 簽）只說「這是哪一台、它的金鑰在晶片裡」。**角色、權限、屬於哪個網路都不寫在節點憑證裡**，而是寫在授權物件（COSE，T2 之下簽）裡。理由：節點憑證寫進晶片後不能改（N5）；角色會變；而且 T1 不該有權決定誰管誰（K22）。

### 4.1 節點憑證（T1 簽）

| 欄位 | 內容 | 寫死或可改 |
|---|---|---|
| 簽發者 | 開發根或原廠根；驗證者以**內建的根公鑰**判斷，不看簽發者名稱的文字 | 寫死 |
| 主體 | 節點 id = SHA-256(N1 公鑰) 的前 9 位元組 | 寫死 |
| 主體金鑰 | N1 公鑰 | 寫死 |
| 擴充 | N2 公鑰、N3 公鑰、晶片序號 | 寫死 |
| 有效期間 | 填固定值，**沒有人檢查**（D4） | — |
| 不放 | 角色、單位、網路、任何會變的東西 | — |

- bench 的格式與大小預算（≤ 416 位元組，608B 槽 8）已在 `255-608b-impl.md` §3.1 定案，本文件不改。**#255 的 PR 3 不用等本文件任何新欄位。**
- 量產憑證用同一組欄位、由原廠根簽。大小上限取決於 #426 選的晶片 ⚠️；晶片放不下就改放 p1（憑證是公開資料，放哪都不影響安全，只影響「重燒卡後還在不在」）。
- 晶片樣式之外的後端（之後的量產晶片）沿用 `Identity` 介面（D7、`255-608b-impl.md` §2.1）；架構不出現任何 608B 專有指令。

### 4.2 授權物件（T2 之下簽，COSE_Sign1 + CBOR）

所有授權物件共用一個外層，內容依類型不同。外層欄位就是 K5 要求綁定的東西：

| 外層欄位 | 內容 | 用途 |
|---|---|---|
| 類型 | 下表之一 | 不能把一種物件當另一種用 |
| 單位 | 信任錨公鑰的識別碼。**不是**錨金鑰的雜湊（§5.4：換錨後單位 id 不變） | 不能拿到別的單位用 |
| 網路 | 網路 id；和網路無關的類型填空 | 不能拿到別的網路用 |
| 目標 | 節點 id；對所有節點有效的類型填空 | 不能拿到別台用 |
| 簽章者 | 簽章金鑰的識別碼 | 找出該驗哪一條鏈 |
| 序號 | 見 §5.1：每個簽章者自己遞增 | 排新舊、擋重放（K4） |
| 世代 | 簽發當時的單位世代（§5.3） | 撤銷 |

| 類型 | 誰能簽 | 內容 | 對應 |
|---|---|---|---|
| 入庫 | A1，或 A1 指定的發證者 | 這台節點（節點 id）屬於這個單位 | 今天的「認領」；#54 |
| 指定發證者 | 只有 A1（K1、K2） | 某把金鑰可以發哪些類型、哪些角色、範圍多大 | #54 |
| 授予角色 | A1 或發證者 | 某把金鑰在某個網路（或整個單位）有某個角色與屬性 | #52 |
| 網路設定 | 有網路管理角色的金鑰 | 網路參數、成員節點清單、管理員集合、網路版本 | 已出貨的 `net_config` 的後繼；#13 |
| 秘密包 | 同上 | 對某台節點的 N3 加密的網路密碼（已出貨 ✅） | #13、K10 |
| 撤銷 | A1（撤任何人）；發證者（只能撤自己發的） | 被撤的金鑰或節點 id；新的世代 | §5 |
| 維修 | 有維修角色的金鑰 | 對某一台打開維修入口，到下次重開機或明確關閉為止 | #393、K23 |
| 更新授權 | 有更新角色的金鑰 | 允許某一台安裝某個發行物件（以雜湊指名） | §9、#393 |

**角色與屬性（和 #52 一起定；這裡定的是欄位，矩陣在 #52）**

| 欄位 | 值 | 寫死或可改 |
|---|---|---|
| 角色 | 發證者、網路管理、更新、維修、成員、唯讀。可以多個 | 重新簽發才能改 |
| 範圍 | 整個單位，或列舉的網路 | 同上 |
| 生命週期狀態 | 服役中、送修、報廢（#70）。寫在入庫物件上，針對節點 | A1 或發證者重簽 |
| 是否需要在場 | 這個角色的哪些動作要現場證明（§8.2） | 由 #393 的動作表決定，不由簽發的人自己選 |
| 不放 | 人名、職稱、到期日（D4）。到期用世代表達（§5.3） | — |

- **「等同 root 的權限」只有維修**（打開 shell）。K3：發證站不能單獨發。所以維修角色只能由 A1 直接授予，或由發證者授予但要 A1 的指定物件明確允許。
- **管理員集合寫在網路設定裡，改它需要目前集合中過半數的簽章，或 A1 的簽章**（K18：單一管理員不能換掉整組）。只有一位管理員的家庭網路，這條退化成 A1 自己。
- 一台節點多組網路：入庫物件對節點只有一份（一台只屬於一個單位）；網路設定可以有多份，各有自己的網路 id。今天「一台一個網路」（`provstore.go:9` ✅）是實作限制，欄位不擋。

### 4.3 節點自己簽的聲明（N2 簽）

| 聲明 | 內容 | 誰驗 |
|---|---|---|
| 當場證明 | 用途標籤 ‖ 這次交握的雜湊（已定案，`255-608b-impl.md` §3.2） | app、其他節點 |
| WireGuard 綁定 | 用途標籤 ‖ N6 公鑰 ‖ 節點 id ‖ 計數 | 其他節點（§6 第 5 步） |
| 狀態證明 | 用途標籤 ‖ 對方給的 nonce ‖ 映像版本與槽 ‖ 平台狀態（§10） | 工作負載、管理員（#97） |

每一種用不同的固定用途標籤；helper 只組它認得的標籤，不簽呼叫者給的任意值（`keystore.go:78-98` ✅ 的延續）。S-A、S-B 這條只靠 helper 軟體把關，持有節點的人可以繞過（威脅模型 S5）。

### 4.4 TAK 憑證（T3 簽）

- 和 Batman 的金鑰、CA 完全分開（D5）。兩邊靠「同一個帳號」連起來：ICS 一次報到發兩樣（Batman 的授權物件、TAK client 憑證），撤銷時兩樣一起撤。
- 節點的 TAK server 憑證私鑰放 p5，不放晶片（OTS 在容器裡，接不到晶片；⚠️ 這表示 S-A、S-B 拔卡就能冒充 TAK server）。
- 欄位、有效期（iOS 要求 server 憑證 ≤ 398 天 ✅ #170）依 #54、#58；本文件只定「分開」和「連結點是帳號」。

## 5. 撤銷

**前提**：沒有網路、沒有中心、節點沒有可信時鐘（D4）。所以 CRL 加到期日的作法都不成立（#58、#95 也是同樣結論）。

### 5.1 用序號與世代，不用時間

- 每個簽章者對自己簽的物件遞增序號。節點對每個（簽章者、類型、網路或目標）記住看過的最大序號，**只收更大的**（K4：重放舊物件不能讓節點回到舊狀態）。
- 單位有一個**世代**，只有 A1 能把它加一。每個授權物件都帶簽發當時的世代。

### 5.2 真正擋人的是換密碼

要讓被撤銷的人或節點**進不了網路**，唯一可靠的手段是換掉網路密碼，而且新密碼只加密給沒被撤銷的節點（N3）與人。這已經是出貨的作法（`wtxn.go` ✅）。因此：

- **撤銷一個成員或一台節點 = 一份新的網路設定（把它拿掉）加一輪換密碼。** 還沒收到新密碼的節點會掉出網路，等管理員手機或已更新的鄰居把新設定送到（送達方式是 §5-4 的題目，在 #13 的實作設計定；本文件只要求：新密碼絕不以舊密碼加密轉送，K11）。
- 被撤銷的人就算拿著舊授權去找一台還沒更新的節點，最多讀到**舊**密碼；新密碼不在那台上（K11 成立的原因）。
- 代價：每次撤銷都要碰到每一台。這是 K15 要量的東西（步驟數、等待時間、斷網時間），在 #13 的實作設計量測並交使用者決定。

### 5.3 撤銷下限：讓舊授權失效

換密碼擋的是進網路；另外要讓被撤銷的**授權**在節點上失效（例如被撤的管理員直接用 BLE 連上節點）。

- 撤銷物件由 A1 簽（撤任何人）或發證者簽（只能撤自己發的；**發證者自己有沒有被撤，只看 A1 簽的物件**，K6）。
- 節點存一個**單位世代下限**：看過 A1 簽的更高世代之後，簽發世代低於下限的授權全部拒絕（除了在新世代被重新簽發的）。這等於「大撤銷」：A1 加一次世代、重發還有效的人，其餘全部失效。用在發證者外洩、名單不可信的時候。
- 個別撤銷（撤一把金鑰、一個節點 id）是清單；清單有上限，滿了就由 A1 加世代清空。
- **下限與清單要撐過恢復出廠與重新入庫（K6）**。所以它們不能放在恢復出廠會清掉的地方。契約：
  - 存放處要「只能前進」而且恢復出廠不清除。bench 608B 有單調計數器（設定區 52–67，目前不用，`255-608b-config.md` §4 ✅ 存在；⚠️ 用法未設計、未實驗），可以存世代下限這一個數字。清單太大放不進晶片，放 p5 之外、恢復出廠不碰的區域，並以世代下限作為「清單不能比這個更舊」的錨。
  - 換一張全新的卡（#404）時清單會不見，只剩晶片裡的世代下限。所以**重要的撤銷（發證者、管理員）要靠加世代**，不能只靠清單。
  - 節點第一次入庫到某個單位時，世代下限取入庫物件的世代。換到另一個單位時下限怎麼辦（計數器只能前進，各單位的世代互不相干）→ ⚠️ 未解，§15 Q-D。
- 這裡的陷阱已記錄在 `255-key-authority.md` §5-1：下限若由發證者自己簽就成了自己證明自己；被入侵的發證站把下限推到最大會鎖死節點。本設計的回答：只有 A1 能動世代（發證者不行）；世代一次只能加一（節點拒絕跳號），所以要鎖死節點得先拿到 A1。

### 5.4 換掉信任錨（K7）

- 單位 id 在建立時隨機產生，**和錨金鑰無關**。換錨 = 舊錨簽一份「新錨是 X」的物件，世代加一。節點驗舊錨簽章後把信任的錨換成新的；既有網路的網路 id、單位 id 都不變，所以仍可管理。
- 舊錨已經遺失（不是外洩）時，沒有人能簽這份物件。小隊靠備份還原（Q3）。家庭見 §5.5。

### 5.5 家庭：家長手機遺失

家長手機的金鑰就是 A1，不可匯出。遺失後：

- 有第二支已被指定為共同錨的手機 → 用它換錨（§5.4）。**架構建議家庭入庫流程預設請使用者加第二支**，但不強制（K15）。
- 沒有 → 只能對每一台做實體操作重新入庫：恢復出廠（S-A：重燒卡；之後依 #402）加上機身 QR（N4）。這是 K8 列出的例外（信任錨本身沒了），要當殘餘風險交使用者接受（§15 Q-C）。
- N4 重燒卡後仍有效，所以機身 QR 是**永久秘密**：拿到 QR 又能碰到節點的人，可以把節點恢復出廠後入庫到自己名下。這不讓他讀到原主人的任何東西（網路密碼在 p5，恢復出廠已清），也進不了原主人的網路。防盜鎖（U9：先不做）才擋得了這個。

## 6. 准入：從出廠到加入 mesh，每一步檢查什麼

每一步都是「預設拒絕」（K14）。缺東西、過期、格式錯一律拒絕並留紀錄，節點維持上一步的狀態。

| 步 | 事件 | 誰檢查 | 檢查什麼 | 不通過 |
|---|---|---|---|---|
| 1 | 出廠燒錄 | 燒錄站（bench：`se-sign`） | 晶片設定讀回與影像一致、已鎖；才用 T1 簽節點憑證 | 不簽；晶片報廢 |
| 2 | 手機連上節點 | app | 節點憑證鏈到內建的根（開發版認開發根，量產版只認原廠根）；節點 id 與主體金鑰相符；**當場證明**（N2 簽這次交握） | 拒絕，什麼都不送、不存 |
| 3 | 入庫（認領） | 節點（helper） | 節點目前未入庫；認領證明（N4，CheckMac）；入庫物件的簽章者是它聲稱的錨 | 拒絕；計次限流（已出貨 ✅） |
| 4 | 加入網路 | 節點（helper） | 網路設定的簽章鏈到本節點的單位錨；世代不低於下限；序號更大；本節點在成員清單裡；秘密包的目標是本節點、解得開 | 整筆交易回滾到之前的狀態（已出貨 ✅ `node.go:1242-1311`） |
| 5 | mesh 鄰居 | 節點 | **第一層**：SAE，用這一版的網路密碼。**第二層（#16，v2.5）**：WireGuard，peer 只收「成員清單裡的節點 id」而且附有效的 WireGuard 綁定聲明（N2 簽） | 第一層：連不上。第二層：不建 peer |
| 6 | 手機 Wi-Fi | 節點 | 手機 Wi-Fi 密碼（每個網路一把，換密碼時一起換） | 連不上 |
| 7 | TAK | OTS | client 憑證鏈到 T3；帳號未停用 | TLS 失敗 |
| 8 | 管理動作 | 節點（helper，K12：每次都驗、不快取） | 呼叫者的授權物件鏈到錨、未撤銷、世代不低於下限、角色涵蓋這個動作、範圍涵蓋這個網路與這台；動作表要求在場時有在場證明（§8.2） | 拒絕並記錄（K24） |

**#13 在 v2.0 做到哪（誠實界線）**
- v2.0（#13）：拿掉預設金鑰（沒有有效的網路設定就不起 mesh，取代 `CHANGE-ME-NOW`）；密碼只對已入庫、通過當場證明的節點加密送達；成員離開就換密碼。到這裡，「知道 image 裡的東西」已經進不了網路。
- **v2.0 還做不到**：節點層級的個別驗證。mesh 第一層是共用密碼，batman-adv 不驗 OGM（`docs/threat-model.md` L2 列）。成員節點（或從成員節點的卡上讀出密碼的人，S-A、S-B）可以用任何裝置加入第一層。第二層（WireGuard，v2.5 #16）才讓「有密碼但沒有成員節點金鑰」的裝置收發不了資料。
- 即使有第二層，S-A、S-B 的 N6 在卡上明文，拔卡就能複製。**節點層級的個別驗證要到 S-C 才真的成立。**
- PTT 語音走 L2 多播，不經 WireGuard（#16 內文）。它只有第一層保護 → 殘餘風險，在 #16 與 #383 的聯合設計處理。

### 7.2 契約（缺、舊、壞的時候怎麼辦）

| 介面 | 寫 → 讀 | 何時有效 | 缺少 / 過舊 / 格式錯 | 誰寫得到（信任邊界） |
|---|---|---|---|---|
| 節點憑證 | 燒錄站 → app、其他節點 | 永久 | 拒絕連線（fail-closed） | 只有持 T1 的人 |
| 授權物件 | 錨、發證者、管理員 → helper | 簽章有效、序號更大、世代 ≥ 下限 | 拒絕、狀態不變、記錄 | 經 BLE、HTTP、mesh 的任何人都能**送**；能被接受的只有持對應金鑰的人。provd 是轉送者，看不到秘密明文（K10） |

| 更新授權 | 管理員 → helper | 指名雜湊、目標這一台 | 拒絕安裝 | 持更新角色的人 |

## 8. 授權的執行

### 8.1 一個決策點

所有管理動作（BLE、HTTP、CLI、之後的主控台 #14）都到 helper 的同一個函式判斷（K12）。provd、網頁、CLI 都只是轉送者，自己不做授權決定。TAK 是另一個系統（T3），它的授權在 OTS，不經 helper。

### 8.2 在場證明（#393、§5-7）

動作分兩類，表在 #393 定；架構只定「在場」的意思和它怎麼表示：

- **在場 = 授權的人當下在這台旁邊，而且這次請求是為這台、這一次簽的。** 表示法：請求裡帶節點當場給的 nonce，由呼叫者的金鑰簽；而且這次連線是近距離通道（BLE）。
- 這擋得了：遠端經 mesh 重放、被入侵的別台節點轉送。**擋不了**：撿到一支已解鎖的管理員手機的人。那要靠手機的使用者驗證（今天沒開，`Keys.kt:64-98` ✅），開不開、哪些動作要，是 K15 的取捨，在 #393 交使用者決定。
- 實體按鍵（v3.0 新 HAT）可以再加一層「人真的碰到機器」；v2.0、v2.5 的硬體沒有，架構不依賴它。

### 8.3 維修入口（K23、§5-14）

- 量產建置預設沒有 shell。打開要一份「維修」授權物件：指名這一台、要在場證明、由有維修角色的金鑰簽。
- 打開後裝上的 SSH 公鑰寫在 tmpfs，**重開機就消失**；另外有明確的關閉動作。不綁時間（D4）。
- 沒有萬用密碼、沒有原廠後門（K22）。現場連不到發證站也能開，因為授權是事先發給維修人員的角色，不是當場去要。
- 開發建置可以讓 SSH 一直開（U7）。

## 9. 開機鏈與更新

### 9.1 誰能做軟體更新（§5-8）

**兩把鑰匙，分屬兩個信任根：**

| 要回答的問題 | 誰 | 物件 |
|---|---|---|
| 這是不是我們發的、沒被改過 | 發行根 R → K（T4） | 發行物件（已出貨 ✅） |
| 這台節點的主人同不同意現在裝 | 有更新角色的金鑰（T2 之下） | 更新授權（§4.2） |

- 我們簽了映像不等於能裝到別人的節點上（K22）。主人同意了也不能裝不是我們簽的映像。
- 更新角色和網路管理角色分開，但可以發給同一把金鑰。不歸到維修（等同 root）角色，否則每次更新都要動用最高權限（§5-8 的陷阱）。
- 版本下限（擋降版）沿用已出貨的機制（`254-p3-impl.md` §3.7 ✅）。**經更新管道的升級或回退都不能讓已收回的權力復活（K13）**：世代下限與撤銷清單放在 A/B 兩槽共用、不隨槽切換的地方。

### 9.2 開機映像簽章（#405、#115）

- #405（v2.0）：CI 產出簽好的 `boot.img`。Pi 4 不燒 OTP，所以 S-A、S-B **不強制**；做的是流水線與金鑰分工（開發金鑰在 CI、量產金鑰離線）。
- #115（v2.3）：CM4 燒 OTP 後才強制。OTP 不可逆，先在專供測試的 CM4 上做完整流程。
- dm-verity 的 root hash 在簽章範圍內（#405、#74）。

### 9.3 #401、#402、#404 需要的

- **LKG 狀態在 LUKS 解鎖前讀得到**：放不加密的地方，內容沒有秘密。S-C 起，竄改它最多讓節點退回另一個**同樣簽過**的槽；版本下限擋住退到有已知漏洞的版本。
- **重置設定（#402 第 4 級）清什麼、留什麼**：

| 留 | 清 |
|---|---|
| 晶片裡的全部（N1–N5）、世代下限、撤銷清單、入庫次數、稽核紀錄 | 網路設定、網路密碼、手機 Wi-Fi 密碼、WireGuard 金鑰、SSH 主機金鑰與任何已裝的 SSH 公鑰、入庫紀錄（錨） |

  重置後節點回到「未入庫」，用同一張 QR 重新入庫（#402、#404 的驗收）。重新入庫到**原單位**時，節點 id 不變，管理員重發網路設定即可回隊。
- **換卡（#404）**：晶片裡的還在；卡上的全沒了（撤銷清單也是，§5.3）。LUKS 金鑰由晶片與主機導出，和卡無關，新卡首次開機重新建立加密分割區。

## 10. 證明（attestation，#97）

節點能證明的東西取決於平台狀態。介面是 §4.3 的「狀態證明」；**內容的可信度由驗證者依平台狀態判斷，節點自己不能宣稱比實際高的狀態**。

| 狀態 | 一份有效的狀態證明代表什麼 |
|---|---|
| S-A、S-B | 只代表：這顆晶片現在接在回答的那台主機上。映像版本等欄位是主機自己填的，不可信 |
| S-C、S-D | 晶片要主機授權才肯簽（#414），而授權值只有開了簽過映像的這顆 CM4 算得出來。所以簽得出來 = 這台開的是我們簽過的映像。映像版本由簽過的映像自己填，可信到「我們簽過的映像不說謊」的程度 |

- Pi 沒有量測開機（沒有 PCR）。這裡做的是「簽不出來就是沒過」的隱含證明，不是逐級量測。這是商用等級，不是高保證等級（`productization.md` 與 #74 已寫明）。
- 平台狀態怎麼讓驗證者知道：寫在節點憑證的簽發根上。S-C 起的量產節點由原廠根簽，而且原廠根**只簽已綁主機的晶片**（出廠站在燒 OTP、綁定之後才簽）。開發根簽的一律當 S-A。
- 金鑰釋放綁證明（#47）：N7 的導出本身就是（S-C 起，沒開簽過的映像就導不出磁碟金鑰）。工作負載要不要把資料交給節點，依狀態證明自己決定（#97）。
- 工作負載身分、發佈者允許清單（#97 第 1、3 項）：發佈者金鑰是獨立的（M5），允許清單是一種授權物件，由有對應角色的金鑰簽。細節在 #97。

## 14. 不在本版架構裡的

## 17. 安全檢查（`REVIEW.md` 第 5 項）

- **攻擊面變化**：本文件是設計，不新增任何輸入。它定義的新輸入（各類授權物件、WireGuard 綁定、狀態證明）在各單實作時各自過 L3。所有授權物件都經既有的 BLE／HTTP 通道進到 helper，由 helper 驗證；provd 不解析內容。
- **權限**：驗證與晶片操作在 root 的 helper（K12、K21）；面對無線電的 provd 維持非 root、只轉送。
- **秘密**：不進紀錄（K24）、不進 URL、不以明文經過 provd（K10）；S-A、S-B 磁碟上的秘密視為持有節點的人讀得到。
- **失敗模式**：全部 fail-closed，唯一例外在 §7.2 寫明。
- **每個 actor**：

| actor | 最壞能做什麼 | 靠什麼擋 |
|---|---|---|
| 遠端（空中、不知道密碼） | 干擾空中（擋不了，`docs/threat-model.md`）；對 BLE 送垃圾 | §6 步驟 2、3、8 的限流與預設拒絕 |
| 手機 Wi-Fi 或 mesh 上的人（知道密碼的成員） | 第一層的任何事；v2.5 起收發不了別人的 WireGuard 流量 | §6 界線；K23 |
| 節點上的非 root 程序 | 送請求給 helper | helper 驗授權；晶片只有 root 能碰 |
| 被入侵的 provd | 丟棄、延遲、重放訊息；看不到秘密 | 序號、世代、端到端加密（K10、K4） |
| 被入侵或離職的管理員 | 在被撤銷前做他權限內的事 | K18（不能換掉整組）、紀錄（K24）、撤銷加換密碼 |
| 被入侵的發證站 | 發出權限內的授權 | K2、K3；A1 加世代可一次作廢（§5.3） |
| 拿到節點的人（S-A、S-B） | 讀卡、用晶片簽、複製 N6、讀網路密碼 | 拿不到 N1–N3 私鑰；撤銷加換密碼後他手上的都作廢。**在那之前他等於一個成員** |
| 拿到節點的人（S-C、S-D） | 拆機、量匯流排 | 開不了自己的系統；晶片綁主機 |
| 供應鏈（映像、套件） | 植入程式 | T4 簽章、SBOM（#73）；S-C 起開機鏈 |
| 我們自己 | 簽錯、金鑰外洩、把開發根放進量產建置 | 根分開（§2）；量產建置的負向測試：開發根簽的憑證要被拒（已是 `trust_gate` 的行為 ✅ `255-608b-impl.md` §3.2） |

- **負向測試**（各單實作時要有，這裡列出架構要求的最小集合）：
  1. 開發根簽的節點憑證，量產版 app 與量產節點都拒絕。
  2. 舊序號的網路設定重放 → 拒絕，狀態不變。
  3. 被撤銷的管理員直接連 BLE 做管理動作 → 拒絕並有紀錄。
  4. 恢復出廠後再入庫，撤銷前簽的授權仍被拒（K6）。
  5. 單一管理員簽的「換掉管理員集合」→ 拒絕（K18）。
  6. 沒有更新授權、只有發行簽章的映像 → 不安裝；有授權但發行簽章不對 → 不安裝。
  7. 沒有有效網路設定的節點不起 mesh（取代 `CHANGE-ME-NOW`）。
  8. 發證者簽的「指定發證者」→ 拒絕（K2）。
