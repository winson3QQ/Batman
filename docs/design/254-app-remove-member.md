## 0. 範圍

做:
1. 網主:選「一個人」或「自己的某一台節點」→ 確認 → 產生 v+1 → 先寫紀錄(同時作廢所有未用邀請)→ **先**為每位留下的成員產更新包、交出去 → **最後**才由網主按按鈕把自己的節點換成新密碼。
2. 成員:貼上更新包 → 驗證 → 寫 mnet;**等網主說包都發完了**,再按狀態頁「把新密碼送給節點」送給自己的每一台相關節點(匯入後不自動送,§3.4)。
3. 共用規則:自己擁有的節點版本落後於手機紀錄 → 狀態頁出現「把新密碼送給節點」(網主、成員都用)。
4. 紀錄存歷代版本;邀請在 v2 之後仍能用;被移除的人可以再被邀請。

不做(原因):
- 網主直接連別人的節點(psk_member):使用者選了轉交;app 也沒有成員連線(R14)。所以 NU §3 的「成員 session pin DAC」「轉送後 session 被斷」「2 個槽位」**不適用**:本單只用擁有者連線,它已 pin 節點紀錄裡的 DAC(R20)。
- 移除別人的單一台節點、移除共同網主:使用者決定 / NU §7(只有網主自己的節點可以單台排除)。
- 改國碼 / 頻道 / 名稱:同一條 update 路,但本單產生的版本只改 SAE、net_root、成員清單;**不變式:本單產生的每一版 netcfg 除 version / prev_hash 外與前一版逐欄相同,admins 永遠不變**(NU §3)。
- QR:相機另案;16 人的成員清單約 4.6 KB,一張 QR 放不下(R16)。kind 4 與剪貼簿只在 dev-trust build(同邀請,invite.rs:12)。
- LoRa PSK / team AP:app 的 secrets 沒有這兩個欄位(R21)→ 不適用。
- 219 §3.3 換密碼前的新鮮 peers/challenge:擁有者連線已 pin DAC、階段 1 file 後端;不做。
- 網主確認別人的節點換好了沒:連不到、沒有回報管道;誠實寫出(§3.5)。
- 網主手機遺失 / 被拿走:ADMIN_SIGN 不需要使用者驗證(Keys.kt:70-80),拿到解鎖手機的人能做任何網主動作。不是本單新增的面 → 誠實界線 + checklist(§6、§9)。

## 2. 資料

### 2.0 名詞
- 用語:**節點版本** = 節點 info 的 key 9;**歷代** = 網主紀錄的 k13 / 成員紀錄 mnet 的 k9(兩者格式相同);**手機版本** = 網主紀錄的目前版本 / mnet k2。下文的「k9」一律寫明是哪一個。
- **網路裡的自己節點**(網主)= k11 中 owner_pub = 自己的項(不論 joining / approved / applied);`node/` 擁有者紀錄只用來登入。被排除的節點在 commit 時從 k11 刪掉 → 它可能還在 `node/`,但**不是**網路裡的自己節點。
- **網路裡的自己節點**(成員)= 這支手機擁有(`node/`)、且是 mnet k7 或 mnet k10 有它目前版本 secrets 的節點(= 入口 3 的集合)。
- **對象守則**(三個入口各自檢查,只檢查各自需要的;都在任何寫入或 SignAdmin 之前):
  1. **網主送 `network/update`(§3.2)**:目標 dac_hash 必須在 k11(owner_pub = 自己);net_secrets 的 ecdh_pub 只取自那一項。被排除的節點在 commit 時已從 k11 刪掉 → 不送。不看 removed。
  2. **網主 join2 加一台自己的節點**:在 join2 的**第一次 SignAdmin 之前**(begin 階段,join2flow.rs:298-366;不只是 PersistNet 之前)查目標 dac_hash:**「之前被移出過」= 在 k14(v6.5)、k13 任何一版或目前版本的 removed 裡**(入口 2 與同意畫面用同一個判斷,B-m2)→ 確認對話框「這台之前被排除(遺失 / 被抓),確定它回到你手上、而且沒被動過嗎?」;確認是 join2 begin 的參數、由 Rust 強制(同 ApproveFlow::start,B-m2);按否 = 0 次寫入、0 次 SignAdmin;按是或不在 removed(全新節點)→ 照今天的 join2(它自己建 k11 項,join2flow.rs:12-13)。
  3. **成員送 `network/update` / 隊員模式加入**:目標必須是 mnet k7,或 mnet k10 有它的**目前版本** secrets。不看 removed(能送的 secrets 都已由網主加密給特定節點,成員端守則不是防線,B-M2)。
- 不符 → 不送,畫面:網主 1 →「這台不在隊伍網路的成員名單裡(被排除或被忘記),只能『離開網路』;要加回請用『加入網路』」(第 8 輪 A-m8:被忘記的節點也會看到);成員 3 →「這台的新密碼不在這支手機,請網主重新產生你的更新包」(A-MAJOR-1)。

### 2.1 網主紀錄 `net/<id>`
- **k13 歷代**:`[ {1 version, 2 netcfg Sign1, 3 members Sign1} ]`,版本遞增。沒有 k13 的紀錄 = 一項,由 k7 / k8 補成,**version 取 k7 payload 的 key 2**(降級後 k7 可能已是 v2)。保留最近 32 版(連續;只做必要的,A-m13:不再為 creator 保留最舊一項)。
- k7 / k8 = 目前版本;k5 / k6 = 目前版本的 SAE / net_root。
- **`creator()` 不變**(k8 第一筆),但**它的使用者都改成只在紀錄 pending 時用**(v6.2 的「applied 之後只剩畫面標示」是錯的:今天 `confirm()` 不看 state、「確認網路」按鈕對 applied 紀錄也在,netrec.rs:307-329、nodes.dart:1130-1133;第 8 輪 A / B MAJOR):
  - `confirm()`:**前兩個檢查照舊在前**(join_state 不是本網 Applied → NoChange;節點版本 ≠ 紀錄版本 → OtherVersion;`save_pending` 照舊取自 info);通過之後,紀錄 applied → 回「已建立」(Already),**略過「呼叫 creator() 與升級」那一步、不碰 k11**(第 9 輪 A-m1 / B-m1);只有 pending 才升級建立者(否則建立者被排除後,k8 第一筆換成別人,按「確認網路」會把別人的 approved 項或自己另一台 joining 項改成 applied)。
  - `forget_joining`(與 bridge owner.rs:127 的重複檢查)、`net_summary` 的建立者標示:只在 pending 時呼叫 `creator()`;applied 時不呼叫(k8 可能是空的 —— 排除最後一台、沒有其他成員 —— `creator()` 會回錯,不能讓它擋住 forget / 畫面)。
  - 新版 members 不另外排序:key 4 照 k11 的順序(k11 本身建立者在前);產 v+1 不呼叫 `creator()`(否則排除最後一台、k8 空的時產不出新版,緊急換密碼被擋)。v6.3 的排序規則依「只做必要的」刪掉(第 9 輪 A-m5 / B-m7)。
- k9:不再使用,留著。
- **k14 離開過的項**(v6.5):`[ {1 dac_hash, 2 owner_pub, 3 name} ]`,換密碼 commit 時把本次排除的每一項加進去(同一台只留最新一筆),只增不減。理由:成員名單只在換版時重簽、同意時不重簽,所以「在 v 之後被同意、在 v+1 被移除」的項**不會出現在任何一版的 members**(實作審查 r1 A-F1 / B-MAJOR-1 實驗證實)—— 只靠歷代 members,§3.6 的「之前的擁有者」幾乎永遠是「不明」,而且「被移除的人換一台全新節點申請」(比 owner_pub)**根本不會跳框**。§2.0 入口 2 與 §3.6 的「之前被移出過」判斷與「之前的擁有者」**先查 k14,再查歷代**。降級的舊 app 寫回會丟 k14 → 回到只看歷代 members(誠實界線,§5 降級列)。
- **成員項 k10 = 這台節點的擁有者確定擁有的版本**:同意他時的版本。**缺 k10 = k13 最舊一版 − 1**(今天所有既有的項都缺;降級再升級也會缺;這樣產包一律從 k13 最舊一版起,不需要特殊條件,A-m6)。複製更新包**不**推進它。**k10 只在 k11 的編碼出現,不寫進 mnet k7**(member_value 拆成兩個編碼)。
- k12 邀請:換密碼的那次寫入把所有 `used = false` 改成 `true`。
- 不再有「進行中的換密碼」(v2 的 k14 拿掉,只做必要的):**可能還要包的人** = 成員項 k10 < 目前版本、owner_pub ≠ 自己(這支手機看不到對方是否已匯入,所以第一次換版後這份清單會一直是全部成員);自己的節點還沒換 = §3.5 共用規則。第二次移除不必等第一次「結束」。
- 寫入:Rust store 唯一寫者、CAS(R4)。所有寫回紀錄的流程(R24)把 k13 與成員 k10 納入 NetRec 結構,原樣保留。

### 2.2 成員紀錄 `mnet/<id>`
- **k9 歷代**:同 k13 格式,從這支手機第一次匯入的版本起,保留最近 32 版。沒有 k9 = 只有目前版本(k3 / k4)。
- **k10 本版給自己節點的 secrets**:`[ {1 dac_hash, 2 net_secrets Sign1} ]`(這支手機擁有、且包裡有的每一台)。**取用時比對 secrets payload 的版本 = mnet 目前版本**,不符當作沒有。
- **k5 = k7 那台的目前版 secrets**(隊員模式加入只送 k5,R17);匯入時一定換成新版(§3.4-4)。mnet 沒有 k7 時 k5 不動、也不使用(沒有 k7 就沒有隊員模式加入,B-m7)。
- k2–k6 = 目前版本。
- **同意包匯入的 +1 路**寫進 mnet k9 的 members 要驗 prev_hash = 舊 members 的 OBJECT_HASH(今天 approve.rs:304-317 只驗 netcfg 的,B-m9)。
- **其他寫入者要帶上 k9 / k10**(R27,A-M5):`approve::import` 從頭建 MNet 時,若已有同 net_id 的 mnet:同版路 → k9 / k10 帶過去;**+1 路 → k9 帶過去(舊 mnet 沒有 k9 時,把舊的 k3 / k4 當成一項帶過去)並加上新的 k3 / k4,k10 清空**(舊 k10 是前一版的 secrets,帶過去會被送給節點而被拒,A-M1);走 TooOld 取代(§3.6-2)時 k9 重設為只有這一版、k10 清空;join2 隊員模式寫 mnet 時原樣保留 k9 / k10。歷代中間缺的版本 = 「沒有,不比」(B-m2)。

### 2.3 更新包(kind 4,網主 → 成員)
```
{1: net_id,
 2: [+ {1 netcfg Sign1, 2 members Sign1}],   ; 從 start 到目前版本,連續
 3: [+ net_secrets Sign1],                    ; 目前版本,給這個人在 k11 的每一台節點各一份
 4: member_secrets Sign1}                     ; 目前版本,給這個人的 owner_enc_pub
```
- **收件人契約**(B-M1):按下「產生更新包」時照同意的做法**重讀一次紀錄**(Dart `_readRecord` = Rust `storeReadSealed` + Kotlin `open`,nodes.dart:614-621、:696),解碼一次交給 Rust,k11、k5 / k6、k13 都出自這一次讀取(第 8 輪 B-m2、第 9 輪 B-m3);產包不寫紀錄,與 commit 競爭時最多產出舊版的包,而收件人在那次讀取時就在 k11、本來就有那一版 → 不漏;產包只從**目前的 k11** 取 owner_pub = 這個人的項(net_secrets 的對象與 ecdh_pub)與他的 owner_enc_pub;一項都沒有、或 owner_pub = 自己 → 拒絕,0 次 SignAdmin(不吃畫面快取、不吃 k13 歷代)。同一個 owner_pub 的各項 owner_enc_pub 不一致 → 拒絕產包,告警「這位隊員的資料不一致 —— 請先移除這個人,再重新邀請」(已入網的項重新申請會被回 AlreadyMember,approve.rs:78-84;第 8 輪 A-m5)。
- **start = max(這個人各節點項 k10 的最小值 + 1, 目前版本 − 15, k13 最舊一版)**:鏈最多 16 步。**網主端一律產包**(A-M4 / B-M1:k10 只在同意時設、不會前進,網主端不能據此拒絕);成員端若接不上(§3.4-2)才說「你的資料太舊,請網主讓你的節點離開網路、再重新邀請你」(重新邀請會重設 k10)。
- exact keys;鏈長 ≤ 16 步、整包**解碼後** ≤ 128 KiB(剪貼簿的 hex 約兩倍;超過 → 拒,不驗簽,B-m2);成員已在目前版本 → 不產包。降級再升級後(k13 只剩目前版本):缺 k10 = 目前 − 1 → 清單列出他們、產只含目前版本一步的包,標「升級前的版本不明」(他剛好落後一版才接得上;接不上 → 他的節點離開再重新邀請,A-m4 / v3 A-m10)。
- 16 人時一步約 4.4 KB(NU §3 實測);16 步約 70 KB(剪貼簿可以;QR 那案另算)。
- CDDL:kind 4 加進 219-protocol.cddl 的 qr-object(§9)。

### 2.4 新版本(v+1)
- **v = 紀錄的目前版本**。開始前,網路裡的自己節點(不含這次要排除的那台;**只算 join_state = Applied 的**,NotApplied / OtherNetwork / InProgress 都不算,A-m8)逐台以擁有者連線讀 info;info 回 Unknown / 逾時 = 連不上;連得上的每一台:k9 > v → 不開始,告警「這支手機的紀錄比節點舊(可能還原了舊資料)」,出路 = 重建網路(全隊重新加入);k9 ≤ v 且 k9 那一版在 k13 裡 → 可以(A-M1:第二次移除時自己的節點本來就還在舊版)。告警要**指名是哪一台**(device_id 後 4 碼):被抓、還沒排除的節點謊報 k9 就能擋住換密碼 → 網主可以先把那一台排除(檢查本來就不含這次要排除的那台);兩台以上同時謊報會互相擋 → 告警加一句「若這些節點不在你身邊,關掉手機藍牙再開始」(連不上 = 不檢查,B-m1)。自己節點 k9 不在 k13 裡(比歷代還舊)→ 不擋開始,那台之後由 §3.2 說「落後太多,離開再加入」。網路裡還有自己節點但一台都連不上、或已沒有自己的節點(排除最後一台)→ 可以開始,對話框寫明「沒有你的節點可以確認這支手機的紀錄是最新的」(緊急換密碼不被擋,A-m3)。
- netcfg:除 version = v+1、prev_hash = OBJECT_HASH(v 的 netcfg) 外逐欄沿用;由 v 的 admins(= 這支手機)簽。
- members:net_id、version、prev_hash = OBJECT_HASH(v 的 members);key 4 = k11 中狀態 applied / approved、且不在本次排除對象裡的項目,**每項恰為 cose::Member 的 key 1–5**,順序 = k11 中的順序;key 5 removed = (v 的 removed ∪ 本次排除的 dac_hash) − key 4 的 dac_hash;key 6 / 7 = v 的值(今天空)。
- 本次排除對象 = 選中的人在 k11 的所有節點(owner_pub = 他),或網主自己選中的那一台。
- secrets:新 SAE(同 join 的產生器)、新 net_root(32 B 隨機)。
- 同一個版本號只簽一次:netcfg / members 寫進 k13 後不再重簽;net_secrets / member_secrets 每次送 / 產包時用 k5 / k6 現產(臨時金鑰不同、內容相同),不存。

### 2.5 大小
- k14 每筆約 0.1 KB(每台被排除過的節點一筆,不修剪;33 次移除 ≈ 3 KB,實作審查 r2 A 量到整份紀錄 71 KB,主要是 k13)。壞掉的 k14(型別、長度、缺欄)→ 整份紀錄打不開(fail-closed:確認框不能靜默消失;t38_a_malformed_key_14_is_fail_closed)。
- k13 每版約 0.5 KB + 每位成員 0.3 KB + removed 每筆 32 B(只增不減,B-m7;100 筆 ≈ 3 KB / 版);16 人 × 32 版 ≈ 160 KB。塊數檢查(§3.2-3)本來就是實算,含 removed。⚠️ 封存檔實際上限實作時量測;若 32 版放不下,調低保留版數(產包的 −15 不受影響,保留 ≥ 16 版即可)。

## 3. 流程

### 3.1 網主:開始
- 成員名單頁以「人」分組:每組顯示名稱、**owner_pub 指紋(前 8 碼)**、每台節點的 device_id 後 4 碼(名稱由成員自取,可能重複)。同一個真人換過手機 / 重裝 app = 另一個 owner_pub = 另一組;同名的組在移除對話框列出「另有同名的一組:〈指紋〉」,要一起移除得各按一次(B-m4)。別人那組有「移除這個人」;自己那組每台節點有「排除這台(遺失 / 被抓)」。
- 前置(任一不成立 → 不開始並說明):
  1. 這支手機是網主,且**目前 netcfg 的 admins == [這支手機的 ADMIN_SIGN 公鑰]**(只有一位網主;不是時不開始,B-m9),紀錄 state = applied;
  2. 沒有 joining 的成員項,**本次要排除的那一台除外**(卡在 joining 的自己節點被抓也要能排除;排除時一樣進 removed,A-M1 / B-M2);
  3. 對象不是自己這個人(排除自己的單台可以,**包括最後一台**,使用者決定);
  4. §2.4 的版本檢查(k9);**開始時不檢查 k4**(被抓的節點可謊報 k4 擋住換密碼,而 §3.2-2 每次送出前本來就查 k4,B-M1);
  5. 確認對話框裡使用者勾選「全隊的節點都已更新到新版軟體」(別人的節點這支手機看不到,只能由網主確認,§6 M2)。
- 確認對話框(移除一個人):
  「要把〈名稱〉(〈指紋〉)的 N 台節點移出隊伍網路嗎?全隊會換一組新密碼。順序:① 這支手機先產生每位隊員的更新包,你把包交給他們(他們用自己的 app 匯入,他們的節點才會換);② 包都交出去之後,再按『把新密碼送給節點』換你自己的節點 —— 你的節點一換,就和還沒換的人斷線,之後很難再把包傳出去。在大家都換好之前,隊伍會暫時分成兩邊。如果〈名稱〉的節點是某些節點唯一的轉送路徑,換完後那些節點會斷線,直到附近有別的節點。被移除的人之後可以由你重新邀請(他的節點若在舊設定裡接不上,要先離開網路再加入)。所有還沒用的邀請會作廢。換完後請每位隊員把自己節點的手機 Wi-Fi 密碼改掉。」
  (排除自己的一台:「要把你的節點 …〈後 4 碼〉排除在隊伍網路外嗎?」+ 同樣的順序與提示。)
- 產生 v+1(§2.4)→ SignAdmin netcfg、members → **寫紀錄(CAS)**:k13 加一項、k5–k8 換新、k11 刪排除對象(**k11 一律寫成實際的清單**,即使是空的也不留 None,第 9 輪 B-m5)、k12 未用邀請全標 used。**這次寫入是唯一的 commit 點**;之前任何失敗 = 什麼都沒變。**commit 之後不自動送任何節點**(A-M1)。
- 接著直接進 §3.3(產包畫面)。
- 排除最後一台之後:網主手機仍保有紀錄,照樣產包;之後認領一台新節點用 join2「加入網路」加回(用目前版本)。

### 3.2 送給自己的節點(網主與成員共用;狀態頁「把新密碼送給節點」)
對一台自己擁有的節點(擁有者連線,已 pin DAC):
0. 對象守則(§2.0 入口 1 / 3)。
1. 讀 info,依 `flow::join_state`(R22):Unknown(缺 / 限速)→ 等 2 s 再讀,三次仍是 → 「稍後再試」;InProgress → 「節點正在加入,稍後再按」;OtherNetwork → 「這台在別的隊伍網路」(停);NotApplied → 導向隊員模式 / 網主的「加入網路」(先過對象守則入口 2 / 3;成員端只在 k10 有、不是 k7 的節點不能走隊員模式加入(join2flow.rs:339-341 NotThisNode)→ 直接說「這台要請網主重新邀請」(B-m5);用手機的目前版本加入,節點接受 v>1,R15);Applied 且 k11 = true → 「節點還有沒完成的變更,等一下再按;超過 10 分鐘仍如此,重新開機一次」(與狀態頁同一句,A-m2)。
2. Applied:k4 不通過 §3.6 → 「這台要先更新軟體」(停);k9 = 手機版本 → 「已是新密碼」;k9 > 手機版本 → 告警「節點比這支手機新」(停,不送)。
3. k9 < 手機版本:鏈 = 歷代 (k9, 目前] + 這台的目前版 net_secrets(網主:現產;成員:mnet k10 / k5 中 dac_hash = 這台的那份;沒有 → 「這台的新密碼不在這支手機,請網主重新產生你的更新包」);歷代裡沒有(節點版本 + 1)那一版 → 網主手機與成員的 k7 那台:「這台落後太多版,請讓它離開網路再重新加入」;成員只在 k10 的節點:「這台落後太多版,請網主重新邀請這台」(離開後隊員模式只認 k7,第 8 輪 A-m4);**app 分塊器實算 > 8 塊 → 同一句,不送**(R13)。
4. 送 `network/update`(不帶 key 7)→ 不論回應,再讀 info(NU F17):k9 = 目前 → 已換;k11 = true → 套用中;k9 未變 → `E_REJECTED{2:14}` = app 的錯(告警);其他 → 「沒有換成功,可再試」。
- 「k9 = 目前」足以判定的理由:擁有者連線 pin DAC、網主只有一位且同版只簽一次、admins 不變、送前檢查 k4 → 唯一能造出同版號另一份的是第二位簽署者(本單不支援,NU F18),或**網主紀錄被回滾後重簽**(§6:k9 檢查只擋部分,回滾 dev 機上可經 adb,本 PR 設 allowBackup=false)。**例外**:分裂期間還是 wsl.24 的節點可能被 F10 污染(k9 新、SAE 舊),升級後 app 讀到 k9 = 目前就判「已是新密碼」,app 分不出 —— 誠實界線,§3.5 的提示要這些節點離開再加入。

### 3.3 網主:給每位成員更新包
- 列出 k11 中 owner_pub ≠ 自己、且 k10 < 目前版本(缺 k10 依 §2.1 的預設)的每一個人(以 owner_pub 分組):名稱、指紋、「這次已複製 / 未複製」(只是畫面記號,存在記憶體 / 不擋任何事)。這個人有缺 k10 的項、而且 k13 最舊一版 > 1(降級再升級後;再換版也不會消失)→ 標「升級前的版本不明 —— 若他匯入失敗,請讓他的節點離開網路、再重新邀請」(第 8 輪 A-m2)。按一位 → 產 §2.3 的包 → 複製到剪貼簿,(不另做敏感標記:包裡只有密文與名冊;成員端照今天貼上的做法,**按下貼上那一刻就清空剪貼簿**(nodes.dart:603-607);網主手機的剪貼簿會留著最後一份包,剪貼簿歷史 / 同步看得到名冊與密文 —— 誠實界線,只做必要的,A-m12、第 9 輪 A-m4 / B-m4)。
- 固定說明:「已複製 ≠ 已換好。對方要在他的 app 匯入,他的節點才會換;這支手機看不到對方節點的狀態。包都交出去之後,再到狀態頁把你自己的節點換成新密碼。」
- 這個畫面隨時可從成員名單再進來(「產生更新包」),與有沒有新的移除無關。

### 3.4 成員:匯入
「貼上網主的更新包」(dev-trust build)→ 第一段(Rust)讀 mnet(記 generation)並依序驗證,全過才進第二段:
1. 大小 / 形狀(§2.3);net_id = 某個 mnet;沒有對應 mnet → 「請先匯入網主的同意」;
2. 鏈:把鏈中 ≤ mnet 目前版本的各版去掉 —— 與 mnet k9 中同版號者逐 byte 比對,不同 = 分叉(拒絕並告警);比 mnet k9 最舊一版還舊的,**略過不比**(B-m3);剩下的第一版必須 = mnet 版本 + 1,netcfg 由 **mnet k3 的 admins** 簽、prev_hash = OBJECT_HASH(mnet k3);之後每一版由前一版 admins 簽、prev_hash 連續、version 連續、net_id 相同、國碼 = 前一版;members 由前一版 admins 簽、net_id / version = 該版、prev_hash = 前一版 members 的 OBJECT_HASH;第一版 > mnet 版本 + 1 → 「你的資料太舊,請網主讓你的節點離開網路、再重新邀請你」(重產會得到同一個起點,沒有用;與 §2.3 一致,第 8 輪 A-m1);
3. **net_secrets / member_secrets 都要是 Sign1,由前一版 admins(依不變式 = 目前版 admins)簽**,net_id / version = 目前版本(B-M1:ECDH-ES 不認發送者);
4. net_secrets 的 target:對這支手機擁有的節點(node/ 紀錄)逐一配對,至少要有一份配到自己的節點;**只有在這份包會讓手機版本前進時**,若 mnet 有 k7,包裡必須有 k7 那台的 secrets(否則拒:「這份更新包沒有你節點 …〈後 4 碼〉的新密碼,請網主重新產生你的更新包」;k5 不能留舊版,A-m7)。手機版本不變(「已經匯入過」分支)時不要求 k7(A-MAJOR-1:先貼第二台的同意包、後貼較早的更新包時,包裡只有第一台的 secrets,這是對的);
5. member_secrets 的 target = SHA-256(自己的 owner_enc_pub);
6. 包裡有 secrets 的每一台自己節點都不在目標版本的 removed(否則「你這台節點(…〈後 4 碼〉)已不在這個網路,請向網主確認」,不寫);**不要求 k7 在 members**(在這一版之後才被同意的節點本來就不在 members,A-M1);
- 包比 mnet 舊(包的目前版本 < 手機版本)→ 「這份更新包比你的紀錄舊,已忽略」,不寫(A)。
- 鏈全部已有、目前版本 = mnet 版本 → 「已經匯入過」;若包裡有 mnet k10 沒有(或版本不符)的自己節點 secrets,**一樣跑規則 3–6**(規則 6 只看 removed)後在同一次 CAS 補進(B-m4)。
- 第二段:Kotlin ECDH → Rust 解出 net_root → **以第一段的 generation 做 CAS**(同 approve 的 pend_gen 做法;中間有別的寫入 → 「請網主再複製一次你的包,再貼上」—— 剪貼簿在貼上時已清空):k9 加新的各版、k2–k6 換成目前版本(k5 = k7 那台的新 secrets)、k10 換成本版各節點的 secrets。明文 net_root 用完歸零。剪貼簿在貼上時已清空(B-m7,第 9 輪更正說法)。
- 貼上順序提示(A-m4 / A-m7 / B-m5):網主產第二台的同意包時,若這個人還有沒換的版本(他的 k10 < 目前)→ 同意畫面加一句「請他先貼更新包,再貼這份同意」;換密碼時這個人有**換密碼前產、還沒用的同意包**(k11 有他 approved 而 k10 < 目前)→ 產更新包畫面加一句「他手上若有換密碼前的同意包,請先貼同意包、再貼更新包;順序反了就要重新邀請那台」(第 8 輪 A-m3);成員端 TooOld 取代的確認框加一句「若你手上還有網主給的更新包,先貼更新包」。
- 匯入更新包之後再貼舊的同意包:approve 回 NoRequest(approve.rs:348 比 secrets bytes)→ 句子「這份同意已經過時,你的網路紀錄已是較新的版本」(A-m7)。第二台節點的同意包若在換密碼前產生、而這支手機已先匯入更新包 → SameVersionDifferent → 句子「這份同意在換密碼前產生,請網主重新邀請這台」(check_joinreq 要未用的邀請,approve.rs:69-73;網主端同意永遠用目前版本,A-m3)。
- 比 mnet 歷代還舊的版本略過、不存:這個人另一台節點若落在那段,§3.2 會說「落後太多版」,隊員模式又不能讓非 k7 的節點重新加入(join2flow.rs:339-341)→ 只能請網主重新邀請那台 —— 誠實界線(A-m8)。
- **匯入後不自動送節點**(A:成員的節點一換,就和還沒換的人斷開,可能切斷網主還在發包的路徑)。匯入成功畫面:「已收到新密碼。等網主說大家都拿到更新包了,再到狀態頁按『把新密碼送給節點』。」狀態頁共用規則會一直顯示按鈕。

### 3.5 狀態頁的共用規則與提示
- **成員手機**:這支手機擁有、節點 info k10 = 本網、節點版本 < 手機版本、但手機沒有它的目前版 secrets 的節點 → 「這台還在舊密碼,這支手機沒有它的新密碼 — 請網主重新產生你的更新包」(只顯示,不放寬送出)。**網主手機**:擁有、在本網、但不在 k11 的節點(被排除的)→ 入口 1 的句子「這台不在隊伍網路的成員名單裡(被排除或被忘記),只能『離開網路』;要加回請用『加入網路』」(第 9 輪 A-m3,與 §2.0 一致)(A-m3 / B-m1)。
- 對每一台網路裡的自己節點(§2.0):手機版本(網主 = 紀錄、成員 = mnet)> 節點 info k9 → 「這台還在舊密碼 — 把新密碼送給節點」→ §3.2。網主、成員同一條。
- 隊員模式「加入網路」**與網主的 join2** 回 5(節點已是成員)時,不只看 join_state(R22):比節點版本與手機版本,節點較舊 → **直接走 §3.2 送新密碼**(不另外再按;效果 = 節點換到手機版本,§3.2-4 判定);這支手機的歷代接不上節點版本(被移除後重新加入、手機紀錄被取代)→ 「這台節點還在舊的隊伍設定裡,請先按『離開網路』再加入」;接得上 → 同上直接送(與 §3.6-1 同一條)。**只在 k10、不是 k7 的成員節點**接不上時不能叫它「離開再加入」(離開後隊員模式只認 k7)→ 句子「這台要請網主重新邀請」;leave.md:31 的隊員句「之後可以按加入網路」只在這台是 mnet k7 時才顯示(A-m5;R19 的結論更正)。
- 換完的提示(網主產包畫面、成員匯入成功畫面):「請把你節點的手機 Wi-Fi 密碼改掉(換密碼不會換手機 Wi-Fi)。本次沒有換:手機 Wi-Fi 密碼、Meshtastic / LoRa 頻道金鑰、TAK(OTS)憑證。如果你的節點在這次換密碼期間還是舊軟體(wsl.24 以前),更新軟體後請讓它離開網路再重新加入。」

### 3.6 其他功能
- **節點版本規則(k4,R25、R30)**:`k4` 中取第一個 `-wsl\.(\d+)`,**數字超過 9 位 = 不通過**(B-m3:`\d{1,9}` 會只吃前 9 位而通過);N ≥ 25 → 通過;N < 25 → 不通過;**找不到 / 缺 → 不通過**(fail-closed)。前提:wsl.25 起的節點帶 F10 修正(R30);⚠️ 假設 wsl 編號單調遞增(基礎版本號前進時不歸零)—— 沒有證據,但規則是 fail-closed,假設錯只會多擋、不會漏;正式版的版本字串格式定下來時要能被這條規則認出,否則改規則 —— 進 §9 checklist(A-m2)。
- **邀請**:`open_netcfg_v1` → `open_netcfg_current`:netcfg 由它自己的 admins 之一簽、且該公鑰 = 邀請的 admin_pub;版本不限(R15)。它不提供新鮮度(舊的真邀請照樣打得開 → 由 k12 標 used 處理);將來換 admins 時規則要改(換網主不在本單)。今天只有遠端邀請。
- **同意**:members / secrets 用目前版本(k8、k5、k6);同意時把該項 k10 設為目前版本。check_joinreq 對作廢的邀請回 InviteUsed → 句子改為通用「這張邀請已用過或已作廢,請重新邀請」(R10)。申請的 DAC 若「之前被移出過」(§2.0 入口 2 的同一判斷)→ 同意前跳**與入口 2 同一個確認框**;**申請者的 owner_pub 若在 k14 或歷代 members 出現過、而現在不在 k11**(被移除的人換一台全新節點申請)也跳同一個框(第 8 輪 B-m3;v6.5:先查 k14,否則這條在真實路徑上永遠不成立);k14 不修剪(被排除後又加回的節點,之後每次重新加入都會再問一次 —— 只多一次確認,實作審查 r2 A-m5,記錄為界線),只有被舊版 app 寫回丟掉 k14 之後才退回「只比 k13 歷代」(k13 修剪到 32 版後更早的 owner_pub 比不到)—— 誠實界線(第 9 輪 B-m2);框裡帶 device_id 後 4 碼與**之前的擁有者**(k14 中這台 / 這個人的最新一筆,否則歷代中最後一版含它的 members 的名稱與 owner_pub 指紋;防止被移除的人拿網主被抓節點的 DAC 來申請,B-m3;歷代已被修剪、找不到 → 顯示「之前的擁有者:不明」,第 8 輪 B-m4);確認是 `ApproveFlow::start` 的參數,由 Rust 強制(它的第一步就是 SignAdmin;沒有確認 → 0 次 SignAdmin,B-m2);按否 = 不同意;使用者決定可以重新邀請;回應 NU §3「審核時擋 removed」。
- **同意過但還沒入網的成員**(approved,他還沒匯入同意包):他的項會進 v+1 的 members。他之後要先匯入舊的同意包(建立 mnet),再匯入更新包;反過來(先貼更新包)不可能 —— 沒有 mnet → 「請先匯入網主的同意」(A-m10:前者 / 後者寫反更正)。§5 有這一列。
- **重新加入被移除的人**(使用者決定可以):
  1. 他的節點在舊版:手機的歷代接得上就直接送新密碼,接不上就先「離開網路」再加入(§3.5 同一條規則)。
  2. 他的手機 mnet 停在舊版:匯入新同意包時若 TooOld(落後 ≥ 2 版),允許**以新同意包取代整個 mnet**,條件全部成立才行(B-M1):新邀請的 netcfg **由舊 mnet k3 的 admins 簽**、net_id 相同、version > 舊 mnet 版本;使用者確認「這支手機有這個網路的舊紀錄(v…),要換成新的嗎?」。v2 的「k7 不在 members 也觸發」拿掉(會對合法的第二台節點誤觸發)。
  2b. **不論走 +1 路或 TooOld 取代**:舊 mnet 的 me(k7)若在同意包 members 的 removed → **當作沒有 me**(在 existing() 的 PreviousNode 判斷之前,否則舊 me 若是 joining / 有 prev_country 會讓重新邀請失敗,A-m5),建新的 joining 項(A-m4 / B-m1;approve.rs:319-320 今天同 DAC 會沿用)。
  3. 網主同意他時:k11 加回他的節點(k10 = 目前版本),下一版 removed 不再列他(§2.4)。
- **建立者的「忘記」保護只在紀錄 state = pending 時生效**(R31;今天不看狀態 → 建立者那台被排除、找回、join2 中斷留下 joining 時會永久卡住,A-M1b)。
- **加回找回來的節點、節點沒被重設**:network/join 回 5 → 照今天的程式把 k11 項寫成 applied(R31),接著若 k9 < 紀錄版本 → §3.2 送 update(A-M1c)。
- **「忘記」的導向**(B-MAJOR):approved 項只會出現在 applied 紀錄(邀請 / 同意 / join2 都要求 applied,invite.rs:181-184、approve.rs:124、join2flow.rs:304-306),所以**別人的 approved 項不再提供「忘記」**,改成「移除這個人」;**由 Rust 強制**:`forget_joining` 對 applied 紀錄裡的 approved 項拒絕(bridge `net_forget_joining` 同),T39 在 bridge 層測(A-m1 / B-m3)。自己卡在 joining 的節點:「忘記」的對話框(dev-trust build)同時提供「排除這台(換密碼)」並說明「只忘記不會撤銷它已拿到的密碼」;兩台以上同時卡在 joining 時:前置 2 只例外本次排除的那一台,所以其他卡住的要**先忘記**才能開始 —— 被忘記的那台失去 removed 的保護(之後加回不會跳確認框),誠實界線;要保護就逐台:先排除最可疑的那台、其餘忘記(第 8 輪 B-m1;v6.2 的「先不要忘記」與前置 2 矛盾,刪)。已經被忘記的項(本版之前忘記的)→ §6 誠實界線:它不在 k11、不在 removed,只能靠下一次任何一次換密碼(它不在名單裡,不會拿到新密碼)把它切掉,且之後加回不會跳確認框。
- 已忘記的項的繞路:排除自己的一台再加回,也會換一次密碼把它切掉(A-m11)。
- **管理者 join2 / 隊員重新加入 / 第二台自己的節點**:都用目前版本;都先過對象守則(§2.0;網主把找回來的節點加回 = 入口 2 的確認對話框)。
- **build 閘門**(A-m9 / B-m5):kind 4 的產生與匯入、「移除這個人」、**「排除自己的一台」**都只在 dev-trust build(正式版今天沒有遠端隊員;正式版的 k4 規則一律 fail-closed,排除後會 commit 一個送不出去的版本,A-m5);「把新密碼送給節點」所有 build 都有(正式版因 k4 規則實際上不送)。正式版開放要等版本字串規則定下來(§9)。非 dev-trust build 的 bridge 拒絕 kind 4(T25)。

### 3.7 被移除的人那一邊
- 他的手機收不到更新;他的節點留在舊 SAE,與還沒換的節點仍連得上,與已換的斷開。他的手機不會知道自己被移除 —— 誠實界線。
- 他拿到別人的包:secrets 加密給別人的節點 / owner_enc_pub,解不開;他的節點收到鏈也沒有自己的 secrets → `E_BAD_OBJECT`(NU §2.2-5)。
- 他用舊 net_root 能算出舊版 psk_member,新版換了 net_root。
- 他不能偽造更新包(都要網主簽);也不能用偽造的重新邀請蓋掉別人的 mnet(§3.6-2 要舊 admins 簽)。
- 他能對分裂期間還是 wsl.24 的別人節點用 F10 灌「新 netcfg + 舊 secrets」→ 那台升級後被判「已是新密碼」(§3.2 例外);前置 5 要網主確認全隊已升級,§3.5 提示要那種節點離開再加入 —— 誠實界線。

## 6. 安全
