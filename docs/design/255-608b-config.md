## 2. 做法

| 槽 | 金鑰 | 只能做 | 第 1 期的用途 |
|---|---|---|---|
| 1 | 身分金鑰 | 內部簽章 | 公鑰決定節點 id，是憑證的主體金鑰；**第 1 期不簽任何東西** |
| 0 | 連線金鑰 | 外部簽章 | 每次連線的身分證明（簽「固定標籤 ‖ 交握雜湊」的摘要） |
| 2 | 解密金鑰 | ECDH | 給節點的密碼包的加密對象 |

- **節點 id** = SHA-256(槽 1 公鑰，SEC1 未壓縮) 的前 9 位元組（與 `nodecert.rs:177-180`、`keystore.go:118-120` 一致）。
- **晶片序號與節點 id 分開**：認領比對時晶片只用序號裡固定的 3 個位元組（SN[8]、SN[0:1]，F§4），所以認領證明用晶片序號；機身 QR 不帶序號。
- **金鑰的證明 = 開發根簽的憑證**：主體金鑰是槽 1 公鑰，憑證另外載明槽 0 公鑰、槽 2 公鑰與晶片序號（格式見 `255-phase1-impl.md` §3.1）。開發根只在燒錄時、讀回設定與鎖定狀態完全符合後才簽（§5）。app 驗證連線證明與加密對象時，公鑰**一律取自這張憑證**，不取自節點另外送來的欄位。
- **開發根的簽章代表什麼**：「開發者在自己掌控的節點上燒了這顆晶片」，**不是**晶片自己的證明。讀回的資料是節點回報的，所以燒錄只在剛燒好卡、開發者在場的實驗台或 bench 節點上做（§5）。開發版 app 不能把它說成更多。
- **為什麼拿掉 v3 的晶片背書**（審查 v3-A M4）：開發根在燒錄時已經讀回並確認了設定，再讓憑證載明三把公鑰，C2、C3 就成立；背書在 bench 上不增加保護，卻要開機做兩次內部簽章、`node_cert` 多四個欄位、驗證者要釘住 55 位元組訊息的每一個位元組，而且整條第 1 期都卡在 E7（K16 的假設連原廠主機程式都不支持，審查 v3-A M2）。量產晶片是另一顆，bench 學到的背書行為未必適用。晶片背書是否需要、怎麼做，移到選量產晶片時一起決定（§10）。
- **槽 1 為什麼仍是「只能內部簽章」**：設定位元組不變（兩輪審查都確認過），且身分金鑰本來就不該簽主機給的任何東西。第 1 期它只產生一次、公鑰進憑證。
- **連線金鑰簽什麼**：只簽 helper 組成的「固定用途標籤 ‖ 32 位元組交握雜湊」的 SHA-256，由主機以直通 nonce 載入暫存區後外部簽章（F§2.3）。用途是固定的列舉，不接受任意標籤（`255-phase1-impl.md` §2.1）。provd 提供交握雜湊，所以被攻破的 provd 可以讓槽 0 簽任何雜湊；這等於 provd 本身被攻破（它握有連線金鑰），不是新的洞（審查 v3-A m12）。
- **給節點的密碼包**（`net_secrets`）的加密對象是憑證載明的槽 2 公鑰。

## 3. 槽位規劃

| 槽 | 用途 | 燒錄時 | 規則 |
|---|---|---|---|
| 0 | 連線金鑰 | 資料區鎖定後產生，再個別鎖定 | 只准外部簽章 |
| 1 | 身分金鑰 | 同上 | 只准內部簽章（第 1 期不用） |
| 2 | 解密金鑰 | 同上 | 只准 ECDH；結果不寫入下一槽 |
| 5 | 認領秘密 | 資料區鎖定前寫入開發者電腦產生的值；之後永不可改 | 只能比對；不可讀；NoMac |
| 8 | 開發根簽的憑證（完整 DER） | 鎖定前寫全 0；憑證格式定案後寫入 | 明文可讀；**bench 上不個別鎖定**（§5.3） |
| 3、4、6、7、9–15 | 不使用 | 鎖定前寫全 0（含 36 位元組槽的全部 36 位元組） | 永不可寫、不可讀、NoMac |

- 沒有任何槽的 `ReadKey` 是 0（比對後複製的功能不會開啟）；認領秘密在奇數槽。
- **不使用的槽是公開的已知值（全 0）且 NoMac**，可以被拿來做 GenDig / CheckMac。這不構成風險，因為沒有任何槽的 WriteKey / ReadKey / AuthKey 指向它們，而且沒有驗證者接受晶片的 MAC 或內部簽章（C2）（審查 v3-A m15、v3-B m8）。

## 4. 設定區數值

**設定區的校驗值每顆晶片不同**（位元組 0–15 含序號），所以交付物是「位元組 16–127 的固定影像」，校驗值由燒錄模式對每顆晶片讀出 0–15 後計算。影像在 E1 讀到空白值後產生並附在本文件。

| 位元組 | 設定 |
|---|---|
| 16 | `0xC0`（7 位元 0x60） |
| 17 | 維持 E1 讀到的空白值，寫明 |
| 18 | `0x00` |
| 19 ChipMode | `0x00`：第 0 位元 0（不用替代位址）；**第 1 位元 0**（固定輸入準位：VIH 最低 1.5 V，與 VCC 無關，F§9；3.3 V 匯流排兩種都可以，選固定的較單純，審查 v3-A m1）；第 2 位元 0（看門狗 1.3 秒）；時脈最快 |
| 20–51 | 各槽 SlotConfig（下表） |
| 52–67 計數器 | 不碰 |
| 68–83 | 全 `0x00` |
| 84–87 | 不寫 |
| 88–89 SlotLocked | `0xFFFF` |
| 90–91 ChipOptions | `0x0008`（`08 00`）：只開「亂數健康測試失敗自動清除」。第 2 位元（KDF-AES）0；第 15–12 位元（IO 金鑰槽號）0 只在加密輸出模式有意義，E10 確認加密輸出被拒 |
| 92–95 | `0x00` |
| 96–127 | 各槽 KeyConfig（下表） |

| 槽 | SlotConfig | KeyConfig |
|---|---|---|
| 0 | `0x2081` | `0x0073` |
| 1 | `0x2082` | `0x0073` |
| 2 | `0x2084` | `0x0073` |
| 5 | `0x8F9F` | `0x001C` |
| 8 | `0x0F0F` | `0x003C` |
| 3、4、6、7、9–15 | `0x8F9F` | `0x001C` |

槽 0–2 的 KeyConfig 第 6 位元（ReqRandom）保留。v3 對它的理由（「背書一定含晶片亂數」）是錯的：TFLX §5.1.4.1 的 nonce `0x8000` 模式可以讓主機完全決定暫存區（審查 v3-A M2）。v4 已不用背書，這個位元沒有作用，也無害；保留是為了不改已審過的位元組。

## 5. 燒錄（bench）

### 5.1 誰、在哪、怎麼做

- **燒錄是 helper 的命令列模式**（`batman-provhelper se-burn …`），由開發者經 ssh 以 root 執行。它**只在以下條件都成立時**才動晶片：helper 常駐程式已停止（procd 服務停止，且取得晶片鎖，見下一條）；不是試用開機（`batman-slot is-trial` 回「已確認」）；有 console 或 `/etc/batman-dev-open`（同 `provhelper qr` 的規則，`main.go:598-623`）。
- **晶片鎖**：所有碰晶片的程式（helper 常駐、燒錄模式、實驗工具）先對 root 專用執行目錄下的一個鎖檔取得獨占鎖；常駐程式終生持有。拿不到就拒絕執行。常駐程式內部另有一個序列器，一次只跑一個指令序列（喚醒 → … → 閒置），序列之間不保留暫存區（審查 v3-A M6、v3-B M2）。
- **認領秘密由開發者電腦產生**（審查 v3-B M1）：燒錄前，開發者電腦的燒錄工具（`se-sign`，`255-phase1-impl.md` §2.5）以自己的 CSPRNG 產生 32 位元組秘密，先寫進該晶片的燒錄紀錄（狀態「待寫入」），再經 **stdin**（不是命令列參數）交給節點。節點不把它寫進檔案、log 或 stdout。
- **開發根的簽章在開發者電腦上做**：節點輸出一份資料包（設定區原始 128 位元組、鎖定狀態、序號、三把公鑰），開發者電腦**自己**重算設定區校驗值、逐位元組比對影像、確認三個金鑰槽與兩區都已鎖，通過才簽。

### 5.2 步驟與可接續的狀態

| 晶片狀態（由讀回判斷） | 燒錄模式做什麼 | helper 常駐看到時 |
|---|---|---|
| S0 空白：設定區未鎖 | 讀 0–15 與版本（必須 `00 00 60 03`，否則停）；寫 16–127；讀回逐位元組比對；計算校驗值；**鎖設定區（帶校驗值）** | 燒錄未完成 |
| S1 設定已鎖、資料未鎖 | 寫槽 5（stdin 給的秘密）、槽 8 與所有不使用的槽（全 0）、OTP（全 0，⚠️ E5）；**鎖資料區（帶校驗值；校驗值跳過私鑰槽，F§1.3，所以由已知內容算得出來）**；再以 CheckMac 用同一個秘密比對槽 5，成功後燒錄紀錄改為「已鎖定」。中斷就重做此步：開發者電腦對同一序號沿用「待寫入」的秘密 | 燒錄未完成 |
| S2 資料已鎖、槽 0–2 有未鎖的 | 對每個未鎖的金鑰槽 GenKey（SlotConfig 第 13 位元 = 1，未鎖的槽可以重新產生，F§3）、讀公鑰、個別鎖定。**不需要報廢**（審查 v3-A m2、v3-B M2） | 燒錄未完成 |
| S3 金鑰槽都已鎖、槽 8 沒有有效憑證 | 輸出資料包 → 開發者電腦驗證並簽 → 寫入槽 8、讀回 | 燒錄未完成：缺憑證 |
| S4 槽 8 的憑證有效（開發根簽、主體金鑰 = 槽 1 公鑰、載明的槽 0 / 2 公鑰與序號都和晶片相符） | 無事可做；回報「已燒錄」 | 已燒錄 |
| 版本不是 `00 00 60 03`，或設定區已鎖但與影像不同（例如變體晶片） | 拒絕 | 非本設定的晶片 |
| 無回應 | 拒絕 | 晶片無回應（重試） |

每一步都可以在中斷後重跑同一個命令，從讀回的狀態接續。寫入槽 8 前，節點檢查憑證的主體金鑰等於這顆晶片的槽 1 公鑰、簽發者是開發根（避免兩顆晶片的憑證互換，審查 phase1-A M6）。

### 5.3 槽 8 為什麼 bench 上不鎖

v3 把憑證寫入後個別鎖定。憑證格式要到第 1 期協定定案才確定，開發根也可能換；鎖了之後任一項改變，這顆晶片就永遠帶著錯的憑證（審查 v3-B M3、phase1-B m8）。不鎖的代價：有 root 的人能覆寫槽 8，結果只是 app 驗不過（拒絕服務），因為憑證是對開發根驗的。所以 bench 上槽 8 保持可寫；憑證格式或開發根改變時，重跑 S3 即可。

### 5.4 燒錄紀錄與開發根的保管

- 燒錄紀錄（每顆晶片一筆：序號、節點 id、三把公鑰、認領秘密、狀態）與開發根私鑰放在 DSKT-MOONLIGHT 的同一個目錄，權限 0600，不進任何 git repo、不進 log。開發根私鑰以密碼加密存放。
- 驗證工具從這份紀錄取認領秘密，在**主機端**回答認領挑戰；秘密不送到節點（`255-phase1-impl.md` §4）。這是「印成 QR 後刪除」的 bench 例外：bench 晶片終生是開發單元（憑證只由開發根簽），保留秘密才能自動化驗證（審查 v3-A M7、v3-B M1）。
- 備份：使用者把整個目錄（加密後）另存一份到可移除媒體；保管說明寫進 Batman-P（只寫做法，不放秘密）。開發根遺失或外洩：產生新的開發根，對每顆 bench 晶片重跑 S3；外洩期間的後果是「能做出開發版 app 信任的假節點」，開發版不對外。

## 6. 實驗台與晶片分配

- **實驗台**：一台專用的 Pi 加一片備用 WM1302 HAT（U3 焊 608B、加 C6 / C7），**不是 02 / 04**，不跑驗證套件。E0–E13、E15、E16 都在實驗台做（不需要 HaLow）。⚠️ 實驗台的 Pi 型號焊好時確認；E14 的時間量測要在 Pi 4 上，若實驗台不是 Pi 4，E14 在 v1.6 結束後到 bench 節點上做。
- **晶片**：手上 10 顆，全都只用於 bench。第 1 顆用變體影像（§8.1）；第 2 顆用 §4 最終影像走 §5 的燒錄流程（F1）；第 3 顆在第 2 顆不通過而改設定時用。變體需要第二顆時直接用（一顆約 1 美元加一次重焊，審查 v3-A m11）。其餘給 bench 節點。

| 憑證 | `se-sign` → 燒錄模式 → 槽 8 | DER | 主體金鑰或簽發者不符 → 不寫 |

系統層面的生命週期（開機、試用、OTA、重燒、換 HAT、降版）在 `255-phase1-impl.md` §7。燒錄中斷見 §5.2。

## 8. 實驗

### 8.0 規則

- 實驗工具 `se-lab` 是獨立的開發者工具，**不進任何映像**；放在實驗台的 tmpfs 執行；執行前停止 helper 常駐並取得晶片鎖（§5.1）；只對開發者電腦傳入的「犧牲晶片序號清單」上的晶片動作，其他一律拒絕（審查 phase1-A m11）。它實作產品驅動沒有的指令（UpdateExtra、KDF、SHA 到暫存區、AES、PrivWrite、GenDig 各區）。這是 C8 的明文例外：實驗台不是帶有身分的節點。
- 每條「應該失敗」都寫明預期狀態碼，並有對照：同一個指令只改受測欄位、或同一個指令對另一個槽，要成功。沒有對照的列寫「只靠文件」，不算 C7 的證明。
- 每次動節點（含實驗台）前取得使用者同意；E0–E3 不留下永久改變。**E4 以後要等本文件 v4 審過**。E1 讀到的版本不是 `00 00 60 03` 就停。

### 8.1 變體影像（第 1 顆）

與 §4 相同，只改三個不使用的槽作為對照（值與 v3 相同，審查已逐位元確認）：

| 槽 | SlotConfig | KeyConfig | 對照用途 |
|---|---|---|---|
| 3 | `0x0F8F` | `0x003C` | 秘密、可明文寫、**沒有 NoMac**：E8 的 MAC 類指令在這裡要成功 |
| 4 | `0x2083` | `0x0073` | 私鑰槽：E6 在資料區鎖定前以明文 PrivWrite 寫入（對照「鎖定後寫私鑰槽被拒」） |
| 6 | `0x0F0F` | `0x003C` | 一般資料、隨時可寫、可個別鎖定：E6、E9、E13 的寫入與鎖定在這裡要成功 |

硬規則：沒有任何 WriteKey / ReadKey / AuthKey 指向槽 5，讓 E8 對槽 5 的結論可以套用到最終影像。順序：E6、E9 在 E13 鎖住槽 6 之前做。

## 10. 移到「選量產晶片」時才處理的

- **晶片背書**：要不要讓晶片自己證明金鑰屬於它（K16 的晶片版本）、怎麼做。v3 的 E7 清單與審查 v3-A M2、M3 的修正是起點；要在量產晶片上做，不在 608B 上。
- **入庫計數器**（U9）：顯示「最多被入庫過 N 次」（v2 的「至少」方向錯了，U9 的措辭要請使用者確認）；何時加一（認領證明與擁有者簽章都驗過之後）；計數器簽章（v3 的 E11）。
- 機身 QR 是否終身固定、標籤遺失怎麼辦。
- 晶片壞掉時節點的行為與使用者要接受的代價。
- 晶片與主板的綁定（自家 HAT v1 有 TPM，一起看）。
- 出廠站、原廠根、批次燒錄、量產生命週期。
- 預先設定版（608C TrustFLEX）的槽位由 Microchip 決定，要確認能否做到三金鑰分工。
