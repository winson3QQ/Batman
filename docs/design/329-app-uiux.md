## 4. app 架構

### 4.1 元件與擁有權

| 資源 | 唯一擁有者（可改） | 只讀 |
|---|---|---|
| BLE 連線、`OwnerSession`、進行中的請求 | `NodeLink`（app 層級，一個實例） | 所有頁面（經 `Listenable`） |
| 節點 / 網路 / 成員等金鑰紀錄（node、net、mnet、mpend、claim-pending、forgotten-*） | 現有流程程式（搬進各流程的 controller，寫入順序不變） | 首頁、節點頁 |
| `ui/state-v1` | `UiState`（一個實例；所有寫入排隊、CAS） | 所有頁面 |
| 每台節點「這次開 app 讀到的狀態」 | `NodeLink`（記憶體） | 首頁、節點頁 |
| 文字紀錄（開發者選項） | `NodeLink`（記憶體環狀，500 行，不落地） | 開發者選項頁 |
| 主題 token | `BatTheme`（常數） | 全部 |
| Keystore 金鑰 | Kotlin `Keys`（不變） | — |

沒有任何資源有兩個寫入者。`ClaimPage` 的認領用自己的連線（現況如此，F17 的注入點）；`NodeLink` 在認領流程開始前先放掉自己的連線，流程結束後才恢復（單一藍牙使用者的規則，§4.2-5）。

### 4.2 `NodeLink` 的行為

1. **對外狀態**（每台節點一個）：`cached`（只有快取）→ `connecting` → `fresh(view, readAt)` | `unreachable(reason)`。`reason` 是：藍牙關閉、沒有權限、60 s 內找不到、登入被拒、手機金鑰不可用。
2. **什麼時候讀**：
   - app 啟動檢查通過後；
   - app 回到前景，且距離上次完成一輪 ≥ 30 s；
   - 使用者按重新整理；
   - 一個會改變狀態的操作完成後（只讀那一台）。
   沒有背景輪詢、沒有定時器輪詢。
3. **怎麼讀一輪**：依序對每台「我的節點」：登入 → `requestStatusPage` → 記下結果 → 下一台。最後停在使用者上次打開的那一台（沒有就停在第一台）並保持連線。使用者在這一輪中點進某台節點：那一台插隊成為下一個，其他的往後排。
4. **在背景時不開始新的登入或掃描**；回到前景才繼續。已經送出的請求不取消（讓它照原本的逾時與「結果不明」規則結束）。這同時是 F22 那個未歸因問題的翻轉測試位置（§9 T-L6），但本設計**不宣稱**修好它。
5. **互斥**：`NodeLink` 一次只做一件事（讀一輪中的一台、或一個使用者操作）。使用者操作優先：讀一輪在兩台之間讓出。認領、軟體更新傳送期間，讀一輪暫停。
6. **藍牙與權限**：登入前先看 `statusStream`。藍牙關閉 → 立刻回 `unreachable(藍牙關閉)`，不等 60 s；首頁顯示 2.3。藍牙重新打開 → 自動再讀一輪。沒有權限 → 2.2。
7. **找節點變快（提示，不是信任）**：登入成功時把那台節點當時的 BLE 位址記在 `ui/state-v1`。下次掃描到的候選裡如果有這個位址，先試它。位址不對或換了：照現況逐台試。**身分只由登入的金鑰驗證決定**（現有 `_tryLogin` → `OwnerSession.start`，A2），位址提示錯了只會慢、不會連錯。
8. **斷線**：連線中斷 → 該節點變 `unreachable` 或回到 `cached`，首頁與節點頁立刻變成「不明」樣式並寫出原因；在前景時自動再試一次登入，之後不再自己重試（等使用者按重新整理或下一次回到前景），避免無限掃描耗電。
9. 現有的 `_ask` 行為（一次重試、逾時、「結果不明」、金鑰 gate）原樣搬進來，不改語意。

### 4.3 `ui/state-v1` 契約

| 項目 | 內容 |
|---|---|
| 寫入者 / 讀取者 | 只有 `UiState` 寫；頁面經 `UiState` 讀 |
| 位置與格式 | 紀錄庫 `ui/state-v1`（符合 F7 的路徑規則），用現有 `seal` / `storeWriteCas`；內文是 CBOR map，欄位見下 |
| 欄位 | 1 版本（=1）；2 看過歡迎頁；3 看過首頁提示；4 節點表 `{device_id → {1 暱稱, 2 上次狀態種類, 3 上次狀態一句話, 4 讀取時間(UTC 秒), 5 BLE 位址提示}}`；5 移除檢查清單 `{net_id → {成員雜湊 → {1 已交出, 2 已換好}}}`；6 上次打開的節點 |
| 何時有效 | 任何時候；每次寫入是整筆替換（CAS，generation +1） |
| 不存在 | 全部用預設值：沒看過歡迎頁；**但手機已有節點紀錄時不顯示歡迎頁**（舊使用者升級） |
| 解不開 / 格式錯 / 版本不認得 | 當成不存在，下一次寫入時覆蓋。**fail-open**，理由：內容只影響顯示，沒有任何授權或金鑰決定依賴它 |
| 過期 | 上次狀態只用 T2 的「不明」樣式顯示；讀取時間在未來或超過 30 天 → 只寫「之前讀過」，不寫時間 |
| 有節點紀錄被忘記 | `UiState` 在載入時刪掉節點表裡已經沒有對應 `node/<id>` 的項目 |
| 信任邊界 | app 私有目錄；備份關閉（F9）；能寫這個檔的人已經能寫所有紀錄 |
| 不能放的東西 | 任何金鑰、密碼、邀請 / 同意碼、QR 內容。暱稱與狀態句子以外的節點字串不存 |

`ui` **不加進** `RECORD_KINDS`（F8）：金鑰能否重新產生的判斷不該被一筆顯示用的紀錄影響。後果：全新安裝、金鑰重新產生後，舊的 `ui/state-v1` 解不開 → 當成不存在（上表）。

### 4.4 流程 controller

每條流程（新增節點、建立網路、加入網路、邀請、加入隊伍、移除成員、換密碼、手機 Wi-Fi、國家、離開、軟體更新）一個 controller：持有該流程的步驟狀態，向 `NodeLink` 要 session 做事，寫自己的紀錄。現有函式整段搬移，對照表：

| 流程 | 現有程式 | 畫板 |
|---|---|---|
| 新增節點 | `ClaimPage`、`ClaimRecords`、`ClaimRecovery` | 3.1–3.7 |
| 建立 / 加入 / 確認網路 | `_makeNetwork`、`_joinNetwork`、`_confirmNetwork`、連線檢查 | 4.1–4.5 |
| 邀請（隊長） | `_makeInvite`、`_checkRequest`、`SasConfirmView` | 7.1、7.3–7.7 |
| 加入隊伍（隊員） | `_takeInvite`、`_requestJoin`、`_showPending`、`_takeApproval`、`_importApproval`、`_memberJoin` | 7.8–7.10 |
| 成員、移除 | `_members`、`_remove`、`_runRemove`、`_makeUpdates` | 8.1–8.4 |
| 換密碼（隊員） | `_takeUpdate`、`_sendUpdate`、`updateHint` | 8.5、1.10 |
| 設定 | `requestSetCountry`、`requestSetAp`、`requestSshKeys` | 5.6–5.8、10.2 |
| 離開 | `leaveFlow` | 10.3 |
| 軟體更新 | `SwUpdatePage` | 9.1–9.5 |

**搬移規則**：紀錄的寫入順序、簽章步驟、gate、逾時值一個都不改；每搬一條流程，該流程現有的測試檔必須不改判定就通過（只改建構方式）。

### 5.2 第一次使用（1.1–1.4、1.7、2.1–2.4）

- 1.2–1.4 只在「沒看過」且「沒有任何紀錄」時顯示；按「開始」或「跳過說明」都算看過。
- 權限（2.2）：藍牙權限在歡迎頁之後要；相機權限等到第一次掃 QR 才要（現況，F：QrScanActivity）。被拒絕 → 留在 2.2，說明去哪裡開，並提供「開啟 app 設定」。
- 1.7 的提示卡在第一次出現「一切正常」的首頁時顯示一次。
- 2.4（手機金鑰等級不足）沿用現有 gate 的判斷與文字，只換版面；**不放寬任何 gate**。

### 5.3 新增節點（3.1–3.7）

- 3.1 只有一個主要動作「掃描 QR code」。貼上 / 輸入 16 進位只在開發者選項（devTrust）。
- 不顯示附近藍牙裝置清單（U2-2）。「附近的節點」掃描頁移到開發者選項。
- 3.2 取名：手機暱稱，1–24 個字，去掉控制字元與前後空白；預設「節點 XX」（XX = 後四碼前兩碼不夠辨識，所以預設就是「節點 後四碼」）；之後可在 5.7 改。
- 認領期間顯示步驟清單與經過時間；中斷後回首頁會看到待辦（§5.1），由 3.7 接著做（現有 claim-pending 恢復，邏輯不變）。
- 完成後：第一台 → 3.5（下一步：建立網路 / 我是隊員）；之後的 → 3.6（加入同一個網路 / 再加一台）。
- 「這台節點已經在手機裡」的覆寫詢問沿用現有對話框（254-app-claim-noover），只換樣式。

### 5.4 建立 / 加入網路（4.1–4.5）

- 4.1：網路名稱（預設「第一小隊」這類示意不寫死；預設值沿用現況 `Batman`，可改）、要加入的節點（可勾多台，至少一台）、「進階」裡的頻道（40 / 42，預設 40）。
- 勾多台時：對第一台做建立，其餘逐台做加入（現有 `_joinNetwork`）；每台各自顯示進度與結果，一台失敗不影響已完成的。
- 4.2 等待：顯示「已經過 M:SS，最多 6 分鐘」（F19 的 360 s）與目前步驟；不能返回（PopScope），文字「請留在這個畫面」。
- 結果不明（連線在送出後中斷）：用「可恢復的錯誤」樣式，原文沿用現有「結果不明」文字，下一步 = 「重新讀取這台節點的狀態」。**不自動重送**（現況如此）。
- 4.5 失敗：顯示 Rust 給的原因句子 + 下一步；代碼在技術資訊。

### 5.5 節點頁與設定（5.1–5.8）

- 節點頁上半 = `StatusHero`（資料 = `StatusView`）；下半依任務分組：網路、手機 Wi-Fi、成員（隊長才有）、軟體更新、更多。
- 進節點頁時如果這台不是目前連線的那台，`NodeLink` 切過去；切換中顯示 busy，舊資料用 T2 樣式。
- 手機 Wi-Fi（5.6）：名稱 1–32 個位元組；密碼 8–63 個可顯示 ASCII 字元（WPA2 的規定）；密碼欄可切換顯示；送出後清空（現況）；這一頁開 FLAG_SECURE（F18 的 `SecureScreen`）。節點拒絕時顯示節點的原因。
- 國家（5.8）：選單，顯示「台灣 TW」「美國 US」；目前值來自 `requestSettings`；改變要確認（現有對話框的文字精簡成 ≤ 3 行）。**本單不改任何預設國家或頻道**（§11 Q4）。
- 更多（5.7）：改暱稱、國家、離開網路、技術資訊；「忘記這台節點」只在開發者選項，而且不再用長按（F：nodes.dart:1594 的長按 = 忘記，容易誤觸）。

### 5.6 全隊（6.1–6.3）

用現有 `TeamView{visible,title,only,cards,note,tech}`。`visible` 為 false 就沒有入口。卡片文字、「僅供參考」的註記沿用 254-app-team-status 的凍結設計。

### 5.7 邀請、加入、成員、移除（7.x、8.x）

- 三段式不變：邀請碼 → 申請碼 → 同意碼，確認碼（SAS）核對畫面保留現有設計（大數字、單一按鈕、提醒不要在同一個聊天核對）。
- 每一段的碼：QR（放得下時）+「複製文字」；收的一方：「掃描 QR」+「貼上文字」。掃描用現有 `scanQr`。顯示碼的頁面開 FLAG_SECURE。
- 隊員名稱必填（1–24 字；盤點 A5 的空名稱問題）；選網路時同名的網路後面加建立日期與網路代號後四碼（盤點 A5）。
- 移除成員（8.3 → 8.4）：確認只一次，按鈕寫後果；之後進檢查清單頁：每位留下的隊員兩個勾（已交出更新包 / 已換好），勾選存 `ui/state-v1`；「全隊都換好了」才能按下一步（沿用現有必勾的規則）。中途離開，首頁節點頁的「成員」列顯示「換密碼進行中」。
- 這一整區只在 devTrust 版本顯示（F14）；本單不改 gate。

### 5.8 設定、關於（10.x）

- 10.1 設定：說明、換手機 / 手機遺失說明（10.4，純文字，誠實寫出做不到的事）、診斷（10.5）、關於與版權（10.6）、開發者選項（devTrust 才有）。
- 10.2 開發者選項：貼上 QR / 各種碼、SSH 金鑰、文字紀錄、附近的節點、忘記節點、舊版控制台（T7）。
- 10.6：臂章、app 名稱、版本（從建置時帶入，見 A5）、版權聲明（文字待使用者確認，§11 Q1）。
- 10.7：Flutter 內建的授權登錄（`LicenseRegistry`）會自動收齊 Dart / Flutter 套件的授權；Rust crate 的授權由一支工具產生成文字資產、隨 app 出貨、一併登錄；節點軟體的授權（GPL 等）放一段固定說明與原始碼位置。全部離線顯示，不連網。

## 8. 安全

**資產**：擁有者 / 管理者金鑰（Keystore）、節點紀錄裡的 K 與 root 密碼、認領 QR 的秘密、手機 Wi-Fi 密碼、邀請 / 同意碼、確認碼。

**逐個角色**：

| 角色 | 本設計新增或改變的面 | 處理 |
|---|---|---|
| 附近的攻擊者（藍牙） | app 開啟時會自動掃描並嘗試登入，次數比現況多；假節點可以廣播同一個服務 UUID 引來連線 | 登入本身是現有的雙向驗證（A2），假節點拿不到 session；位址提示只影響順序（§4.2-7）。每輪每台最多試現況的 60 s，前景才做，斷線只自動重試一次 |
| 同一支手機上的其他 app | 新檔案 `ui/state-v1`；剪貼簿 | 檔案在 app 私有目錄、加密；不放秘密（§4.3）。剪貼簿的用法不比現況多；能用 QR 的地方不必用剪貼簿 |
| 旁邊看螢幕 / 截圖 / 最近使用的 app 縮圖 | 新增顯示 QR 與密碼的頁面 | 顯示各種碼、手機 Wi-Fi 密碼的頁面開 FLAG_SECURE（把 F18 的 `SecureScreen` 接上） |
| 拿到手機的人（已解鎖） | 首頁直接顯示節點狀態；自動連線 | 與現況相同的權限（現況點一下就連）；金鑰用途的 gate 不變 |
| 被入侵的節點 | 節點給的字串顯示在更多地方（首頁、快取） | 一律 `display_name` + 截 64 字；快取只存 Rust 產生的狀態句子，不存原始節點字串 |
| 供應鏈 | 可能新增 QR 產生套件；授權清單工具 | 優先用 Rust 端產生 QR（已有 vendored 依賴流程）；新增任何依賴在 PR 列出版本與授權；A4 |
| 我們自己的錯 | 舊綠燈誤導；搬移流程時改到寫入順序 | T2；§4.4 的搬移規則 + 既有測試不改判定 |

**攻擊面變化**：新的使用者輸入 = 暱稱（長度與字元限制）、隊員名稱（已有 `check_name`）、Wi-Fi 名稱與密碼（新增長度檢查，節點端檢查不變）。沒有新的埠、沒有新的 intent、沒有深層連結、沒有網路請求（授權頁離線）。

**權限**：不新增 Android 權限。

**秘密**：不進文字紀錄、不進 `ui/state-v1`、不進截圖（FLAG_SECURE）。文字紀錄只在記憶體。

**失敗模式**：連線、登入、金鑰 gate 全部 fail-closed（不變）。唯一 fail-open 的是 `ui/state-v1`（§4.3，理由已寫）。

**負向測試**：T-S1（顯示碼的頁面 FLAG_SECURE 有打開；關掉 `SecureScreen` 那一行就 FAIL）、T-S2（`ui/state-v1` 的內容不含任何紀錄裡的秘密欄位）、T-S3（假節點廣播同 UUID：`NodeLink` 不會把它標成 `fresh`）、T-S4（非 devTrust 版本：開發者選項、邀請、成員入口都不存在）。

## 12. 實作順序（同一張單，分幾個 PR；每個 PR 都保留全部現有功能）

1. 主題 token + 共用元件 + `UiState` + `NodeLink`（含自動連線、藍牙 / 權限）+ 首頁 + 節點頁（狀態）+ 第一次使用 + 關於；舊控制台移到開發者選項。**U2 的四點在這一個 PR 就全部看得到。**
2. 新增節點流程 + 建立 / 加入網路。
3. 手機 Wi-Fi、國家、暱稱、離開、軟體更新換版面、設定各頁。
4. 邀請、加入隊伍、成員、移除、換密碼（含 QR，先量 A4）。
5. 全隊頁（接 `teamView`）、診斷頁、刪除舊控制台；真機全情境。

每個 PR：全套 `flutter test` + Rust 測試、真機走該片涵蓋的情境、PR 內附結果。

## 13. 考慮過但不採用

| 方案 | 不採用的理由 |
|---|---|
| 四分頁導覽（219 原型） | 使用者已同意畫布的架構（U5）；兩台節點的規模下分頁只增加空畫面 |

| 定時輪詢狀態 | 耗電、與使用者操作搶 session；現場看狀態的時機就是打開 app 或按重新整理 |
