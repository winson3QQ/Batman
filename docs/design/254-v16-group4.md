## 1. `prov-ac-flap-254` asserts the P3 rule

**Premise.** A trial whose helper keeps exiting is not commit-worthy. The deadline revert removes it even while it is held.

**Why this is deterministic** (v1 A, verified):
- The helper never lives the 60 s that `provd-stable` needs.
- So every poll's why is the (a) or the (b) reason, and HELD cannot occur.

**Flow** (shaped like `prov-ac-radio1off-254.sh`):
1. `pr_begin 3000`, then precondition `ble-ok`, then `pr_ota_b "$PR_V.dirty.wbox-helper-flap" B`.
2. Poll every 10 s, in the trial boot, until 30 s before the trial's own deadline (`$RUNDIR/autocommit.deadline`).
   - Log every `autocommit.why` sample to the unit log.
   - Kept from the old unit: the mutant is live (at least 2 `WBOX-helper-flap-f4703b1d: exiting` lines) and the health file is fresh (F14).
3. Call `pr_wait_reverted`. It FAILs on HELD, renews the lease on a deferral, and reports INVALID on a panic. It also re-finds the node after the revert (`prov-254.sh:417-450`).
4. Judge with `acflap_judge <samples> <PR_REVERT_LINE>`:
   - at least one sample must *contain* `svc batman-provhelper down`; if none does, FAIL "(a) never observed";
   - the revert line must contain (a) or `batman-provd not stable`.
5. `pr_end revert`.

**Negative controls**
- Offline: `scripts/dv/test-acflap-254.sh` feeds `acflap_judge` with synthetic inputs, labelled as such:
  - (a) samples plus an (a) revert line → PASS;
  - (b)-only samples → FAIL;
  - a revert reason of `mesh not joined` → FAIL;
  - no samples → FAIL.
- On the device: wsl.35 FAILed under the old judgement (the evidence above). The new unit must PASS on wsl.36 with its samples logged.

**E-H5 #2** (`254-h23-harness.md:989`): the old dry-run arm's timed run moves unchanged into `prov-autocommit-p3-254`, on its healthy trial.

### 3.2 p5 restore: the harness's own mounts are unmounted, anything else is named

In `node/prov-base-254.sh` p5-restore:
1. Print `P5-MOUNTED <mountpoint>` for every p5 line of /proc/mounts.

## 4. Slot commands: guarded, prechecked, or allowlisted with a reason

**The rule.** Every command in scope that reboots, rolls back or commits a node is in one of three groups:
- **guarded** through `slot-guard-254.sh`;
- **prechecked**: a read-only tryboot-flag GET right before a plain reboot;
- **allowlisted**: with a reason.

The lint enforces it from a checked-in inventory.

**Out of scope:** product-initiated reboots and killpoints.

**Pi 3 rule** (v2 A m7, B M5). Word 5 of the tryboot GET was never captured on a Pi 3 (`254-v16-group1.md:59`), so `rb_guarded` / `reboot_guarded` may refuse there.
- A site that can run on a Pi 3 is **not converted to a guard**. It is prechecked (if it reboots through `reboot_and_wait`) or allowlisted.
- Only sites that can run on a Pi 4 only are converted. The bench is Pi 4 only.

### 4.1 Guard additions (`slot-guard-254.sh`)

- **`commit_guarded <boot8> <slot>`**: same boot, same slot, in a trial (is-trial rc 0) → `batman-slot commit` → `SENT <output>`. Anything else → `WRONG-STATE`, no commit. No DISARM.
- **`reboot_guarded <boot8> <slot> <trial> <reason> <extra-cond> <pre>`** (v2 A m2, B m7):
  - `<pre>` is the **6th** positional argument; `<extra-cond>` may be `-` for none.
  - `<pre>` runs on the node after every check passed.
  - **Today's ordering is kept:** the reboot follows even when `<pre>` fails, because today's `firstboot -y; reboot` reboots regardless. The answer is then `PRE-FAILED SENT`, and the caller FAILs.
  - On WRONG-STATE, `<pre>` never runs, so the node is untouched.
- **DISARM as a second writer of the product's tryboot flag** (v1 A m7, B m8):
  - It clears the flag only on a committed node before a reboot, which is the same effect as the product's own disarm.
  - If the clear fails, there is no reboot (fail-closed).

### 4.3 The lint: an inventory, not a clever regex

v2 A M4 and B m9 showed that a single line regex cannot tell a reboot inside a node command from text.

**Lint (1)** keeps today's regex and adds:
- `"$BS"` and quoted-path forms;
- the `reboot` verb: `(batman-slot["']?|"\$BS")[[:space:]]+["']?(rollback|commit|reboot)` and `batman-autocommit[[:space:]]+["']?release`.

**Lint (2), the pinned guarded sites:**
- adds `commit_guarded`;
- adds the new `reboot_guarded` rows, with their `<pre>`.

**Lint (3), new.** A word-level search in scope (`scripts/dv`, `scripts/node`, `scripts/fault-injection.sh`, `scripts/ab-selftest.sh`, `scripts/negctl-old-slot-254.sh`, `scripts/daily-validation.sh`):
- the pattern is `\breboot\b|sysrq-trigger|reboot_and_wait`;
- minus comment lines.
- Every hit must match a row of the checked-in inventory `scripts/dv/data/slot-sites.tsv`. A row is `file`, a substring of the line, and a group, which is one of:
  - `guarded`: the line must contain a guard call;
  - `prechecked`: the line is inside `reboot_and_wait` or calls it;
  - `allowlisted:<reason>`;
  - `text`: a log or echo line, about 120 of them.
- A hit with no row is a FAIL.
- A row with no hit is a FAIL.
- An empty inventory or zero hits is a FAIL.

**Negative control.** Run lint (1)–(3) on b885a2c with the new inventory. It must FAIL, and the set of FAILs is checked against the `guarded` / `prechecked` rows of the inventory (generated, not written by hand). After the change it PASSes.

**Behaviour proofs** (v1 B m10). Each converted host site is extracted and run against the stub node of `test-slot-guard-254.sh`:
- the matching state → `SENT`;
- another boot → `WRONG-STATE`, and no command;
- for overlay-wipe: no `firstboot` on `WRONG-STATE`, and `PRE-FAILED SENT` when `<pre>` fails.

`reboot_and_wait` gets the same treatment, with a stub `fssh`:
- an armed flag → no trigger;
- a clear flag → the trigger.

## 9. Security

**Assets:** control of the two bench nodes (slot, boot, p5 identity).

**Actors:**
- **Our own mistakes:** an armed reboot, an unmount of a product write, a wipe followed by a refusal, a test that cannot fail. Each is addressed above:
  - the guards fail closed;
  - `<pre>` keeps today's ordering;
  - only harness mounts are touched;
  - the CI test fails on zero rows or on a mutant that passes.
- **A local unprivileged host process:** same trust as today. The patch files and the inventory are repo content, reviewed like code. A host-derived mutant runs only in a dry-run bind on the node.
- **A compromised node:** nothing new is trusted from node output. The DISARM, `<pre>` and commit run only after the node-side checks pass.

**Attack-surface delta:**
- no new port, node env or secret;
- the `PB_*` seams are gated (§3.2);
- `<pre>` is a fixed string from the harness source.

**Privilege:**
- The node-side restore runs as root, as today.
- It unmounts only mountpoints under `/tmp/run/batman-dv/`, matched on the /proc/mounts entry.
- A non-root process cannot create a mount there.

**Failure mode:** fail-closed throughout.

**Secrets:** none touched. The dead-man IRK exposure is unchanged.
