## 1. `prov-ac-flap-254` asserts the P3 rule

**New premise.** A trial whose helper keeps exiting is not commit-worthy. §3.7.6(a) requires the enabled helper to run, so the trial is reverted at its deadline even while held. This is the rule the product implements; the unit now proves it.

**Flow.** The shape of `prov-ac-radio1off-254.sh` (an existing hold+revert unit):
1. `pr_begin 3000`.
2. Precondition `ble-ok` present (kept: the health-file checks below need the helper's BLE line).
3. `pr_ota_b "$PR_V.dirty.wbox-helper-flap" B`.
4. While in the trial (same boot), poll every 10 s up to uptime 480:
   - **mutant live:** at least 2 `WBOX-helper-flap-f4703b1d: exiting` lines this boot (kept);
   - **health file fresh:** this boot's, at most 60 s old (F14, kept);
   - `$RUNDIR/autocommit.why` read at least once as `svc batman-provhelper down`. This is the observed reason; it shows that §3.7.6(a) and not some other check is what holds the trial back. Never seen = FAIL "the helper gate never fired".
5. `pr_wait_reverted`. It already fails on HELD ("the mutant had no effect"), bounds the wait by the deadline + DEFER_MAX + 120, renews the lease on deferral, and is INVALID on a panic.
6. The reason of `PR_REVERT_LINE` (this trial boot only) must be `svc batman-provhelper down` or `batman-provd not stable for 60 s yet this boot`. Both are §3.7.6 (a) / (b) consequences of the flapping helper; the helper writes `provd-stable`. Anything else is a FAIL with the line.
7. `pr_end revert`, as radio1off: bad-slot checked and removed, then the restore.

**Removed.** The dry-run arm ("DRYRUN decision: COMMIT") asserted the pre-P3 premise. Its E-H5 #2 timing (time to the decision) is measured by `prov-autocommit-p3-254` on a healthy trial, so nothing is lost.

**Fixed with it.** The wsl.35 run failed its restore because the product rebooted the node, so the unit's lease expired. `pr_wait_reverted` + `pr_end revert` already handle a product revert (radio1off passes on the same machinery).

**Negative control.**
- Offline: the judging step (4–6) is a function fed with captured `autocommit.log` / `why` text. Fed the wsl.35 flap boot (395990f8) it PASSes. Fed the V boot of the recovery run (737210b4, `AC HELD slot=B`) it FAILs "HELD".
- On the node: the existing `pr_wait_reverted` HELD branch is that same negative.

## 3. `pr_restore_cycle` restores to the snapshot's slot

**Host** (`prov-254.sh:462-483`):
- `want` = `slot=` of `/opt/batdata/dv-prov/$RUN/snap/identity`. Unreadable or not A/B → NEEDS-PERSON (fail-closed, as today).
- A trial is left with `rb_guarded <boot8> <trial slot> 0 prov-dv-254`, not with the A-only `back_to_a`.
- The precondition becomes "slot = want, trial_rc = 1". If the node is committed on the other slot, that is NEEDS-PERSON: rolling a committed node over is not the restore's job.
- `:480` becomes `reboot_guarded <boot8> <want> 1 prov-dv-254` and must answer SENT.
- `back_to_a` (`:395-406`) answers "already on A" for an **A trial** too. It now requires trial_rc = 1 for that answer and handles an A trial through `rb_guarded`.
- `pr_p9` adds 02's state to its preflight line, for the record only. 02's slot no longer matters to the restore.

**Node** (`node/prov-base-254.sh:213-227`, p5-restore):
- Print `P5-MOUNTED <mountpoint>` for every p5 line of /proc/mounts.
- Unmount only the known temporary patterns: `*/batman-dv/pbm.*` (the harness's own), `*cfgsave-mnt.*`, `*autocommit.p5*` (product, read-only mounts).
- Re-check; die listing what is left.
- The host prints every `^(P5-|FAIL)` line, not only `tail -1`.

No umount of an unknown mount: that could be a product save in progress. That case is NEEDS-PERSON with the names.

## 6. `prober_test` "r2 D-2" measures the prober, not the feeder

- The `probe` helper runs its feeder unawaited and stops it when `f` completes, then returns `f`. The bound stays 1000 ms.
- What the bound protects: `prober.dart:227-230` starts the 20 s answer limit only on a whole msg2. A fragment must not start it, else the probe ends at 20 s instead of the 50 ms msg2 budget. Any bound far below 20 s discriminates.

**Negative control:** mutate `prober.dart:228` `if (st != null && !gotMsg2)` to `if (!gotMsg2)`. The fixed test FAILs (about 20 s); the real code PASSes on Windows with the whole file run.

## 9. Security

- **Assets:** control of the two bench nodes (slot and boot state, p5 identity).
- **Actors:**
  - Our own mistakes are the main one. An unguarded reboot can boot an armed test slot; a restore can leave a node on the wrong slot.
  - A local unprivileged process on the host could edit the harness, but the harness runs as the same user. No new privilege.
  - Nodes are reached as root over ssh with the lab key, as today.
- **Attack-surface delta:**
  - `PB_MOUNTS` is a test-only file seam, honoured only under `PROV_BASE_TEST_ROOT`; a production node never runs the harness.
  - No new port, no new env on the node, no new secret.
- **Privilege:**
  - The node-side restore runs as root, as today. It now unmounts by pattern; the patterns are fixed strings under `/tmp/run`, and it never follows a user-supplied path.
  - TOCTOU: the restore reads /proc/mounts and unmounts the listed mountpoint. A lower-privileged node process cannot create a p5 mount, because mount needs root.
- **Failure mode:** fail-closed everywhere. An unreadable snapshot slot, an unknown p5 mount, or a guard that answers anything but SENT gives NEEDS-PERSON or FAIL, never a silent reboot.
- **Secrets:** none touched. The p5 restore content is unchanged.
