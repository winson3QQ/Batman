## 0. 一句話與原則

**使用者只看到「現在能做什麼」和「這則訊息到了沒」,永遠不必知道是哪張網在送。**

原則【決策】:**HaLow 常開;LoRa 發射稀少、有預算、可被 EMCON 關掉。**
- v3 寫的「一次只讓一種電台發射」只在「使用者流量」層面成立:HaLow 只要開著,就一直在發 beacon / ELP / OGM;H 模式下的逐則升級、出口代發、孤島代理也都是「HaLow 開著時發 LoRa」。所以真正的約束不是「互斥」,而是「**LoRa 每次發射都是昂貴動作,必須稀少、分散(不連發)、算進預算**」(F1)。
- 切換要慢、要穩、要誠實,寧可晚一點切,也不要讓畫面來回跳。

## 2. 使用者心智模型(UX 原則,最高優先)

使用者不懷疑系統的前提是:**系統說的話永遠是真的,而且不會一直改口。** 六條規則【決策】:

1. **講「能做什麼」,不講「用哪張網」**。操作者介面只有三個狀態:

   | 狀態 | 對使用者的一句話 | 背後 |
   |---|---|---|
   | 🟢 **完整** | 語音、照片、地圖都可用 | HaLow 通 |
   | 🟡 **精簡** | 依 EMCON 等級顯示(見下) | HaLow 不通,LoRa 可用 |
   | 🔴 **無法確認送達** | 「訊息已送出/已保存,但一直沒有收到任何回覆;可能沒送到」 | L 模式下超過 T 沒有任何收訖(§3.1 X) |

   🔴 **不說「離線」也不說「沒送到」**:非對稱鏈路時(H 聽得到我、我聽不到 H)訊息其實可能已送達。系統只說它知道的:**沒收到確認**。

   🟡 的一句話依 EMCON 等級(§3.4):
   - AUTO:「只能傳文字和位置,可能要等幾分鐘」
   - SOS_ONLY:「靜默中:位置不自動回報,求救仍可送出」
   - LORA_SILENT:「**LoRa 靜默(主網仍在發射;要完全靜默請關閉電台)**」

   HaLow、LoRa、batman 這些字**只出現在管理員視圖**;唯一例外是 LORA_SILENT 的措辭,因為那是操作者主動選的戰術等級,必須講清楚哪個電台還在發。

2. **每則訊息有自己的誠實狀態**,和網路狀態分開顯示:
   `排隊中` → `已送出` → `備援已接收`(收到出口的收訖摘要,§5.2;只代表「某台 H 節點收到並轉進主網」)→ `已送達`(收到**端對端確認**,產生者見 §5.2;目的地是 ATAK / iTAK 使用者時,只能確認到「**已送到伺服器**」,就照這樣寫)。經 LoRa 送出的小字標「經備援送出」。位置廣播本來就沒有確認,寫「已廣播」,**絕不假裝已送達**。

3. **不讓按鈕騙人**:精簡狀態下,語音 / 照片按鈕變灰並寫原因;按照片時提供「先存著,恢復後送出」或「改傳一段文字描述」。

4. **狀態不閃爍**:狀態切換經過去抖動(§4.2);反覆切換時**停在誠實的穩定狀態**(🟡 附註「連線不穩」),不在 🟢/🟡 之間跳。

5. **降級時說一次原因和該做什麼**,之後不重複騷擾(超出範圍 / 疑似強干擾 / 電量低)。

6. **備援本身壞了要先講**:🟢 狀態下小圖示顯示「備援就緒 / 備援不可用」,依本機 serial API 健康檢查,**不靠週期性 LoRa 發射**。沒有 RAK 的節點顯示「本機無備援」(§3.5)。

**指揮所端**:經 LoRa 來的位置標「經備援」(孤島代理打包來的標「經備援·代轉自 <代表>」);依 EMCON 政策靜默的節點標「依政策靜默」(只有在該節點進入靜默前有送出通知時才標得出來,§3.4);孤島成員標「孤島中」,讓指揮官分得出「人不見了」「刻意不發」「被隔開了」。

**操作者端的指揮所連線橫幅**(🟢 狀態下也要誠實):HaLow 內隊友都在、但指揮所不在時,🟢 旁邊必須顯示一行:
- 孤島、島包已送出但還沒收到收訖:「與指揮所連線中斷,位置經備援送出中(尚未確認)」
- 孤島且已收到收訖:「與指揮所連線中斷,位置經備援回報」
- 孤島但一直收不到收訖:「與指揮所連線中斷,位置回報無法確認送達」
- 指揮所預告維護中:「指揮所維護中,位置暫未回報(約 N 分鐘)」

## 3. 系統模式(每台節點本地的狀態機)

### 3.1 模式

| 模式 | 進入條件 | HaLow | LoRa | UX |
|---|---|---|---|---|
| **H — 主網** | 預設 | 正常收發 | **只收不發**;例外見下,全部受預算、最小間隔與 EMCON 限制 | 🟢(可能加「連線不穩」標籤 §4.2、指揮所連線橫幅 §2) |
| **I — 孤島** | H 模式 + 孤島判定成立(§4.4.1) | 正常收發 | **只有被選出的代表**發(島包、代發成員的文字 / SOS);其他成員不發 LoRa(例外只有 SOS 交接失敗,§4.4.4) | 🟢 + 橫幅「與指揮所連線中斷…」 |
| **L — 備援** | 所有 wlh0 鄰居 batman last-seen > 60 s(§4.1) | **保持入網、正常功率**;本機產生的應用資料不走 HaLow(應用層選路,batman 照常轉發) | 依 EMCON 收發 PLI / 文字 / SOS,受 L 預算限制 | 🟡(依 EMCON) |
| **L-probe — 回切觀察中** | L 模式下,最近 10 s 內有 ≥ 5 個有效樣本、且其中 ≥ 50% 有任一 wlh0 鄰居 last-seen < 3 s,且不在 probe 退避期(§4.1) | 同 L;本機 PLI **同時**在 HaLow 上送一份(不等確認,§4.1) | 停止**自主** LoRa PLI;保留 SOS 與 PLI 底線 | 🟡 |
| **X — 無法確認送達** | L 模式、EMCON=AUTO、本機送出的 LoRa 訊息在 **T** 內**沒有任何收訖摘要涵蓋**(§5.2) | 同 L | 同 L,但 PLI 間隔拉長 | 🔴 |

**X 的判定細節**【決策】:
- **只看「有沒有收到涵蓋我訊息的收訖摘要」**。v4 的「也沒聽到任何受信任節點」刪除:聽得到別人只代表我收得到,不代表我送得出去;兩台一起困在外面的 L 節點會互相聽到而一直停在 🟡(第四輪 M5)。
- **T = 12 min** = 2 × 收訖摘要間隔上限(5 min)+ 摘要排隊上限(2 min)。**收訖摘要不受全隊縮放影響**(§5.1),排隊逾時升優先(§5.1),正常情況下摘要不會晚到超過 T;但這不是硬保證(見下)。
- **只在 AUTO 判 X**。SOS_ONLY:送出 SOS 後 **T_sos = 3 min** 沒有 SOS 確認才顯示 🔴(SOS 重送 3 次 × 15 s 間隔 + 出口確認排隊 ≤ 1 min + 餘裕);LORA_SILENT:永不判 X。
- EMCON 必須全隊一致(§3.4);出口的收訖摘要與 SOS 確認都帶 EMCON 欄位,L 節點據此知道政策。
- **X 與收訖摘要同一步上線**(§10 第 4 步);在那之前不顯示 🔴。
- **介面方向**:msg-router 維護「本機最後一次被收訖摘要涵蓋的時間」並提供給 radio-mode;X 由 radio-mode 判定。
- **T 不是硬保證**:摘要排隊超過 2 min 會升優先,但仍受預算;出口預算 2%(§5.1)下,摘要本身平均只佔約 0.7%,正常情況不會超時,超時時頂多延後判 X。

**H 模式下 LoRa 只收不發的例外**【決策】(全部經 lora-sched、先過 EMCON;除「連線不穩」下的 SOS 雙發與 SOS 確認外,都受預算與最小間隔):
- **LoRa 出口**:目的地的 originator last-seen > `ORIG_STALE_S`(§4.3)、且本機被選為該目的地的出口(§5.2)時代發;包含 SOS 應用層確認與收訖摘要。
- **逐則升級**:見 §4.3(只對「會回確認」的目的地)。
- **孤島代理**:見 §4.4(只有代表)。
- **沒有 PLI 底線**:H 模式與孤島成員**不適用** `PLI_MAX_GAP`(第四輪 B2);H 模式的位置只走 HaLow。

### 3.2 為什麼 H 模式不讓 LoRa 自由發射

F1:LoRa 發射會把自己的 HaLow 打到剩一半或更少;F2:920–925 MHz 內靠分頻擋不住。所以 LoRa 在 H 模式只做「沒有它就送不到」的發射,而且分散開(§5.1 最小間隔),不讓兩次發射連在一起形成 F1 的崩潰型態。

### 3.3 為什麼 L 模式不降 HaLow 功率

連鎖(A 降功率 → 只靠 A 的葉節點 B 也進 L)、互鎖(大家都降功率,誰都聽不到誰的 ELP,回切永遠不成立),且 F4 顯示 ≥ 20 dBm 的設定沒效果。【決策】L 模式 HaLow 維持正常功率。L 模式 HaLow 控制流量對自己 LoRa 收訊的影響目前沒有可靠數據(F3),待 V15。

### 3.4 電磁靜默(EMCON)政策【決策,預設值待拍板】

**定義**:EMCON 控制的是「**因為被干擾而增加的 LoRa 發射**」。它**不控制 HaLow 本身的發射**。

| EMCON 等級 | LoRa 行為 | 實作 | 適用 |
|---|---|---|---|
| **AUTO** | 依模式發 PLI / 文字 / SOS / 收訖摘要 / 島包,全受預算限制 | lora-sched 策略 | 民用 / 救災 |
| **SOS_ONLY** | 平常不發;只發 ①使用者按下的 SOS ②**對 SOS 的確認**(唯一例外:每個 (來源, 紀元, SOS 序號) 由唯一出口確認 1 次;每台出口 ≤ 1 則確認 / 分鐘) | lora-sched 策略 | 戰術預設候選 |
| **LORA_SILENT** | LoRa 完全不發;求救需操作者明確解除靜默(會寫一次 flash) | **`tx_enabled=false` 硬閘**(韌體層,轉發 / ACK / NodeInfo 都不發) | 高威脅環境 |

**EMCON 的分發與一致性**【決策】(第四輪 M4):
- EMCON 是**全隊政策** `(紀元, 版本, 等級)`,由管理員設定,擁有者是 policy 程序(§5.5)。
- **分發有兩條路**:
  1. HaLow:policy 程序經 bat0 廣播分發(政策變更時送一次 bat0 廣播,之後各節點在**回到 H 模式時查一次、之後每 10 min 查一次**,以單播向 policy 程序補齊;不做週期廣播,§5.2)。
  2. **LoRa**:出口的收訖摘要與 SOS 確認**都帶 3 B 的 `(紀元, 版本, 等級)`**。L 節點只能從這條路聽到政策。
- **政策欄位**(3 B,24 bit):紀元 6 bit | 版本 16 bit | 等級 2 bit(0 AUTO / 1 SOS_ONLY / 2 LORA_SILENT / 3 保留)。**紀元只由 provisioning 改**(本機 app / 實體);**經網路收到的政策,紀元 ≠ 本機紀元就一律忽略**(第六輪 R-M2),紀元相同時才比版本。
- **收緊與放寬不對稱**(第五輪 C-M1 修正):
  - **只採用 (紀元, 版本) 比目前新的政策**。重放舊摘要帶的是舊版本 → 直接忽略,不會讓節點收緊。
  - 新版本的收緊一律採用,**但經 LoRa 收到的政策最多只能收緊到 SOS_ONLY**;LORA_SILENT(要寫 RAK flash)只接受經 HaLow 或本機操作設定,不接受經 LoRa 遠端觸發。
  - W13(簽章)上線前,**放寬**只在「經 HaLow 收到」時採用,且:
    - 有操作者的節點:要操作者在本機確認(「指揮所要求改為 AUTO,確認?」);
    - **無人值守節點**(provisioning 標記 `unattended=1`,例如固定站、gateway 側收聽節點):經 HaLow 收到即採用(它們在管理員那一側,否則會永遠卡在嚴格等級,第五輪 C-M2)。
  - 經 LoRa 收到的放寬一律不採用。
  - **有效等級與全隊最新政策不同的節點(不論原因)不參加出口選舉與孤島代表選舉**,避免卡在嚴格等級的出口不回摘要、害 L 節點被誤判 X。
  - **版本鎖死的復原**:未認證期間,有人灌一個最大版本號就能讓管理員發不出更高版本。復原方式:管理員在 provisioning 時對全隊寫入新紀元(需要接觸每台,或經 #219 app 本機設定);因為網路上來的不同紀元一律忽略,偽造的高紀元無法把節點鎖死。**誠實界線**:W13 前 EMCON 分發沒有認證,HaLow 內部的人可以讓全隊收緊(DoS),但無法遠端讓全隊放寬。
- 節點離開 HaLow(L 模式)時沿用最後已知政策,並依 LoRa 收到的摘要只收緊不放寬。
- 操作者只能在本機**加嚴**,不能放寬;本機加嚴的節點**不參加出口選舉與孤島代表選舉**。本機加嚴狀態放在**本機每則 LoRa 上行封包的 1 bit 旗標**與孤島廣播中,讓出口知道「這台不會回摘要 / 不會當代表」。
- **SOS 解除 LORA_SILENT**:需切 `tx_enabled=true`(寫 flash)。**V6 是 LORA_SILENT 的上線前置閘**:若 V6 顯示會重開 RAK,UX 在操作者選 LORA_SILENT 時就要講「解除後求救約需 X 秒」。
- 所有會發 LoRa 的路徑都經 lora-sched 的 EMCON 閘,**沒有第二條發射路徑**(BLE 例外見下)。
- PLI 間隔用**指數分布**隨機化。
- **BLE 路徑**:手機透過 RAK BLE 直接發送的封包不經 Pi,繞過預算與 AUTO/SOS_ONLY(只有 `tx_enabled=false` 擋得住)。戰術版 RAK BLE 在 provisioning 時關閉(#220 W6);民用版保留 BLE 時,部署文件寫明,且 EMCON ≠ AUTO 時建議關閉 BLE。
- 旁邊的 Tier-0 手機不受我們控制;部署文件提醒。

**全電台關閉(RADIO_OFF,不是 EMCON 等級)**【決策,第四輪 M10 修正】:
- 範圍:HaLow(wlh0)down、Pi 的 2.4 GHz AP(radio0,brcmfmac)down、LoRa `tx_enabled=false`。RAK BLE:戰術版在 provisioning 已關;民用版若開著,RADIO_OFF **無法在不重開 RAK 的情況下關閉**(F15 類風險)[?],文案要寫出來。
- 進入前:H 模式時先經 HaLow 送一則「進入全靜默」給指揮所(讓指揮所能標「依政策靜默」);L 模式時**不為此發 LoRa**,文案改為「指揮所可能看到你失聯」。
- 文案:「本機電台已關閉:你收不到、也發不出任何訊息。**手機本身的 Wi-Fi / 行動網路 / 藍牙不受本系統控制,請自行關閉。**」
- 只能由操作者本人手動恢復,系統不自動開回。實作屬 §10 之後的獨立單。

### 3.5 沒有 RAK 的節點

- radio-mode 照跑,計算模式並回報,但不能進真正的 L:HaLow 鄰居全失時直接顯示 🔴「無法確認送達」(本機無備援),訊息存著。
- 孤島時是**成員**:把自己的 PLI 交給代表;不能當代表。
- 🟢 時的備援圖示顯示「本機無備援」,不是「備援不可用」。

## 4. 切換邏輯:慢、穩、誠實

### 4.1 觸發器

取樣約每 1 s 讀一次 wlh0 上的 batman 鄰居 last-seen。**所有「最近 N 秒內」的條件都以 monotonic 時間窗計算,不以樣本數計**(取樣會漂移,實際間隔約 1.1–1.3 s);窗內有效樣本太少時該窗不判定。

| 方向 | 條件 | 理由 |
|---|---|---|
| H → L | **所有 wlh0 鄰居** last-seen > 60 s;**鄰居表為空**時,自空表起算 60 s(只計 HaLow 介面;wlh0 不在 bat0 視同空表) | F6/F7 |
| L → L-probe | 最近 10 s 內有效樣本 ≥ 5 個,其中 ≥ 50% 有任一 wlh0 鄰居 last-seen < 3 s;**且不在 probe 退避期** | 瞬時條件會被邊緣鄰居反覆觸發(第三輪 N2) |
| L-probe → H | **固定觀察窗**(30 s,阻尼時延長 §4.2)**結束時判定一次**:窗內扣除本機 LoRa 發射時段與取樣空窗後的有效樣本,≥ 90% 滿足「任一鄰居 last-seen < 3 s」。有效樣本 < 窗長的 50% → 觀察窗延長一次,仍不足則判失敗 | 對稱、只看本地 |
| L-probe → L | 觀察窗判定失敗 | 回到 L,恢復自主 PLI,啟動 probe 退避 |

- **probe 退避**:L-probe 失敗後,下一次可進 L-probe 的最短等待依序為 **30 s → 2 min → 5 min(上限)**。歸零條件:成功回到 H,或連續 10 min **沒有任何一個樣本**有鄰居 last-seen < 3 s。
- **PLI 最大間隔底線 `PLI_MAX_GAP`**(防 PLI 餓死,第四輪 B2 重寫)【決策】:
  - **只適用於會發 LoRa PLI 的狀態**:L、L-probe、X、孤島代表。**H 模式與孤島成員不適用**。
  - 「送出」= **LoRa 已發射**(不看 HaLow;位置本來沒有確認)。
  - 各狀態的值(都 ≥ 2 × 該狀態的平均 PLI 間隔,讓指數分布的隨機性大部分保留):

    | 狀態 | 平均 PLI 間隔 | `PLI_MAX_GAP` |
    |---|---|---|
    | L | 60 s | 5 min |
    | L-probe | (不發自主 PLI) | 5 min(沿用 L) |
    | X / 看門狗絕對上限後 | 5 min | 15 min |
    | 孤島代表(有收訖) | 島包 5 min × 包數(§4.4.4) | 2 × 平均島包輪次間隔 |
    | 孤島代表(無收訖) | 15 min | 30 min |

  - L-probe 期間本機 PLI **同時**在 HaLow 上送一份(免費、不等確認);LoRa 只由底線觸發,不做「HaLow 30 s 沒確認就升級」(位置沒有確認,那條規則會每次都觸發)。
  - **不變式**:`PLI_MAX_GAP` ≥ 2 × **縮放後的**平均間隔。全隊縮放把平均間隔拉長時,底線跟著乘同一個倍數(第五輪 C-M6)。
  - **底線觸發時間加抖動**:在 `PLI_MAX_GAP × (1 − U(0, 0.2))` 時觸發,不在固定時刻,避免 X / 無人收聽模式變成嚴格週期的測向信標。
  - 底線發射經 lora-sched,受 EMCON 與最小間隔,優先序見 §5.1。
- **開機寬限**:uptime < 3 min 時不評估 H → L(F9)。**HaLow 設定變更**(已 commit 的 morse / mesh 設定改變,含 F10 還原)後另起 3 min 寬限。**程序重啟**不給寬限(H→L 本來就要 60 s 證據),但重啟後前 60 s 的狀態記為「未知」。
- **gateway / OTS 可達性不當 H/L 回切條件**,只用於孤島判定(§4.4)、逐則升級與指揮所圖示。
- **L 模式看門狗**【決策】:
  - 軟上限:L 模式超過 30 min 且期間曾進 L-probe 但未回 H → 記錄並上報。
  - **絕對上限**:L 模式連續 **2 h** → PLI 改用 X 的間隔與底線,並對管理員告警;**不自動改任何無線電設定、不重開機**。
- 所有計時用 monotonic clock(節點無 RTC,#174)。

**不用的訊號**:802.11s peer 消失(F6)、batman 移除鄰居(200 s)、「在不在 originator table」(F19,400 s)、絕對掉包率(F8)。

**回切觀察被 LoRa 遮蔽**:lora-sched 匯出本機每次 LoRa 發射的起訖時間,回切判斷扣除那些時段;進 L-probe 就停止自主 PLI。別台 L 節點的遮蔽受各自預算限制【推論,待測】。**影子模式量到的 L-probe 統計是樂觀值**(影子不發 LoRa,也沒有 L-probe 內的 HaLow PLI 流量)。

**觸發器的已知盲點**:last-seen 只反映「我聽得到對方」。本機發不出去但收得到時會一直留在 H;緩解靠逐則升級與 originator TQ 輔助【推論,待 V13】。

### 4.2 防抖動:遲滯 + 翻轉阻尼

- **非對稱時間**:下切 60 s;上切要 L-probe 觀察窗的穩定證據。
- **翻轉計分**:每次 H→L→H 算一次翻轉。
  - **阻尼等級** 0 / 1 / 2 / 3 對應觀察窗 30 s / 30 s / 2 min / 5 min。
  - 最近 10 min 內的翻轉數 ≥ 2 → 等級 +1(每多一次翻轉再 +1,上限 3)。
  - 連續 10 min 沒翻轉 → 等級 −1。
  - 等級 ≥ 1 時對操作者加上「**連線不穩**」標籤(純 UX 標籤,不是模式);等級回到 0 才移除。
- 阻尼期間延長的觀察窗,仍受 §4.1 的 `PLI_MAX_GAP` 保護。
- **「連線不穩」標籤下只有 SOS 立即雙發**(HaLow + LoRa,受 EMCON,不受預算);文字不雙發。
- L↔L-probe 轉換**不算翻轉**,由 §4.1 的 probe 退避處理。
- **UX 去抖動的定義**:顯示層只在「距上一次顯示變化 ≥ 30 s」時才更新,**更新成當下最新的內部狀態**;中間經過的狀態不顯示。每日可見變化次數依此計算(影子模式 Q6)。

### 4.3 逐則訊息升級(處理半殘與網路分割)

- **只對「會回端對端確認」的目的地升級**(第四輪 M6):
  - 有 #219 app 的節點(app 會回確認)、OTS 橋接(寫進 OTS 後回確認)。
  - 送給 ATAK / iTAK 使用者的文字,是先進 OTS 再由 OTS 轉送 → 以 OTS 橋接的確認為準,狀態寫「已送到伺服器」。
  - 其他不會回確認的目的地:不升級;傳輸層送出成功(例如 TCP 寫入成功)即標「已送出」。
- 文字 / SOS 走 HaLow 送出後,若 **T 秒內沒收到端對端確認**(SOS 10 s、文字 30 s),自動再經 LoRa 送一次;UI 顯示「已改走備援送出」。
- **目的地的 originator last-seen > `ORIG_STALE_S`**(預設 20 s,待影子模式校正)→ 直接走 LoRa(或孤島時交給代表),不必先等 HaLow 逾時。**不用「在不在表中」**(F19)。單次逾時不算。
- 所有升級發射受 H 預算與最小間隔限制(SOS 除外),先過 EMCON,並依全隊縮放(§5.1)。
- 兩條路都到的重複訊息,由收端依 **(來源節點, 序號紀元, 訊息序號)** 去重(§5.4)。

### 4.4 孤島與孤島代理(使用者 2026-09-28 選 B;v4.1 重寫)【決策】

**情境**:整組一起離開 gateway 範圍,彼此仍是 HaLow 鄰居,沒有人會進 L。做法:**孤島內選一台代表,把全島的位置打包成一則從 LoRa 送,其他節點孤島期間不發 LoRa。**

#### 4.4.1 孤島判定

- **gateway 集合**:provisioning 時登錄的「上行節點」(OTS host、有線回指揮所的固定站)的 originator 位址;可有多台。沒有登錄任何 gateway 的部署 → 孤島功能關閉。**本機自己在 gateway 集合內 → 本機不判孤島。**
- **「gateway 在場」= 該 gateway 的 originator last-seen < `GW_FRESH_S`**(預設 10 s,待影子模式校正)。不用「在不在表中」(F19)。
- **進入孤島**(全部成立):
  1. 本機在 H 模式;
  2. gateway 集合中每一台都**不在場**,且持續 ≥ `ISLAND_S`(預設 120 s);
  3. **沒有生效中的「gateway 維護預告」**(見下)。
- **gateway 維護預告(取代 v4 的 80% 啟發式,第四輪 B1)**:
  - OTS host 在**計畫性**關機 / 重開 / 更新前,由 policy 程序經 bat0 廣播「維護中,預計 N 分鐘」(管理員操作或關機腳本自動送出)。**N ≤ 60**;**只接受來源是 gateway 集合內 originator 的預告**(未認證期間這是唯一的過濾,偽造者需在 HaLow 內部且冒用 gateway 位址,照實列為風險)。
  - 收到且未過期 → 狀態 **GATEWAY_MAINT**(不是模式,只是旗標):不選代表、不發 LoRa;操作者橫幅「指揮所維護中,位置暫未回報(約 N 分鐘)」。
  - 預告過期(N + 5 分鐘)而 gateway 仍不在場 → 視為孤島。
  - **沒有預告的消失,一律當孤島處理**。代價寫明:OTS host 意外當機時,全隊會被判為孤島,代表會發島包,但如果 gateway 那側沒有其他帶 RAK 的收聽節點,島包沒人聽到 → 12 min 無收訖後代表退到 15 min 一包(§4.4.4)。**寧可多發幾包,也不要整隊靜默卻顯示 🟢**。
- **離開孤島**:任一 gateway 在場持續 ≥ 30 s。
- **開機寬限**:uptime < 3 min 不判孤島。
- **部署需求**:gateway 那一側要有**帶 RAK 的 H 節點**(OTS host 自己帶 RAK 即可)當收聽者,島包才有人聽;部署文件寫明。

#### 4.4.2 代表選舉

**資料交換不用 alfred**(第四輪 M3):alfred 是 master / slave 架構,分割後島內可能拿不到彼此的資料 [?]。改用 **bat0 上的孤島廣播**(msg-router 送出,**只在孤島期間**,**內容有變化時才送、至少每 5 min 一次**(第六輪 R-m2:整隊都成孤島時,每 60 s 週期廣播仍是 N² 級負載);資格逾期門檻相應改為 10 min):`{node, has_rak, rak_ok, emcon_local, battery_pct, wlh0_nbr_count, best_summary_snr, is_proxy}`。

- **候選**:本機判定為孤島、且在本機看得到的節點(originator last-seen < `CAND_FRESH_S`,預設 30 s,與 `GW_FRESH_S` 分開校正)中,**名冊標記有 RAK** 的節點。
- **資格**(需該候選的孤島廣播 ≤ 10 min 內):`rak_ok`、有效 EMCON 等於全隊政策、電量 ≥ 30%(沒有電量資料視為 50%)。
- **完整視圖規則**(第五輪 C-M3 修正):只有在本機**收到了所有候選**(originator 新鮮、名冊有 RAK)的孤島廣播時,才用下面的完整排序;**只要缺任何一台的資料,就只用「node num 小者」排序**(包含自己,自己的資料也不用)。這樣廣播完全不通時,每台只靠 originator table + 名冊算,會得到同一個結果;不會變成每台都選自己。
- **完整排序**:①**現任代表優先**(黏著,見下)②`best_summary_snr` 高者(曾被出口聽清楚)③`wlh0_nbr_count` 少者(優先挑葉節點,避免代表是島內中繼——代表每發 1.3–1.9 s,自己的 HaLow 就斷那麼久)④電量高者 ⑤node num 小者。
- **無收訖換人探索**(第五輪 C-M4):代表送出後 T(12 min)內沒有任何收訖摘要 → 讓位給排序中的下一台(在 bat0 廣播 `yield`),下一台同樣有 T 的機會;所有候選輪過一圈都沒有收訖 → 回到第一順位,進「無人收聽」慢速模式(§4.4.4),每 1 h 再輪一次。
- **黏著**:現任代表只有在 ①失去資格 ②孤島廣播逾期 > 10 min ③originator last-seen > 30 s ④無收訖讓位 時才換人;挑戰者的 `best_summary_snr` 比現任高 ≥ 6 dB 且持續 10 min 才可取代。
- **衝突處理**(沒有 `term`,v4 的 term 刪除):
  - 自稱代表者在孤島廣播設 `is_proxy`。看到另一台 `is_proxy` 時,**只用 node num 比較**(小者留下),不用各自的完整排序;這樣部分視圖(一台資料齊全、一台缺資料)也會收斂成一台(第六輪 R-m1)。
  - 備援判斷:代表在 LoRa 上**聽到**另一個本島代表的島包(同島的節點距離近,一定聽得到),且對方 node num 較小 → 讓位。這條不依賴 HaLow 廣播。
  - 最壞情況:短時間兩台都發,發射量仍受各自預算上限。
- 代表自己進 L → 不再是孤島成員,其他成員重選。
- 同時是出口又是代表的節點:預算取兩者之和,但絕對上限仍是 3%。
- **誠實界線**:`best_summary_snr` 量的是「出口 → 代表」,不是「代表 → 出口」;第一包送出前大家都沒有這個值,首選只能靠葉節點 / 電量,**不保證是被聽得最清楚的那台**。

#### 4.4.3 打包格式(應用層,Meshtastic 頻道廣播 payload 內)

| 欄位 | 大小 | 說明 |
|---|---|---|
| 版本 / 類型 | 1 B | `ISLAND_PLI_V1` |
| 名冊版本 | 1 B | 收端名冊版本不同 → 丟棄所有成員項,只採用代表自己的位置(不會把 A 的位置畫給 B,第五輪 C-M7) |
| 代表 node num | 4 B | |
| 序號紀元 + 序號 | 2 B + 4 B | §5.4 |
| EMCON 旗標 | 1 B | 本機加嚴 bit + 政策版本低位 |
| 代表位置 | 8 B | lat/lon int32(1e-7 度) |
| 代表年齡 / 旗標 | 1 B + 1 B | 同成員 |
| 成員數 n | 1 B | |
| 每位成員 | **7 B** | **名冊索引 1 B**(名冊 ≤ 255 台,由 provisioning 發;名冊不同版本的節點不互相打包)+ 相對代表的東 / 北位移 int16×2(單位 2 m,±65 km;超出範圍者只送旗標「位置超出範圍」,不送座標)+ 年齡 1 B(10 s 為單位,**在送出當下計算**,排隊期間重算)+ 旗標 1 B(SOS / 低電量 / 無 GPS / 超出範圍) |

- 固定開銷 24 B。**上限 200 B**(< 233 B)→ 未簽章每包最多 **25** 位成員,簽章後 **16** 位。
- airtime(F18 公式):10 位成員(94 B)約 1.09 s;25 位(199 B)約 1.87 s。

#### 4.4.4 發射規則與預算

- 代表的所有發射經 lora-sched,受最小間隔、EMCON;**代表的預算 = H 預算 1% + 每 10 位成員 0.5%,絕對上限 3%**(10 分鐘 18 s)。
- **島包輪次**:一輪 = 送完所有成員需要的包數(未簽章 ≤ 25 人一包)。輪次平均間隔 **5 min**(指數分布);若一輪所需 airtime 超出預算,就**拉長輪次間隔**,並讓成員 UX 顯示「位置約每 N 分鐘回報一次」(誠實顯示實際間隔)。
- **成員不發 LoRa**。成員的 PLI 經 HaLow UDP 單播給代表(代表發射那 1–2 s 內會掉 → 成員每 30 s 送一次最新位置,不需逐則重送);文字與 SOS 也交給代表代發。
- **SOS**:代表轉發時**保留成員原本的 (紀元, 序號)**,讓去重生效。
- **SOS 例外**【決策,待拍板】:成員的 SOS 交給代表後,**10 s 內代表沒有回「已交接」**,成員自己從 LoRa 發 SOS(受 EMCON);成員自發後,代表收到遲到的交接就**不再轉發那一則**。交接有競態(代表回覆剛好遲到),同一則 SOS 最壞約 6 次發射、2 個來源;收端以 (成員, 紀元, 序號) 去重,只影響 airtime 不影響正確性。
- **收訖回饋**:出口的收訖摘要列出島包的 (代表, 紀元, 序號),代表經 HaLow 把「備援已接收」轉回各成員。
- **沒有人聽得到**:代表送出後 T(12 min)內沒有任何收訖摘要 → 輪次間隔拉長到 15 min(`PLI_MAX_GAP` 30 min),成員橫幅顯示「位置回報無法確認送達」。

#### 4.4.5 回程(指揮所 → 孤島成員)

- 出口在 LoRa 上聽到島包後,把「成員 → 代表」的對應以單播回覆給發出出口查詢的節點,並在其快取中保存(對應表的擁有者是 msg-router)。
- 指揮所要送給孤島成員的訊息 → 目的地 originator last-seen > `ORIG_STALE_S` → 出口查表發現它屬於某代表 → 頻道廣播、應用層目的欄寫「成員 X 經代表 Y」→ 代表經 HaLow 轉給成員。
- 對應表逾期(30 min 沒聽到該島包)→ 刪除;之後只有在「最近 T 內在 LoRa 上直接聽到該成員」時才直接對它發,否則訊息排隊並回報「目的地無法到達」。

#### 4.4.6 殘留風險(寫明)

- 代表承受自己 LoRa 對自己 HaLow 的干擾(F1);選葉節點當代表、單發不連發是緩解。V2 要量「每 5 min 一發 1.9 s」對島內 HaLow 的影響。
- 代表是單一發射源 → 測向只需找一台;但比 N 台都發的暴露面小。代表輪替 v4.1 不做,列為開放題。
- LoRa 只有單跳:孤島到最近的 H 收聽節點超過單跳距離就送不到。
- OTS host 意外當機會被判成孤島(§4.4.1),代價是少量無人收聽的島包。
- 名冊索引依賴全隊名冊版本一致;版本不一致的節點不互相打包(退回各自在 L 或由代表只送名冊一致者)。

## 5. LoRa 用量控制(不讓備援打爛主網)

### 5.1 硬性 airtime 預算【決策,數字待 V2 實測校正】

以**秒**計(F18)。**預算就是 token bucket**(一個機制,不是「滾動 10 分鐘」加 bucket 兩套):補充速率 = 預算 / 600 s。

| 角色 / 模式 | 補充速率(相當於 10 分鐘內) | 約等於(0.85 s / 包) |
|---|---|---|
| H(含升級) | 1% ≈ 6 s | 約 7 包 |
| H + 出口 | 2% ≈ 12 s(出口替 L 節點與孤島發摘要 / 確認) | 約 14 包 |
| I 代表 | 1% + 0.5% / 10 位成員,上限 3% | 見 §4.4.4 |
| L / L-probe / X | 5% ≈ 30 s | 約 35 包 |
| SOS | 不受預算;每則最多 3 次,間隔 ≥ 15 s(加抖動) | — |

- **bucket 深度 = 2.6 s**(≥ 最大單包 1.87 s,且約等於 3 個短包);**最小發射間隔 20 s**(SOS 除外)。所以不會出現 7 包連發約 6 s 的 F1 崩潰型態。
- 由 lora-sched 在**送出前**以實際 payload 長度換算 airtime 扣款;涵蓋**所有**經本機 RAK 發出的封包。
- **全隊縮放**(第四輪 M8 修正):`N_tx` = 最近 10 分鐘在 LoRa 上聽到的**名冊內** node id 數(含本機;名冊外的 id 不計,擋住陌生節點與偽造 id 灌大)。PLI(非底線)、升級、島包的平均間隔乘以 `min(4, max(1, N_tx / 3))`。**收訖摘要、SOS、SOS 確認、PLI 底線不縮放**。
- **發射優先序**(lora-sched 單一佇列,由高到低):

  | 優先 | 類型 | 受哪些限制 |
  |---|---|---|
  | 0 | RADIO_OFF / LORA_SILENT | 一切都不發 |
  | 1 | SOS、SOS 確認 | EMCON;最小間隔除外;不受預算 |
  | 2 | PLI 底線 | EMCON、最小間隔;可讓 bucket 欠額最多 1 包 |
  | 3 | 收訖摘要(排隊 > 2 min 時升到這一級) | EMCON、最小間隔、預算 |
  | 4 | 島包 | 同上 + 縮放 |
  | 5 | 逐則升級文字、L 模式 PLI | 同上 + 縮放 |
  | 6 | 一般收訖摘要(未逾時) | 同上 |

- 預算用盡時:位置只保留**最新一筆**;文字排隊;UI 照實顯示「排隊中」。
- 在 TW 韌體沒有任何本機 TX 上限(F13),預算只能靠 lora-sched。
- 數字從 F1 外推,**V2 必須掃佔空 1–10% 與發射形態**(單發、間隔 20 s 連兩發、1.9 s 島包)。

### 5.2 洪泛與確認控制

- **所有 RAK 在 provisioning 時設為 `CLIENT_MUTE`**(不轉發他人封包),**永遠不在執行期改**(F15)。[?] CLIENT_MUTE 是否仍送 routing ACK / NodeInfo 回應:待 V10;LORA_SILENT 下由 `tx_enabled=false` 硬擋。
- **Pi 發出的所有 LoRa 封包:`want_ack=false`;`hop_limit` 為參數 `LORA_HOP_LIMIT`,預設 0**:
  - `want_ack=false`:避免韌體自動重傳;確認一律在應用層做。這也讓 master 的 `sendLocal` 不會把 hop_limit=0 改回預設(F17)。
  - `hop_limit=0`:避免旁邊不受我們控制的裝置代轉。
  - **V10 用第三顆 RAK 讀空中 `hop_limit` / `hop_start`**;若韌體送出 3,改用 1 並重新評估代轉風險。
- LoRa 只走**單跳**;多跳由 HaLow 骨幹承擔。H 模式節點聽到 LoRa 包,**經 HaLow 轉**,不在 LoRa 上重播。
- **出口選舉**【決策】:
  - **按需查詢,不做週期廣播**(第五輪 C-M5:bat0 廣播每台都會轉送、無線介面上每次送 3 遍,N 台週期廣播是 N² 級負載,而廣播負載正是 F14 裡最傷同機 LoRa 收訊的情況):
    - 需要出口的 H 節點(目的地 originator last-seen > `ORIG_STALE_S`)送**一則** bat0 廣播查詢「誰最近聽到 X」;最近 5 min 在 LoRa 上聽到 X 的節點以 **UDP 單播**回覆 SNR;查詢者選 SNR 最好者,並把結果經單播通知出口。
    - 同一目的地的查詢結果快取 5 min;出口持續聽不到 X 超過 5 min 就自行放棄並通知。
    - 影子模式加錄 bat0 廣播幀率,作為這項負載的基準。
  - 目的地 X 的 originator last-seen > `ORIG_STALE_S` 時,由「聽到 X 的 SNR 最好」的那台當唯一出口;SNR 差 < 1 dB 視為平手,依 node num 小者。
  - 有效 EMCON 等級 ≠ 全隊政策的節點(含本機加嚴)、沒有 RAK 的節點不參選。
- **收訖責任**(第六輪 R-M1:出口改成「要送東西給 X 才查詢」後,往上送的 L 位置與島包不會觸發查詢,沒有人會發收訖)【決策】:
  - 收到某名冊來源 S 的 LoRa 封包(S 的 originator last-seen > `ORIG_STALE_S`,即 S 不在 HaLow 上)的 H 節點,若有 RAK、有效 EMCON 等於全隊政策,就成為 S 的**收訖候選**。
  - 候選依 SNR 退避:等待 `(1 − 正規化 SNR) × 20 s + U(0, 5 s)` 後,若還沒聽到別人宣告,就經 bat0 **廣播一則宣告**「我負責 S 的收訖(SNR x)」。聽到 SNR 更好(差 ≥ 1 dB;平手比 node num)的宣告就取消 / 讓出。
  - **事件觸發**:只在「出現新來源 S」或「責任者逾期」時宣告;每個來源每 5 min 最多一則宣告。責任者在 10 min 沒聽到 S 的任何封包就釋放責任(再廣播一則釋放)。
  - 收訖責任者同時就是 S 的回程出口(省掉一次查詢);島包的來源 S = 代表。
  - 負載:宣告數 ≈ 島外來源數(L 節點 + 代表)每 5 min 最多一則,和 N² 週期廣播不同級。
- **收訖摘要**【決策】:
  - **頻道廣播**,應用層放目的清單,不走 Meshtastic DM。
  - 內容:`{出口 node, EMCON (紀元, 版本, 等級) 3 B, [(來源 node, 序號紀元, 已收序號範圍)…]}`。
  - 間隔:平均 3 min、上限 5 min(指數分布);只在「最近 T 內有收到該來源的新訊息」時才發;**不受全隊縮放**;排隊 > 2 min 升優先(§5.1)。SOS_ONLY 下不發一般摘要,只發 SOS 確認。
  - **產生者**:收訖責任者(或出口)的 msg-router(它從 H 端收聽程序拿到「我在 LoRa 上收到哪些 (來源, 紀元, 序號)」)。
- **端對端確認的產生者**【決策】:
  - 送往指揮所的文字 / SOS,以及送給 TAK 使用者的文字:**OTS 橋接程序**在訊息寫進 OTS 後產生(§10 第 3 步)。
  - 節點對節點的文字:目的節點的 #219 app 產生。
  - 確認經 HaLow 回到出口,再由收訖摘要或 SOS 確認帶回 L 節點。位置廣播沒有端對端確認。
- **多台 L 節點之間**:只能直接單跳互通;多跳需另設中繼節點,屬後續決策。
- Meshtastic 韌體設定在佈建時一次定好:自動位置廣播 / 遙測 / NodeInfo 關閉或拉到最長。驗收:「H 模式 24 小時內非預期 LoRa 封包數 = 0」(V1)。

### 5.3 模式切換不碰會重開 RAK 的設定

依 `AdminModule.cpp`(master)【事實】:只有 region、preset、頻寬、SF、CR、tx_power、頻率等變動才需重開;`tx_enabled` 切換不需重開但寫一次 flash。本機韌體需上機確認(V6)。
【決策】:
- 模式切換**只用 lora-sched 的送出策略**控制 LoRa 發射,平常不動 RAK 設定。
- **`tx_enabled=false` 只用在 LORA_SILENT 與 RADIO_OFF**;V6 是 LORA_SILENT 的前置閘。
- **LoRa 的 preset / 頻率 / 功率永遠不做執行期自適應**。頻率由佈建決定,暫定 923.0 MHz(F14,待 V14)。
- lora-sched:停止時先 SIGINT、再 TERM,**永不 SIGKILL**(F11);斷線自動重連;以 USB 序號辨識裝置;**RAK serial 只有 lora-sched 一個擁有者**,其他程序(含影子模式、H 端收聽)一律經 lora-sched 的本機介面取得收到的封包。

### 5.4 信任與序號(過渡期)

- 只把**白名單公鑰**簽章的 LoRa 封包轉進 HaLow / OTS;白名單正式機制屬 W13。
- Meshtastic 頻道廣播**沒有逐節點簽章** [?],簽章在應用層加(+64 B,約 1.34 s / 包)。
- **過渡期**:OTS 上把經 LoRa 來的訊息標「未驗證來源」;公鑰只用 provisioning 預先登錄的。bat0 孤島廣播、出口查詢與 alfred 一樣沒有認證 → 只當提示,不當信任依據。
- **序號設計**【決策】:
  - 每則訊息帶 **(序號紀元 16 bit, 訊息序號 32 bit)**。序號以**區塊保留**方式持久化於 p6(一次保留 +1000 寫一次;重開後跳到下一個區塊),避免每則寫 flash。p6 重建或序號檔遺失 → 隨機產生新紀元、序號從 0 開始。
  - **未簽章期:序號只用來去重,不拿來拒收**。收端對每個 (來源, 紀元) 保留滑動窗(最近 256 個序號的位圖 + 最高序號);在窗內且已見過 → 丟棄;其餘(含低於窗)一律接受,再依內容雜湊去重一次。
  - **誠實界線**:未簽章期**只有去重、沒有防重放**;每來源最多保留 4 個紀元,攻擊者偽造 4 個紀元就能把真紀元擠掉,之後的重複會被接受(只剩內容雜湊去重)。影響只是重複,不會阻斷服務。
  - **簽章上線後**:才強制單調;換紀元的訊息必須有簽章。
  - 偽造 / 重放的 SOS 可能觸發出口的確認 → 確認前查去重窗,且每台出口 ≤ 1 則確認 / 分鐘。
  - **去重窗的擁有者**:H 端收聽程序(LoRa → HaLow 轉送前)與 OTS 橋接(寫進 OTS 前)各自一份;兩者都只去重不拒收。

### 5.5 執行期擁有者(誰強制這些機制)【決策,第四輪 M9】

| 機制 | 唯一擁有者 / 寫入者 | 說明 |
|---|---|---|
| 模式狀態機(H / I / L / L-probe / X)、孤島判定、維護預告的**接收**與 GATEWAY_MAINT 旗標 | **radio-mode** | 影子版先行(§10 第 1 步);輸出狀態給其他程序讀 |
| 所有 LoRa 發射、token bucket、優先序佇列、最小間隔、`N_tx`、EMCON 閘、`tx_enabled`、發射時段匯出、RAK serial | **lora-sched** | **任何 LoRa TX 都只經過它,沒有第二條路**(BLE 例外,§3.4) |
| LoRa 收到的封包 → HaLow / OTS 轉送、第一層去重 | **H 端收聽程序**(lora-sched 的本機訂閱者) | 不直接碰 serial |
| 訊息四段狀態、**序號配發(紀元 + 區塊保留)**、逐則升級、PLI 排程與底線、出口查詢、孤島代表選舉與打包、收訖摘要產生、成員 → 代表對應表、孤島廣播 | **msg-router**(新程序) | 決定「要發什麼」,交給 lora-sched 決定「何時、能不能發」 |

## 10. 建議實作順序

1. **影子模式**(`radio-mode-shadow-design-v3.1.md`):只計算、寫 log,不動作;含 L-probe 持續證據與退避、假想 X 上界、假想孤島(用 gateway originator last-seen);跑 V3 / V16 / Q8 的可答部分,並錄 bat0 廣播幀率當 C-M5 負載基準。**V15 不由影子做**(要切換 HaLow 開關,是另一個受控實驗,需授權)。

3. **H 端收聽 → OTS + OTS 橋接確認**(去重、標「未驗證來源」、寫進 OTS 後回端對端確認),做 V14。
4. **msg-router 第一版 + L 模式**(含收訖責任 §5.2):L + L-probe + 對稱回切 + PLI 底線 + **逐則升級(只對會回確認的目的地)** + 出口選舉 + 收訖摘要 + X 判定 + SOS_ONLY 的 SOS 確認 + policy 程序(EMCON 分發、只收緊規則),**一起上線**;做 V4 / V5 / V7 / V11 / V18。
5. **孤島代理**(§4.4)+ gateway 維護預告,做 V9 / V16 / V17。**上線前 §4.4 要再過一次審查**(第四、五輪要求)。
6. 延後:應用層簽章(上線後才強制單調序號、EMCON 放寬走簽章)、L 節點之間多跳、RADIO_OFF 操作、孤島代表輪替。

**v4.3(2026-09-28)** — 依 v4.2 確認(SOUND-WITH-CHANGES,R-M1 / R-M2 + MINOR)修訂:

**v4.2(2026-09-28)** — 依第五輪審查(v4.1 審查,SOUND-WITH-CHANGES,無 BLOCKER)修訂:
