### 1.5 Arm `kill` (UD9): the position watcher

**Choice** (unchanged since v2; both reviews accepted it):
- The row is about a cut **mid-stream**.
- BAD is synced before the first rootfs byte.
- In the kill sub-arm the orphan's `dd` must end short, so `write_slot`'s read-back fails.
- `write-hang` would leave a one-hour `sleep` holding fd 9 in the kill sub-arm.

**Output-side premise (A v2 m10, A v3 m9).**
- E-UD1 #15 showed the input side: fd 0, and `pos` advancing on a block device.
- The output side is shown by **observe mode in the write arm's UD20 pos**: fd 1 must be B's root partition, and three samples must show `pos` growing.
- The verdict is persisted **on the host** in `~/.batman-dv/ud9-observe/<image version>-<eth MAC>.txt`. It holds:
  - the run id;
  - `BATMAN_VERSION`;
  - 04's eth MAC (the one `pr_begin` checks);
  - the date;
  - the `UD9-OBS` line;
  - the sha256 of the node log it came from.
- The kill arm (a separate run) reads that file. A missing file, a file from another image version or another node (MAC), or a failed observation makes both sub-arms **INVALID "premise not shown"**, and they do not run.

**Watcher lifecycle** (`scripts/node/ud9-watch-254.sh`, root, staged with a sha `stage-check`):

1. **Start and register in one ssh call** (A v3 m3, B v3 m1). The call runs:

   ```
   setsid sh ud9-watch-254.sh <mode> <run> <SQ> </dev/null >/dev/null 2>&1 & echo $! > ud9.pid
   ```

   then `prov-lease-254.sh undo-add kill-pg $! ud9-watch`, and only after that `touch ud9.go`.
   - In a non-interactive busybox `sh`, the background `setsid` child is not a process-group leader when it starts, so `setsid` makes it the leader of a new group: `$!` = its pid = its pgid. The watcher checks `pgid == pid` at start and exits `UD9-MISS pgid` otherwise.
   - The watcher waits for `ud9.go` before it looks at `/proc` at all. So a host death between the start and the registration leaves a watcher that never acts, and the 900 s deadline ends it.
2. **Fresh `dd` only.** The watcher acts only on a `dd` whose start time (`/proc/<dd>/stat`) is later than its own and whose identity matches the kernel facts:
   - the parent is a uid-0 `batman-slot write`;
   - `of=/dev/` is set and `if=/dev/zero` is not;
   - fd 0 is a pipe.
3. **One-shot.**
4. **Deadline 900 s**, measured against `/proc/uptime`, or earlier when `ud9.stop` appears → `UD9-MISS`.
5. **The log file is prepared before any stream exists** (B v3 M1).
   - At start, while no slot write is running, the watcher creates `/opt/batdata/log/dv-ud9-<run>.log` (root 0600, `umask 077`), pre-sized to 4 KiB of spaces. It then runs **one** `sync`; nothing is dirty on the B device at that point.
   - From then on every result line is written **in place**, with `dd of=<log> bs=128 seek=<n> count=1 conv=notrunc,fsync`.
   - That `dd` fsyncs **only the log file** (busybox `dd` supports `conv=notrunc,fsync`: the shipped `batman-slot:752` uses exactly that on the node). The B device's dirty pages are never flushed by the watcher, and no global `sync` happens after the start.
6. **Order of action and log** (B v3 M1).
   - **kill:**
     1. read `pos` = p1 and `kill -9` the helper **at once**;
     2. sample `fdinfo/1` `pos` every iteration until the orphan `dd` is gone; the last value read is `pos_final`;
     3. write `UD9-FIRE mode=kill pos=<p1> pos_final=<pf> sq=<SQ>` in place, then `logger`.

     SIGKILL loses nothing in RAM, so the log can come after the action.
   - **cut:**
     1. read p1;
     2. write `UD9-FIRE mode=cut pos=<p1> sq=<SQ> t0=<uptime>` in place (fsync of the log only);
     3. read p2 and write `UD9-PRE-B pos=<p2> fsync_s=<duration of step 2's write>` the same way;
     4. **re-read pos = p3 from `fdinfo`, with no other I/O between that read and the cut.** If the read fails or is empty (the stream `dd` already exited), or p3 is not a plain integer, that is `UD9-MISS late p3=none`, and there is **no cut**: the test is `case $p3 in ''|*[!0-9]*) miss ;; esac` before any arithmetic, so an unset value can never fall through to `echo b`. If p3 ≥ SQ − 8 MiB, write `UD9-MISS late p3=<p3>` and **do not cut**. Otherwise `echo b > /proc/sysrq-trigger` at once.

     p3 cannot be logged durably (any write would sit between the read and the cut), so the judge uses p2 as the logged bound. The margin argument (B v4 m3):
     - BAD is cleared only by a successful `write_slot`;
     - that needs the stream `dd` to finish its own `conv=fsync` of tens of MB, the boot files to be copied, and an uncached read-back of the whole rootfs (about 112 MB) to finish (`batman-slot:735-775, 856`);
     - that is many seconds, while p3 < SQ − 8 MiB is checked microseconds before `b`;
     - so a cut issued under that check lands before BAD can be cleared.

     The logged `fsync_s` shows how long one log write took on the busy card.
7. **Liveness checks** as in v3: `pr_release` and the next `pr_begin` assert that no `ud9-watch` is alive. **Before deleting the p6 log, `pr_release` prints its non-blank lines into the unit log**, together with its sha256 (B v4 m5). The file holds only `UD9-*` result lines (positions, sizes, uptimes, dev names): no secret. After a host death the undo's `kill-pg` (segment 1) stops it.

**Host flow for the cut sub-arm** (B v5 m1). After the guarded prepare, the host polls the watcher's p6 log over ssh every 2 s (`UD9-FIRE` / `UD9-PRE-B` / `UD9-MISS`).
- A `UD9-MISS` line → stop at once and judge **INVALID**, with no `pr_find`: the node was never reset.
- Only a **lost ssh connection** after `UD9-PRE-B` counts as "cut sent". Then `pr_find 900 <old boot8>` (the boot exclusion) and the cut judge.
- No line at all and the watcher's 900 s deadline passed → INVALID `UD9-MISS timeout`.
- Offline fixture: `MISS late` → INVALID, no `pr_find` call.

**Kill-sub-arm judge** (A v3 M1). After `kill -9`, the orphan `batman-slot write` writes to pipes whose reader is dead.
- `die` / `die_c` print to stderr **before** `otalog_k` (`batman-slot:54-65`), and `disarm_tryboot`'s warnings come even earlier in the failure branch (`:766-770`).
- So the orphan usually dies of SIGPIPE before it writes `SLOT DIE` (P3's own setkey control shows helper children dying this way, `254-p3-impl.md:729`).
- BAD is safe either way: it was synced at `begin_write`, `invalidate_slot` only touches files, and a SIGPIPE death never clears BAD.
- The judge therefore does not depend on the orphan's stderr.

### 4.3 Undo journal, inline inverses (B v2 M2, B v3 M2 / m2 / m3, A v3 m5–m7)

**`ssid-restore` (B v3 M2, A v3 m5).**
- **Why hex.** The executor rebuilds each line with an unquoted `set -- $(awk …)` (`prov-undo-lib-254.sh:239-240`), which word-splits **and** globs. `apChars` allows `*` and a blank (`settingsset.go:66, 77-79`).
- **Argument.**
  - The S0 ssid is read with `uci -q get` and passed as **lower-case hex** (`[0-9a-f]{2,64}`, even length, ≤ 32 bytes).
  - An unset or empty S0 ssid is the literal `-`.
  - Nothing else passes `uvalid`, so the replayed word can never contain a glob character or a blank.
- **One value rule, applied at registration and at replay:** 1–32 bytes, no NUL, no newline. No `apChars` restriction: the value is always quoted, and P3 itself allows operator ssids such as "Tom's AP" (`SKIP_UNSAFE`, `batman-config-save:52-58`).
- **Decode, in `uact`.** A pair loop builds the value with `printf "\\$(printf %03o 0x$pair)"`. The format strings are constants and the value stays in a variable. `$(…)` would strip a trailing newline, which is one reason newline is excluded by the rule.
- **Encoding and round trip happen on the node** (A v5 m2). The host's `q` / `qr` strip CR bytes (`prov-254.sh:62-63`), so the S0 ssid never travels raw: one node-side command reads it (`uci -q get`), encodes it as `v=$(uci -q get wireless.default_radio0.ssid); printf %s "$v" | hexdump -v -e '1/1 "%02x"'`, so uci's trailing newline is not encoded (B v6 m5; `hexdump` present, E-UD1 #13), decodes the hex with the `uact` decoder, compares the bytes, and prints only `HEX=<hex> RT=ok|bad`.
- **Round trip at `undo-add`.** The unit encodes the S0 ssid it just read, decodes the hex with the same `uact` decoder (a dry-run entry, `ssid-restore --decode-only`), and compares byte for byte with the value read. A mismatch, or a value outside the rule → **INVALID before the change**, and nothing is committed. A value the replay would refuse can therefore never be registered.
- **Apply.**
  - `umask 022; uci set "wireless.default_radio0.ssid=$v"; uci commit wireless`, always quoted;
  - for `-`: `uci -q delete wireless.default_radio0.ssid; uci commit wireless`;
  - then assert that `uci -q get` returns exactly the decoded value (or nothing).
- **Binding:** `uwhere` → **`p6 slot:A`** (B v3 m2). The line survives a reboot and is replayed by the next prov unit's `pr_acquire` (`prov-254.sh:205-214`) on slot A.
- **`p5-save`** stays the existing action: `--save`, then `--check`.

**Mode check under `umask 022`** (A v3 m7).
- Every harness `uci commit wireless` runs under an explicit `umask 022`, the product's default for a procd-spawned shell, so the result does not depend on the harness shell's `umask 077`.
- After each commit, `ls -ln /etc/config/wireless` must show the S0 mode recorded at `pr_begin`. A different mode → FAIL, plus the restore.
- Offline: a commit stub under `umask 077` makes the mode check FAIL (negative control).

**Not in v4: ap-on / `ap-restore`** (B v3 m4; owner).
- E-UD1 shows the AP on at S0. A root restore that has never run would ship untested.
- An AP off at `pr_begin` → the upload rows are INVALID "phone AP off".
- `ap-restore` stays the reserved, refused name (`prov-undo-lib-254.sh:70`).
- The v3 design text for it (the hex passphrase producer, the S0-only exports) is kept in git history (03256c4) for a future bench.

**P9 scope (A v2 M2, B v3 m2).**
- The fleet P9 gains:
  - FAIL "a `ud9-watch` is alive";
  - **WARN "undo journal pending: <runs>"** whenever `undo-pending` is not empty. That is the signal for a node rebooted mid-arm (§7);
  - the five lines **gated on the prov dirty flag naming a `pupdate…` run**: inactive slot `bad=1`; `update-last` ≠ the run's snapshot copy; hold flag on a committed boot; `uci changes` not empty; `--check` rc 5. Gated → FAIL with the restore command; not gated → WARN.

### 7.1 Manual recovery after a mid-arm reboot or host death (NEEDS-PERSON)

**How P9 emits the block** (A v6 m1 / m3, B v6 m4):

**Why step 0c holds a lease but does not replay** (A v6 M1, B v6 m1):
- `pr_acquire` is `pr_stage` + `pl acquire` + `undo-pending` / `undo-replay` (`prov-254.sh:205-214`).
- On B, a dead-run line bound `p6 slot:A` stays LEFT, while unbound lines (`p5-save`, `svc-start`) would run on B (`prov-undo-lib-254.sh:76, 242-243`). `pr_acquire` then FAILs, and `back_to_a` never runs.
- `pl acquire` alone (`cmd_acquire`, `ble-lib-254.sh:297-326`) takes the lease, arms the deadman and runs `gc_rundirs`. It does **no** replay. The replay is only in the host's `pr_acquire`.
- So the rollback runs under a lease, which keeps another test off the node, with nothing replayed on B.
- `back_to_a` needs no more than that:
  - it reads state with `qr`;
  - `pr_trial_guard_end` only reads (`prov-254.sh:343-351`; `PR_AB_MT` is empty in a fresh shell, so it returns early);
  - the rollback is `rb_guarded`'s self-contained node command (`slot-guard-254.sh:46-66`);
  - its `pr_find` → `pr_acquire` runs **after the reboot, on A**, where the replay is correct (`prov-254.sh:226-240, 395-405`).
- The final `pl release` releases the lease that `pr_find` took on the new boot.

I chose this over A's lease-free form (no lease before the rollback). Holding the lease keeps the exclusion every other harness step has, at the cost of one `pr_stage`. Either form avoids the replay on B.

**Why no `ble-recover` command is printed** (A v6 m2 / B v6 m3 asked for one; disagreement with evidence):
- `ble-recover` is `cmd_recover` in `ble-lib-254.sh:367-377`, reached through the BLE role scripts (`ble-central-254.sh:118`). It removes `$BT/lease`, the **BLE** lease, and runs the role's restore. It does not touch the prov lease `$BT/lease-prov` (`prov-lease-254.sh:29`), and `prov-lease-254.sh` has no `recover` subcommand (`:86-113`).
- The "tryboot not cleared, lease kept" refusal (`DM_NOCLEAR`) exists only in the BLE role deadmen: `ble-central-254.sh:102`, `ble-periph-254.sh:197`, `bt-uart-305.sh:297`.
- The prov deadman (`cmd_dm_fire`, `ble-lib-254.sh:349-363`) always ends with `rm -f "$LEASE"` after its restore.
- So for a `pupdate254` run, `ble-recover` neither applies nor helps. The only leftover state is "lease expired, no deadman left", which happens if the deadman process itself was killed. The block stops there (NEEDS-PERSON), and the #254 checklist line on the missing recovery entry (§12) now also names "no recover for the prov lease".

## 8. Security

As in v2 §8, with these changes:
- **Secrets.** v4 creates no secret: ap-on is removed. The only journal value is the S0 ssid, hex-encoded. The ssid is not a secret.
- **Offline tests.**
  - A stubbed run's full output (including `bulk-open`, whose reply carries the AP passphrase) must give 0 hits when grepped for the stub passphrase **and** for its sha256 prefix.
- **Temporary ownership (v8, §4.4).**
  - **H0's private key:** `pr_h0` copies `~/.batman-dv/bench/h0/owner.pem` to the run's WSL key dir (mode 0600). The WSL signer reads it there and answers only `SIGN` requests. It is never printed, never sent to the node, and is removed with the run's keys (`pr_keys_drop`).
  - **The claim secret** (B v8 m3, reworded): it is read **into memory by the harness's root-started provclient only**, from `/etc/batman-prov/identity/claim.secret` before the drop to 471 (`tests/tools/provclient/main.go:6, 533-539`). It is used only for the CheckMac (`:631, 655`), and the process is non-dumpable after the drop (`:470-496`). It is never printed, logged, copied or sent. No harness script reads it.
  - **The new root password:** it is set by the product (`genPassword`, 24 random characters). provclient prints only an 8-byte sha prefix of it (`claim.verify … pw=`), which is the Q9 checklist item. The restore puts the old shadow back.
  - **What holding H0 allows** (B v8 m3). While 04's record has Owners=[H0], whoever holds H0 is 04's owner. That includes `root_password.reset` (the new password comes back to the owner in clear), `ssh_keys.set`, `network.leave` and network updates: in effect, root on 04.
    - The window lasts for each arm and, after a host death, until §7.1 restores the snapshot.
    - H0 lives on the WSL host next to the lab ssh key, which already gives root on 04, so the trust level does not change. Acceptable on the bench, stated.
  - **The bench mesh key** never leaves the node in clear and never appears in any harness output, log, `SIGN` / `NETCFG` line, harness argv or harness-created file beyond the existing root-0700 snapshot. Existing product command lines are a local-only finding (§4.4).
  - **The mesh id** reaches the WSL signer in memory only and is never printed by the harness. System daemons log it, as they do on every boot, and it is on air. The checks run every run (§4.4, "Leak checks").
- **Root executor input (B v3 M2).** `ssid-restore` takes hex only, decodes with constant formats, quotes the value, and validates it against `apChars`. A glob or a blank can never reach the unquoted `set --`.
- **openmanetd** is no longer touched.
- **The wireless file's mode.** The unit records the mode of `/etc/config/wireless` at `pr_begin`. After every harness `uci commit wireless`, an `ls -ln` mode check compares against S0. A change → FAIL and restore.
  - No wireless export is copied to p6 on this bench: `ssid-restore` carries only the ssid.
- **Watcher**, against a local unprivileged process or a compromised 471:
  - it acts only on a `dd` whose parent is a uid-0 `batman-slot write` started after the watcher;
  - it kills only the helper pid that procd reports, with exe and uid checked;
  - its log is root-only on p6;
  - a 471 process cannot steer it.

## 25. v12 note: the late ring's window (device run 2026-11-23 ud36d; for review)

**Finding.** The v11 late grep (§4.4 timing item 3; review v11 A m2 / B m2) used the boot window: the ring's first line had to be this boot's (`kernel: [    0.`). UD2 holds its trial to the autocommit deadline (about 600 s). A ring that has run that long has wrapped, so its first line is no longer the boot's and the late grep can never pass: run ud36d gave INVALID "logread window lost (LEAK-NOWINDOW ring start)" at the last HELD sample (`trial.log:31`). The flaw is in the design, not in the run.

**Change.**
- At landing, the unit writes a `logger` mark (`ud_mark`, tag `batman-dv-ud`) **before** the landing grep. The landing grep keeps the boot window: boot start .. landing, which includes the mark.
- The late grep (UD2 at deadline − 60 s; UD1 before the release and before `back_to_a`) runs over **landing mark .. now** (`ud_leak_cmd mark`).
- Together the two windows cover boot start .. last controllable point, overlapping at the mark, with no gap between them.
- If the mark is gone → INVALID "logread window lost" (never a 0 / PASS). The ring is RAM, so the mark is gone after a reboot (the trial ended early) and after a wrap past the mark (the ring rolled over more than the whole trial).
- UD2 additionally keeps its boot check before the grep: a changed boot → INVALID.

**What it does not cover.** Lines logged by the trial boot after the late grep and before its revert or `back_to_a` (seconds), as in v11. Lines that rolled out of the ring between landing and the late grep: then the mark is gone too, so this is visible as INVALID, never hidden.

**Fixtures.**
- A wrapped ring (first line not the boot's) that still holds the mark, with a key line after it → FAIL; the same without the key → PASS. The v11 boot window gives INVALID "ring start" on both: the negative control.
- The mark rolled out → INVALID "window lost".
- A key line written after the landing grep → FAIL (as in v11).

**Other v12 changes from the same run** (implementation only, no design change):
- UD2 waits for the revert with HELD expected (`PR_HELD_OK=1 pr_wait_reverted`). The REVERT units keep "HELD = no effect".
- UD4 / UD5 / UD1 / UD10 are NOT-RUN unless UD2 ended A-committed at phase 6.
- provclient is re-placed once the node booted since its placement.
