# 329-app-uiux v1 → v2：第一輪發現的逐條對應

第一輪：審查 A = REJECT（10 MAJOR、10 MINOR）；審查 B = REJECT（2 BLOCKER、11 MAJOR、14 MINOR）。原文在同目錄的 `review-v1-A.md`、`review-v1-B.md`。
「改在哪」指 v2 的章節。沒有照審查建議做的地方寫出理由。

## BLOCKER

| 發現 | 改了什麼 | 改在哪 |
|---|---|---|
| B-B1 讀完一輪後保持連線，與節點閒置逾時、停止廣播衝突 | 首頁不留連線：逐台登入 → 讀 → 斷線；每 60 s 一輪；節點主動的閒置斷線不算失敗；只有使用者停在節點頁或佔用中才保持連線，代價寫明。節點端行為列成 N1–N7 並附證據 | T1、T12、§1.2、§4.3.2–§4.3.5、§7、T-L10 |

## 沒有照建議做、或只做一部分的

| 項目 | 做法與理由 |
|---|---|
| B-M4 建議「`SwHold` 存在 = 佔用存在」 | 沒有照做：那樣使用者準備好更新、離開頁面之後，整個 app 的其他操作都會被擋到 app 重開。改成只標那一台 `swPending`、自動輪跳過它（§4.8）；要不要跳過取決於 A13 的量測 |
| B-M2 建議的三台以上真機驗證 | 手上只有兩台節點；只有假藍牙測試與推算，標成真機未測（§9.4），列為 Q3 |

| Rust 元件的授權清單 | 本單不做；10.7 放固定說明，#329 checklist 留一行 |
