## MINOR

**m1. `fresh()` 不看藍牙、權限、金鑰的那一層（`blocked`）。**
- 證據：`r2a_test.dart` 的「BT off」。讀到 Y1 之後關藍牙，結果是 `shownWhy=bluetoothOff fresh=true kind=read`。
- 設計 §4.3.1 說「新鮮」是全文件唯一的顏色判斷式，節點列也用它；§4.3.3-1 與 X7 要求這時每台都是 `unreachable(該原因)`。照 `fresh()` 畫節點列的 UI，會在藍牙關閉時顯示綠色的列（狀態區有第 1 列擋著，節點列沒有）。
- 修法：`fresh()` 在 `blocked != null` 時回 false。或者在 API 註解寫死「先看 `shownWhy`、再看 `fresh`」，並加一個 widget 測試。

**m2. 「已知位址兩次沒有回應就丟掉『是 Y』」（code-1 B-m1 的修法）有兩個副作用。**
- (a) 和 §4.3.4 不同。§4.3.4 的「沒找到」寫明：「是 Y」的位址試了兩次都連不上，即使還有沒試過的陌生位址也算沒找到。程式在第二次沒有回應時就丟掉了備忘，`_conclude` 改走陌生位址那條路，結論變成「還沒輪到」。證據（`r2a_test.dart`「known address scanned, silent twice」）：`conclusion=Concl.notYet isY={}`。
- (b) 下一輪那個位址變成陌生位址，陌生位址沒有回應就整輪不再試（`exhausted`），所以那台只剩 **1** 次機會，原本是 2 次。用 `failRate`（連線隨機失敗）跑 2 台、60 分鐘，數一台健康的節點被顯示「連不到」的秒數：

  | 失敗率 | 「連不到」的秒數（node-seconds） |
  |---|---|
  | 10% | 0 |
  | 20% | 45 |
  | 30% | 180 |

  M-1 的連線失敗是 0 / 60，所以列為 MINOR。
- 修法二選一：(i) 丟掉「是 Y」的那一輪結論照 §4.3.4 算「沒找到」，下一輪那個位址照已知位址的規則給 2 次（例如把它記在 `noRespLast` 旁邊的一個「上一輪是 Y」集合）；(ii) 改設計回填。另外加一個隨機失敗的模擬測試，當成真實使用的安全斷言。

**m3. 驅動層的契約沒有把「舊的結果」排除乾淨。**
- `Attempt` 只有（位址, id），沒有序號。一輪被取消之後，新的一輪又挑中同一對時，舊連線遲到的結果會被算到新的一輪頭上。證據：`r2a_test.dart`「late result」。舊連線的 `certRejected` 把 Y1 設成身分不符，並把新一輪的 `running` 清掉（新連線變成孤兒）。
- `LoginFor.result` 只檢查 `c.lease` 這個布林值：舊的佔用被收回、新的佔用開始之後，舊 `LoginFor` 的結果照樣寫入（證據：`old loginFor after new lease: end=identity why=identity`）。
- 照 §4.3.3-8「等斷線完成」做的驅動層不會遇到這兩種情況，但核心沒有守住。修法：`Attempt` 加序號，`LoginFor` 綁佔用的世代號。

**m4. `loginFor` 只在開始時檢查前提。** 中途藍牙關閉時，它跑滿 60 s 才回 `notFound`（證據：`end=LoginEnd.notFound`）。流程頁會顯示 NOT_FOUND 的句子，§4.3.9 要的是 2.3 的內容與按鈕。修法：`setRadio` 讓不成立時，把進行中的 `loginFor` 結束成 `precondition`。

**m5. 殘留的 `leaseDue`。** 佔用在其他頁面釋放（`leaseDue` 留著），10 s 後回首頁、離上一個全輪結束約 16 s，結果立刻開一輪（證據：`rounds started now=1`）。X18 / X27 說要照 §4.3.2，等滿 60 s。後果只是多讀一輪（剛操作完多讀一次也合理）。修法二選一：`setPage` 清掉 `leaseDue`，或把這個行為回填進設計。

**m6. `code1-changes.md` 對 A-m7 / B-m9 的說法不實。** 它說「程式註解寫明 `Res.broken` 只能在登入成功之後回報」，但 core.dart 裡沒有這段註解（`grep broken` 只有 :32 的 enum 和兩個 `case`）。簽名之前的 `End::Broken` 若被驅動層報成 `broken`，附近的裝置就能種下錯的「是 Y」。請補上 `Res` 每一個值的驅動層對應表（`End` → `Res`），並更正那份對應文件。

**m7. `mutate.pl` 列出的 FAIL 測試不完整，`mutate6.out` 低報了對照。**

**m8. 其他沒被抓到的突變（我判斷可以接受，但要寫明）。**
- A6、A15 是等價突變：已知位址的兩次嘗試用完時，那個位址的「是 Y」已經被丟掉，或者 `retry` 還在；讀到之後 `_canTry` 是 false。

**m9. 沒有目標也會開輪。** 首頁沒有任何紀錄（2.1），或節點頁的那筆紀錄被刪掉時，`_begin` 照樣開一輪：馬上就算「全部讀到」而結束，60 s 後再一輪。結果是每分鐘一次沒有用的掃描啟動。修法：目標是空的就不開輪。

**m10. `core.log` 的內容。** 它印出完整的紀錄 id 與 BLE 位址（`'$addr×$id'`）。§4.1 與 §8 說 `NodeLink` 新增的紀錄行只有時間、種類、後四碼。現在的 id 長度不會碰到 T-S4 的 32 個 16 進位字元門檻，但內容規則不合。修法：核心只印後四碼，或在契約寫明「驅動層不可原樣轉出 `core.log`」。

**m11. 冷啟動與第一輪 A-m10(a)。**
- 冷啟動的數字（7 台 240 s、12 台 820 s，測試印出）同意回填。要一起寫明：備忘只在記憶體，所以每次 app 被系統結束後都會重來一次；認領流程裡 `loginFor` 已經建好備忘，所以「從零到組網」的 demo 不受影響。
- 第一輪 A-m10(a) 沒有處理，`code1-changes.md` 也沒有列：`read(2')` 不設 `lastRead`，一直回錯誤碼的節點在排序上永遠算「這次還沒讀到」、排最前面。請處理或回填。

**m12. 「連續兩輪沒找到」用的是計數，不是相鄰兩輪的結論。**
- 依序「沒找到 → 還沒輪到 → 沒找到」，第三輪就變成「連不到」，而且不提前再讀（`miss` 不被「還沒輪到」歸零）。
- 這符合 §4.3.4「還沒輪到不動計數」，但和 §4.3.2「前一次的結論不是沒找到才提前再讀」、§4.3.5「連續兩輪」的字面不一致。
- 設計內部本來就互相矛盾。回填時統一成程式的寫法，並加一個測試鎖住它。

## 模擬器 vs 真機（§1.2、§1.3）

| 項目 | 模擬器 | 真機 | 判斷 |
|---|---|---|---|
| 拿錯紀錄的握手 | 5 s | M-1 W：1.7–4.9 s | ✅ 模擬器比較慢，偏保守 |
| 重新廣播 + 第一次看到 | 5 + 3 s | M-1 R：約 4.9 + 1–2.6 s | ✅ 偏保守 |
| 一次一條連線 | 嚴格一次一條 | N1 靠 5 s 一次的收斂迴圈撤廣播，加上 N3 有 2 個槽；剛連上的頭幾秒，第二支手機可能也連得上 | ✅ 模擬器比較兇，不會因此讓測試過關 |
| N4（每台每分鐘 20 次握手） | 沒有模擬 | 超過的那次斷線 | ⚠️ T-L11(j) 本來就只當安全斷言 |
| 連線隨機失敗（GATT 錯誤） | 沒有模擬 | M-1 是 0 / 60 | ⚠️ 見 m2，建議加一個 `failRate` 的安全測試 |
| A1（登入成功 + 讀狀態 11 s） | 參數 | ❌ 未量 | 量到之後改參數重跑 |

結論：沒有發現哪個測試是因為模擬器比真機寬鬆才通過。

## 四個需求的實際情境

1. **從零到組網**
   - 認領 → 釋放（`setRecords`、N9 窗）→ 立刻建網的 `loginFor`：RB-CLAIM-0/3/6/8 都登入成功。
   - 附近超過 8 台別人的節點時，要按一次「再試一次」（已接受的上限，見上面的改進建議）。
   - 新節點 6 s 後被首頁讀到（code-1 A-M3 測試）。
2. **不顯示多餘資訊**
   - 穩定之後對別人的節點握手 0 次（T-L11(c)(i)、(j)）。
   - 「附近有還沒認出來的裝置」的句子目前沒有測試守著（M1 的 A9）。
3. **掉線、出錯要明顯**
   - 兩輪規則、提前再讀、身分不符的疊加層都有測試。
   - 漏洞是 m1（藍牙關閉時節點列可能仍是綠的）與 m2(b)（連線不穩時的誤報）。
4. **不用每次重連**
   - 啟動、回前景、釋放後都自動讀（T-L1/T-L3/X18）。
   - 冷啟動的時間見 m11。

## 安全（逐 actor）

- **附近冒用位址的裝置**
  - 不回應：兩次就丟掉「是 Y」，下一輪重新找（RB-REPLAY-a/b/c ✅），代價見 m2。
  - 回解不開：第一次只丟「是 Y」，第二次才記「不是 Y」（T-L11(l) ✅），會一直留到重新整理或位址輪換（設計已接受）。
  - 回壞掉的 msg2：要靠驅動層把簽名前的 `Broken` 對應成 `noResponse`，目前沒有寫下來（m6）。
- **一直換位址、不回應的裝置**：已認出的節點不受影響（T-L14 sharpened ✅）。沒認出的那台要等，設計已接受。
- **複製的節點（CertRejected）**：身分不符不會被 `2'`、登入被拒、藍牙或權限的切換蓋掉（k、R12、A-M2 ✅）；只有之後某一輪真的讀到、或紀錄被寫入時才結束。我同意程式比文字嚴格（按重新整理不結束它）。
