## 怎麼產生的

- 測試：`app/test/retest_s_boards_test.dart`（54 個畫板，假資料沿用 `test/ui/layout_test.dart`，另補 layout_test 沒開的流程頁）、`app/test/retest_s_boards_p_test.dart`（12 個畫板，沿用 `test/ui/retest_p_layout_test.dart`）、共用 `app/test/retest_s_shot.dart`。
- 每個畫板 412×915、字級 1.0、淺色與深色各一張；判定 = 沒有溢出（溢出是測試例外）；設 `BOARDS_OUT` 時寫 PNG（2× 像素，824×1830）。字型：`C:/Windows/Fonts/NotoSansTC-VF.ttf`（當成 Roboto 與 monospace）＋ Flutter SDK 的 MaterialIcons。
- 結果：66 個畫板 × 2 主題 = 132 張 PNG，`flutter test` 兩檔 `+132: All tests passed!`（設與不設 `BOARDS_OUT` 各跑一次）。
- PNG 在本機 scratchpad `…/scratchpad/b2/boards/`（不進 repo）。檔名 = `<畫板>_<light|dark>.png`。
- 我實際打開看過的 PNG：淺色 52 張、深色 3 張（`node_page_green`、`swupdate_prepared`、`5.7_remove_dialog`）。下表「沒看」的格子是沒看，不是通過。

### 渲染限制（判讀時要扣掉的）

- 每張只到第一個畫面（915 dp 高）；需要捲動的內容不在圖上。
- 畫板是 `home:` 直接開的，所以標題列沒有返回鍵（實機從上一頁進來會有）。
- QR 由 Kotlin 產生，widget 測試裡沒有 → 7.3 / 7.6 / 7.9 顯示「這個碼太長，無法用 QR 顯示」是測試環境的結果，不是實機畫面。
- 8.1 / 8.4 的「版本讀不到」、「關於」沒有版本號、國家 / 手機 Wi-Fi 的「讀不到…另一個操作還在進行」都是假資料（session 被佔用）的結果。國家選好之後的 5.8 確認、Wi-Fi 讀到值的狀態沒有渲染。
- 4.x_failed 的錯誤句是我照 F11 的 `error_text` 格式（`[REQ_FAIL] <做什麼>沒有成功：<原因>（代碼 N…）`）寫的假回覆，不是從節點收到的。
