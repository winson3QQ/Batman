## 沒有照建議做、或只做一部分的

| 項目 | 做法與理由 |
|---|---|
| B-m8 建議備忘只留「是我的」那一半 | 留著「不是」那一半，但要兩次、相隔 ≥ 10 s 才記（B-M1 的洞由這個規則擋）。不留的話，附近每一個別人的節點每輪都要握手，會吃掉節點的握手配額（N4） |
| A-m6 建議在畫面上寫「狀態最多慢 3 分鐘」 | 只顯示讀取時間。多一句固定說明違反「不顯示非必要資訊」（U2-2）；超過 180 s 的狀態本來就不會是顏色 |
| A-M8 / B-M5 位址一直換的假廣播者 | 不擋：要擋就得讓節點的廣播帶身分提示，那要改節點與協定，不在本單（§13，#329 checklist 一行）。結果是「還在找」，不會顯示錯的狀態、不會寫錯東西 |
| B-m10「Q2 沒同意前 PR 1 不開工」 | Q2 已同意並重現了 U2-4；剩下沒量的項目（A1、A10、A13、F22）需要一台已認領的節點，列成 Q5，PR 1 的第一步就是補量 |
| 三台以上節點、兩支手機的真機驗證 | 手上只有兩台節點、一支手機；假藍牙測試 + 標成真機未測（§9.4、Q3） |

## v3 新增、上一輪沒有看過的東西（請第三輪特別看）

- 嘗試的單位（位址 × 紀錄）、每位址每輪 2 次握手、備忘「兩次才記不是」（§4.3.3）。
- `OwnerStep` 多一個結束種類欄位（T8、F44）—— 這是本單唯一不是文字的 Rust 改動。
- 節點頁不再保持連線（T16）；全 app 只有「讀完就斷」一種。
- `lease.run` / `pageGone` / 420 s 上限、`RecordWriter` 的七個寫入點（§4.4、F47）。
- 狀態 × 事件表 X1–X26（§4.3.6）。
- 「從這支手機移除這台節點」對所有版本開放（T17、§5.5、Q6）。
- 網路摘要表（§4.3.8）與首頁第 6 列。
- `ui/state-v1` 縮成四個欄位、不存任何節點傳來的字串（§4.6）。
- M-1 的實測數字與它沒量到的部分（§1.3、§9.3）。
