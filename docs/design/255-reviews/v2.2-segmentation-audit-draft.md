## 1. 現況（已在程式中確認）

### 1.1 網路分段

**有三條路可以進入同一個網段 `br-ahwlan`：**

| 入口 | 需要什麼 | 出處 |
|---|---|---|
| 手機 Wi-Fi AP | 該節點的手機 Wi-Fi 密碼（隊員自訂） | `meshpoint-1.8.0:66-69` |
| 網路孔（eth） | 實體接觸，不用密碼 | `meshpoint-1.8.0:112` |
| HaLow mesh（bat0） | 全網共用的 SAE 密碼 | `meshpoint-1.8.0:113` |

batman-adv 沒有開 AP 隔離（`:93`），`ahwlan` 防火牆區的 input／output／forward 全部 ACCEPT（`:137-139`），也有 IPv6（`:80-81`）。

**在這個網段上聽的服務：**

| 服務 | 現況 | 出處 |
|---|---|---|
| dropbear（SSH） | 所有介面都聽；認領後只接受金鑰 | `batman-prov-lock:24-28` |
| uhttpd：LuCI／rpcd | 接受 root 密碼登入；密碼是 24 字元亂數，猜不到，但看過的人（T2）知道 | `254-claim-lock-fix.md:45` |
| uhttpd：落地頁、`/cgi-bin/mesh` | 給使用者看的 | `97-batman-landing:7` |
| OTS（TAK 伺服器） | 經 DNAT 開 8088、8089、8443 | `deploy/ots/ots.fw4.uci` |
| alfred、umdns | 在共用二層網段上；openmanetd 用 alfred 做位址保留 | `meshpoint-1.8.0:156` |
| provd 大量傳輸通道（HTTP 8095） | **已經分段**：只收來自本機 `phy*`（手機 AP）連接埠的封包，只在開啟期間；規則不在時 helper 不給位址（fail-closed） | `feed/batman-prov/files/batman-http.nft`、`node/bulk.go:15`、`provhelper/bulk.go:89-120` |

**結論：**除了 8095，管理服務對三個入口一律開放。從任一台節點的手機 AP、網路孔，或知道 mesh 密碼的 HaLow 裝置，都能直接碰到全網每一台節點的 SSH 與 LuCI。8095 的做法（在橋上依進入的連接埠標記、再在 inet 表依標記丟棄）是現成可沿用的樣板。

### 1.2 稽核

| 事實 | 出處 |
|---|---|
| provd、helper 寫 syslog；helper 記的是運作狀態，沒有記「哪把管理員金鑰簽了哪個變更」 | `batman-provd/main.go:61`、`batman-provhelper/main.go` 的 `logf` 呼叫 |

**結論：**今天無法事後回答「誰、何時、用哪把金鑰、改了哪一台的什麼」。殘餘風險 5、7 所說的「事後發現」沒有工具可用。

## 3. 新增規則

### K23 管理服務只從允許的入口提供（第 2 期）

**原文：**節點的管理服務（SSH、LuCI／ubus、provd 的 HTTP 通道）只接受來自允許入口的連線；預設拒絕。

- 做法沿用 `batman-http.nft`：在橋上依**進入的連接埠**（`phy*`、`eth*`、`bat0`）標記封包，在 `inet` 表（同時涵蓋 IPv4 與 IPv6）依標記丟棄。只看本機 AP 和網路孔是不夠的：從 A 節點的 AP 連到 B 節點的 SSH，封包是從 B 的 `bat0` 進來的。
- 允許清單：
  - 8095：只從本機 `phy*`（現況，不變）。
  - SSH：預設全部拒絕；維修模式開啟時只從本機網路孔。
  - LuCI／ubus：不從 `ahwlan` 提供（uhttpd 分開設定）；落地頁、`/cgi-bin/mesh`、OTS 的埠照舊開放，它們是使用者服務。
- 藍牙不是網段，不受 K23 約束；藍牙上的保護由 Noise 與既有規則負責。
- **維修模式**：管理員用 app 經藍牙開啟；重開機或 30 分鐘後自動關閉；開啟與關閉各留一筆 K24 紀錄。

**對使用者的影響：**隊員用 app 經藍牙管理，看不到差別；受影響的是開發與維修人員。

### K24 管理事件留下紀錄（第 2 期）

**原文：**節點對每一個管理事件留下一筆紀錄，存在容器碰不到、只有 root 能寫的位置，重開機與斷電後仍在。

- **記哪些事件：**
  - helper 套用的變更：換管理員、移除成員、換密碼、裝或移除 SSH 金鑰、韌體更新與回退、恢復出廠、開關維修模式。
  - 晶片事件：燒錄完成、換 HAT 被凍結、後端不符被凍結、開機時晶片沒回應、認領或重放失敗。
  - 登入：SSH、LuCI 登入成功與失敗。
  - 開機原因。
- **每筆欄位：**單調序號、節點時間、**請求者手機的時間**（簽章請求裡帶的）、事件種類、簽章者金鑰指紋（不是名字）、結果。
- **被拒絕的請求只記次數：**每種拒絕原因每個時間窗一筆計數，和實際變更分開存放；空間不足時先覆蓋拒絕計數，最後才覆蓋實際變更。provd 自己擋掉的請求（Noise 交握失敗、格式錯誤）也把計數交給 helper。
- **不記：**秘密、密碼、位置。紀錄不能變成追蹤資料（T14）或洩密來源。
- **存放位置：**p5（root 專用），或 p6 上任何容器都不會掛載的目錄；不宣稱加密，直到 LUKS 上線。
- **紀錄無法寫入時（空間滿、分割區沒掛上）：**管理變更照常進行，app 顯示「稽核暫停」。
- **誰能讀：**只有管理員，經藍牙 Noise 通道。

**第 1 期不受約束。**第 1 期的晶片事件寫進 syslog 即可。

### K25 紀錄的副本存在管理員手機上（第 2 期，與 K24 同時）

**原文：**管理員 app 每次連上節點時，取回上次之後的新紀錄並保存副本；序號倒退或中間缺號時，app 顯示警告。

- 透過 Noise 通道取回，所以副本確定來自那台節點。
- 節點上的紀錄就算之後被刪，手機上已有的副本仍在。
- 不用雜湊鏈：拿到 root 的人可以重算整條鏈，雜湊鏈證明不了什麼。
- 不用晶片簽紀錄：K16 規定背書金鑰只簽晶片自己組的訊息。
- 恢復出廠或重刷卡造成序號從頭開始時，節點先記一筆「紀錄重新開始」，app 看到這一筆就不發警告，避免使用者習慣忽略警告。

## 5. 新增殘餘風險

1. 拿到 root 的人可以刪掉節點上「最後一次管理員同步之後」的紀錄；K25 只保得住已經同步到手機的部分。
2. 紀錄證明的是「哪把金鑰簽的」，不能證明是誰拿著那支手機。
3. 同一網段內的使用者裝置之間仍互相可達，也能假冒 DHCP、路由公告、alfred 資料（N2、N3），除非處理 Q2。

## 7. 待決問題

- **Q1 維修模式的細節**：SSH 只開在網路孔是否夠開發用？bench 上要不要有不需 app 的開法（只限沒開 secure boot 的開發映像）？
- **Q2 使用者之間要不要隔離**：開 AP 隔離、只放行 TAK 需要的流量、擋 DHCP 與路由公告。能處理 N2、N3，但可能弄壞 TAK 多播或隊員之間的其他用法。要先實測 TAK 需要哪些流量。
- **Q3 紀錄要留多少**：筆數上限或天數，影響 p5／p6 的空間配置。
- **Q4 要不要防止紀錄整批回退**：若要，可用 608B 的單調計數器記紀錄的世代。這會碰到晶片設定，不放在第 1 期；要做時再對照 `255-608b-config.md`。
- **Q5 和 #65 EMS 收集器的關係**：持續監控（IEC 62443 CR 6.2）由 #65 負責；K24 的紀錄是否也要送進 #65。
